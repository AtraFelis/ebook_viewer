# 앱 전용 PDF 복사본과 중앙 오류 복구

2026-11-07, Asia/Seoul. [계획](../plan/managed-pdf-storage-and-recovery.md), [ADR0022](../adr/0022-managed-pdf-copies.md).

## 기준과 보존

사용자는 외부 파일 이동에 영향받지 않는 앱 전용 복사본과 중앙 오류 팝업을 요청했다. 삭제 시 원본을 보존하고 앱 복사본·기록을 정리하도록 선택했다. CI 우선 요청을 처리한 PR #36은 e8e8fd103c3cc18bc5251c906095b2b003f18bf0으로 사용자 병합됐다. 기존 변경5개·사용자 파일 해시·stash 목록을 ignored local-artifacts/managed-storage-20261107에 백업한 후 origin을 fetch했다. 현재 head와 병합 결과의 파일 차이가 없어 같은 체크아웃에서 codex/managed-pdf-storage를 생성했다. reset/clean·강제 push·새 worktree는 없다. main 브랜치 자체를 이동하지 않았다.

## 구현

읽기 기록 v7은 URI 키/기존 필드/다중 소속을 유지하고 UUID 토큰만 추가한다. v1~v6를 읽고 첫 v7 쓰기 전 원래 바이트를 before-v7 AtomicFile에 보존하며 이전 before-v6도 유지한다. 복사본은 앱 filesDir/documents의 UUID.pdf이며 URI/외부 파일명·임의 경로를 삭제 경로로 사용하지 않는다. 새 등록 시 복사하고 이전 자료는 다음 열기 또는 재등록 시 복사한다. 이미 접근할 수 없는 기존 원본은 재선택이 필요하다.

32KiB 버퍼, 취소 확인·16MiB 공간 여유 검사, pending 파일의 fsync/이름 확정으로 부분 파일의 등록을 막는다. 기존 비탐색 입력은 256MiB·유휴30초 제한/익명 임시 복사/취소 경로를 그대로 사용한다. 정상 탐색 파일에 새로운 256MiB 상한을 적용하지 않는다. 프로세스 중단 후에는 카탈로그 로드가 성공한 경우에만 참조 없는 UUID 복사본/임시 파일을 회수한다. 손상된 카탈로그를 빈 상태로 덮거나 해당 파일들을 임의로 정리하지 않는다. 원본 내용 변경은 내부 스냅샷에 자동 반영하지 않는다.

본문/공유 표지는 복사본을 읽고 현재 페이지 본문 추출은 렌더러가 소유한 같은 FD를 복제한다. PDF payload·URI·제목·개인 문서는 로그/Git로 내보내지 않았다. 앱 제거/데이터 초기화 시 복사본도 없어지며 PDF 크기만큼 앱 저장 공간이 필요하다.

복사본 없는 경우 외부 원본으로 몰래 대체하지 않는다. 중앙의 둥근 복구 창에 이유·다시 시도·파일 다시 선택·문서 삭제와 닫기 아이콘을 표시하고 뒤 목록을 어둡게 한다. 회전 재생성은 실패 URI/viewport·창을 복원한다. 삭제는 기존 중앙 확인을 거치고 저장 성공 뒤 참조 없는 앱 복사본만 제거한다. 책장 삭제는 관계만 지운다. 같은 URI 재선택도 성공한 새 복사본으로 교체할 수 있으며, 이미 존재하는 다른 문서를 선택할 때는 그 문서의 관리 복사본을 사용한다.

삭제 후 지연된 읽기 저장은 기록을 되살리지 않도록 IO 큐에서 방어한다. 이전 HomeNavigationDeviceTest는 finish 이후 lifecycle idle을 기다리기 전에 합성 기록을 삭제하는 경합이 있어 idle 대기·삭제 후 부재 검사를 추가했다. 이전 합성 잔여물의 정리는 정확한 앱 cache 경로·테스트 이름/제목·100페이지·원본 부재·책장/북마크 없음·관리 복사본 없음 조건을 모두 만족하는 것만 대상으로 한다.
