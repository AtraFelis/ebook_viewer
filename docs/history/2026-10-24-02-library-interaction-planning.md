# 서재·문서 조작 방향 정리 — 2026-10-24

사용자가 표시를 넣은 이미지와 전체 문서 화면의 추가 요구를 보냈고, 바로 개발하지 말고 계획/방향부터 정하도록 지시했다. AGENTS→SESSION→CHECKLIST→책장 계획과 Git 상태를 읽었다. 이번 응답에서 수행한 앱 관련 작업은 기존 UI/관리 소스의 읽기 전용 검토뿐이다. 앱 소스 변경·빌드/테스트·ADB·설치·원격 게시/CodeRabbit 호출은 하지 않았다.

[새 계획](../plan/library-interaction-refinement.md)에 배경 없는 아이콘 중심 도구, 작은 회색 편집 테두리, 책장 편집의 삭제/드래그 순서 탭, 더보기/이동 시트, 대체 표지와 문서 목록 제목/간격, 선택 상태 하단을 정리했다. 기존 ‘책장에 추가’의 이름만 바꾸며 저장 동작을 임의로 바꾸지 않도록 이동/삭제 의미를 먼저 질문했다.

사용자 답변으로 문서 삭제는 등록/읽기 기록에서 제거하되 원본 PDF를 보존하는 기존 동작을 유지한다. 책장 이동에는 ‘이 책장에도 남겨두기’ 토글을 넣는다. 켜짐은 현재 소속 유지/목적지 추가, 꺼짐은 현재 책장 관계만 제거/목적지 추가로 정리하며 다른 책장 관계는 유지한다. 출발 책장이 없는 경우를 추가 질문했고 사용자는 **전체 문서에서는 책장 이동 기능을 제거**하도록 결정했다. 전체 문서 선택 하단은 삭제만으로 정정했다.

미분류에서의 이동/토글 숨김, 토글 기본 켜짐, 목적지 하나를 누르면 처리, 새 책장 생성 후 선택, 책장 더보기의 문서 추가 연결은 아직 세부 제안으로 구분했다. 앱 테마를 참고 이미지의 흰 배경으로 강제하지 않으며, 현재 메인 상단 이어 읽기는 유지하고 문서 범위 화면의 중복 이어 읽기만 제거하는 범위다.

목록 제목 누락의 유력한 원인은 격자용 세로 Cell을 가로 목록으로 바꾸면서 빈 buttons 컨테이너의 폭을 다시 배정하지 않는 점이다. 제목 데이터나 기기에서의 원인을 확정한 것은 아니다. 이후 목록의 실제 제목 폭과 관리 영역·행 간격을 재현/검증하도록 계획했다.

기존 codex/bookshelf-library-redesign의 미커밋 구현·사용자 docs/design.md/gradle.properties·stash를 보존한다. 이전 카드 피드백 검증은 [앞선 이력](2026-10-24-01-bookshelf-card-feedback.md)의 결과이며 이번 새 요구의 구현/검증으로 확대하지 않는다. 다음은 화면 배치와 남은 제안의 사용자 검토이며, 개발은 방향을 확정한 뒤 시작한다.
