## 조사와 실제 명령

AGENTS→SESSION→CHECKLIST→roadmap/선명도 계획과 ADR 0001·검증 전략·기획/디자인 이력·Git 규칙을 읽었다. 현재 PdfCanvasView는 512px 미리보기/가시 타일을 요청하고 64MiB 공유 캐시를 쓴다. PdfWorker는 단일 worker에서 최대 4개 타일 작업·세대/epoch 검사를 유지한다. 이 코드 확인은 지연 시간이나 새 엔진 지원의 실측이 아니다.

Context7 첫 검색 `Android SDK PdfRenderer`는 무관한 SDK 후보를 반환했다. `Android Developers`로 다시 resolve한 `/websites/developer_android_reference`를 조회해 공식 API 연결을 확보했으나 최신/PreV 자료가 혼재하고 API 33 고정 버전은 없었다. 공식 [Page.searchText/selectContent](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page), [PdfRenderer/LoadParams 생성자](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer), [PdfRendererPreV와 S Extensions 13](https://developer.android.com/reference/android/graphics/pdf/PdfRendererPreV)로 도입 버전을 교차 확인했다.

`. ./scripts/android-env.ps1` 후 설치 `platforms/android-35/android.jar`에 JDK `javap` 실행: `PdfRenderer$Page`의 getTextContents/searchText/selectContent, PdfRenderer의 LoadParams 생성자, `LoadParams$Builder.setPassword` 서명 확인. 문서 전체 outline 조회는 해당 PdfRenderer/Page 공개 서명에서 확인하지 못했다. compileSdk 서명은 API 33에서 실행 가능하다는 증거가 아니며 엔진/확장·목차 경로를 준비 단계에 남겼다.

`adb devices`의 식별자는 출력하지 않고 승인 device 행만 집계했다. daemon이 시작됐고 **승인 기기 0대**라 API/SDK 확장 속성 읽기는 건너뛰었다. 기기 테스트·앱 설치/실행·성능 측정은 하지 않았다. PDF/URI/개인 내용/암호를 도구나 로그로 보내지 않았다.

PowerShell 경로 wildcard를 `rg` 파일 인자로 넣은 검색 1회는 경로 구문 오류였다. 실제 디렉터리와 `-g` 파일 패턴으로 다시 조회해 DebugFrameProbe의 기존 frame/preview 지표를 확인했다. 첫 타일 준비와 실제 선명한 화면 표시는 구분해야 해서 새 선명화 계측은 아직 미구현이다.

## 산출물·다음 행동

[P2 착수/범위/종료 계획](../plan/p2-scope-and-completion.md)을 만들고 roadmap·선명도 계획·SESSION·CHECKLIST·문서 목차를 맞췄다. 준비는 API 33 엔진/SDK 확장 경로와 구체적인 구성 승인·ADR, 샘플 기대값·측정 기준선/합격선까지다. 그 후 엔진 통합→선명도→검색/선택/목차/암호화→자동 배경/설정→접근성과 최종 통합 수용 순서로 진행한다.

정확한 종료 판정은 모든 필수 기능 수용·최종 통합 기능/성능/접근성 검사·사용자 개인 기기 확인·기능 PR 사용자 병합·완료 기록이다. 날짜는 엔진 경로/승인/기준 측정을 마친 뒤 산정한다. OCR/EPUB/주석/crop/편집/암호화 저장·다른 기기/스토어 출시 및 Figma 전면 적용은 별도다. 새 엔진 후보의 특정 버전/라이선스/크기/ABI/유지보수·영향 비교와 승인 요청은 다음 조사에서 구체화한다. 현재 후보 채택/의존성 추가·앱 구현은 없다.

## 추가 관찰 — DPI와 화질/복구 지연

사용자가 ‘DPI가 낮을수록 오래 걸리는 것 같다’고 보고한 뒤 낮은 DPI가 나쁜 화질을 뜻하는지 물었다. 같은 표시 크기의 이미지 실제 해상도와 원본 화질, DPI 메타데이터, 벡터 및 앱 렌더 배율을 구분해 설명했다. 코드 재확인에서 `visibleTiles`는 페이지 크기/배율/화면 영역으로 요청하고 미리보기는 최대 512px이며, 해당 요청 경로에서 이미지 DPI를 읽어 저DPI 문서를 지연시키는 분기는 없었다. native 내부 처리/실제 대기 기여도는 확인하지 않아 원인을 확정하지 않았다.

[Adobe 해상도/리샘플링](https://helpx.adobe.com/photoshop/desktop/crop-resize-transform/resize-adjust-resolution/image-size-resolution-and-resampling.html)과 [벡터/비트맵 설명](https://helpx.adobe.com/ca/photoshop/using/image-essentials.html)을 대조했다. 선명도 계획에 동일 원본/페이지 배치 크기의 실제 픽셀 해상도 비교, 메타데이터만 다른 대조군·벡터 및 압축 조건 분리를 추가했다. 현재 개인 PDF 분석/샘플 생성/앱 수정·설치/기기 성능 측정은 하지 않았다. SESSION에는 미검증 관찰로, CHECKLIST에는 미실행 비교 항목으로 반영했다. 기존 계획/디자인 변경은 보존했다.
