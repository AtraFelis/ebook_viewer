## 기기 실행 경과

- 연결/승인/잠금 해제된 API33 한 대에 데이터 보존 설치했다. 개인 PDF/제목/본문/기기 식별자를 수집하지 않고 합성 문서/테스트 UI만 사용한다. suite 자체180초/호스트210초 상한.
- 최초 chrome **3개/실패2**: 흰/검은/회색/색상 바탕·100/200% 글꼴에서 투명 번호의 대비 픽셀 검사는 통과했다. 통합 검사는 앱 시작 포커스 안정화 대기에서 실패했고, 버튼 비교는 옅은 강조 예상값과 비활성 회색 실제값이 달랐다. 최초 결과를 ignored `local-artifacts/design-chrome-first-failure.txt`에 보존했다.
- 테스트 실패 시에도 원래 번호 설정을 복원하도록 finally 범위를 넓혔다. 버튼의 enabled 여부/실제 drawable 상태를 확인하고 detached fixture의 상태 갱신을 명시한 뒤 strict 계측 빌드/Lint/ktlint **5초 통과**. 앱 APK는 그대로이며 계측만 재설치했다. 원인/실제 재검사 결과는 뒤에 기록한다.

- 두 번째 chrome3개/실패1: 실제 앱의 중앙 위치/투명/앵커·번호 위 스크롤과 대비 검사는 통과했다. 최초 앱 시작 포커스 실패는 같은 앱에서 재현되지 않았으며 최초 원인은 미확정으로 보존한다. 원래 실패를 삭제/통과로 바꾸지 않았다. 버튼은 enabled=true여도 숨겨진 detached fixture에서 비활성 fill로 그려졌다. 실제 합성 앱 캡처에서는 활성 버튼의 옅은 강조와 비활성 북마크가 올바른 별도 색으로 표시됨을 확인했다.
- 색상 fixture를 실제 Activity Window에 표시한 양 테마의 버튼으로 바꿔 기대값을 낮추지 않고 검사했다. strict 계측/Lint/ktlint5초 통과 후 같은 앱에서 chrome3개/실패0으로 재통과했다. 후속 navigation4/immersive7/font1도 모두 통과해 관련 **15개/실패0**이다. font1개는100/150/200%×가로/세로6조합의 기존 조작 노출 검사다. 이 단계는 최초 app 해시 기준이다.
