# P2 마무리 — 2026-10-20

## 판정과 범위

개인용 SM-N981N(API 33)에서 P2 필수 기능의 구현·자동 통합 검증·사용자 수용과 기능 PR 병합을 완료했다. 사용자가 [PR #17](https://github.com/AtraFelis/ebook_viewer/pull/17)을 KST 16:29:07에 병합했고 원격 main **68ced37d0640d4f54639afad4d9c1cc513f4fa99**를 확인했다. 완료 문서를 별도 PR로 반영하며, 문서 병합 확인 후 P2 종료 기록을 확정한다. 앱/도구/의존성의 추가 변경은 없다.

완료 범위는 기존 PdfRenderer의 제한된 페이지 재사용·선명도 개선, 수동 선택을 보존하는 자동 페이지 외부 배경색, 테마/읽기 밝기/화면 유지, 요청한 한 페이지의 본문 읽기와 native 안전 제한, Canvas 접근성/키보드·TalkBack·큰 글꼴이다. P1의 연속 스크롤·줌/앵커·이어 읽기·북마크/설정과 기존 오류 처리를 유지한다.

사용자 결정으로 검색·선택/복사 UI는 후속 보류, 목차·비밀번호 PDF 읽기는 필수 제외다. 검색 진단 Draft PR #12와 원인 미확정 이력은 보존하며 해결/완료로 세지 않는다. OCR·EPUB·주석/crop·Figma 전면 디자인 적용·다른 기기 검증·스토어 출시는 이번 범위가 아니다.

## 실제 검증 근거

상세 명령·실패/수정·APK와 결과는 [본문/접근성 최종 이력](2026-10-19-03-page-text-accessibility.md), [최종 통합 재현](../testing/p2-integration.md)을 따른다. 이번 마무리 변경에서는 앱 빌드/기기 검사를 반복하지 않는다.

- 최종 앱 기본 59개/실패0(453.3초), 별도 화질1개/실패0, 프로세스 복원 seed/verify 각1개/실패0. 본문10개와 큰 글꼴1개(100/150/200%×가로/세로 6조합)도 실제 별도 검사다. 서로 다른 실행을 합산하지 않는다.

## 외부 리뷰와 한계

CodeRabbit는 원래31개 파일 검토에 이어 실제 f8d9265→31ebdef, **31ebdef→b8b4100**을 검토했고 수정 지적이 없었다. 마지막은 [실제 완료 응답](https://github.com/AtraFelis/ebook_viewer/pull/17#issuecomment-6285584356)과 [검토 구간](https://github.com/AtraFelis/ebook_viewer/pull/17#issuecomment-6271088510)에서 확인했다. 마지막7개 선택 중 유사 문서5개는 건너뛰었고 프레임 계측/host 코드2개가 실제 대상이었다. 이후 결과 기록 Markdown을 코드 리뷰 완료로 확대하지 않는다.

10분 PSS는 약201→275MiB/30초 간격 관측 최고286MiB였다. 중간 감소도 있었으며 증가·변동을 기록했다. 캐시 가열/native·그래픽 메모리를 분리 측정하지 않아 긴 세션 누수 부재나 순간 peak 상한을 보장하지 않는다. 빠른 제스처 직후 페이지 커버 미준비는 frame 기준25/325→최종22/320, long393/2129표본이다. 물리 공백 프레임 수가 아니며 정지 후95% 선명화 지표와 구분한다.

실제 시스템 OOM/고해상도 개인 문서의 검색 사고 재현·다른 API/기기·제조사 provider 전반·재부팅·새 PC의 완전한 환경 복원은 미검증이다. 원본 DPI/압축별 원인 확정도 미완료이며 합성 자료의 성능 목표 충족과 구분한다. RSS/메모리 감시는 native 순간 할당의 hard limit가 아니다.

## 로컬 동기화와 다음 단계

`git fetch origin`으로 main 병합을 확인한 뒤 사용자 Figma SESSION/CHECKLIST 각6줄과 미추적 디자인 이력2개를 백업/해시 대조했다. 복구용 stash를 보존하고 현재 체크아웃에서 `git switch main`→`git pull --ff-only origin main`→stash apply→`codex/p2-completion`을 만들었다. 재적용 과정에서 Git의 줄바꿈 변환 때문에 전체 파일 byte hash가 달랐으나 정규화한 내용은 같았다. 백업과 내용을 대조한 뒤 원래 줄바꿈을 복원해 네 사용자 파일의 원래 byte hash까지 재확인했다. reset/clean·강제 push·새 worktree는 사용하지 않았다.

이번 변경은 완료 기록 Markdown뿐이다. 앱/Gradle/테스트/스크립트/의존성 불변을 diff로 검사하고 링크·공백 검사 결과와 문서 PR/CodeRabbit 실제 응답을 후속 기록한다. 사용자만 PR을 병합한다.

다음 단계는 별도 범위의 P3 안정화 또는 Figma 디자인 적용이다. 더 긴 메모리 세션·메모리 압박/기기·API 확대·CI 도구 유지보수는 후보이며 이번 문서 작업에서 착수하지 않는다. 검색·선택/복사 재개 및 새 의존성/배포·릴리스는 별도 결정/승인이다.
