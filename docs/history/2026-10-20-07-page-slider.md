## 구현

- PageScrubState는 실제 페이지와 미확정 목표를 분리한다. 정규화 위치를 전체 범위로 반올림/제한하고, 같은 페이지·취소·중복 확정·미확정 범위는 이동 대상을 반환하지 않는다. 페이지 수/실제 위치/활성 상태가 바뀌면 목표를 폐기한다.
- PageScrubberView는 48dp 터치, 4dp 트랙, 18dp 손잡이를 기존 light/dark 토큰으로 그린다. 단일 페이지/미확정 범위에는 손잡이/채움을 숨기고 숫자 이동도 비활성화한다. 비활성 트랙 터치도 빈 공간 닫기로 넘기지 않는다.
- 드래그 시작에서 기존 플링만 멈추고 PDF 위치/렌더 요청은 바꾸지 않는다. 목표 번호를 현재와 구분하며 드래그 중 렌더/기록을 요청하지 않는다. 놓을 때 기존 goToPage 경로를 한 번 사용하고 도구를 유지한다. 기존 숫자 입력 이동은 읽기로 복귀한다.
- ACTION_CANCEL/다중 포인터/앱 Window 밖/포커스 상실/Back/비활성화/재생성/문서 교체는 미확정 목표를 버린다. Back은 먼저 미리보기만 취소하며 후속 Back이 도구를 닫는다. Activity에서도 다중 포인터를 확인해 형제 View로 나뉘는 이벤트 경로를 보완했다. [공식 MotionEvent 취소 의미](https://developer.android.com/reference/android/view/MotionEvent#ACTION_CANCEL)를 확인했다.
- 페이지 카탈로그 준비 중에는 실제 위치를 유지 표시하고 중복 요청을 막는다. 준비 안내가 카탈로그 콜백에서 완료 안내로 덮이지 않도록 보완했다. 기존 렌더러/64MiB 캐시·줌/가로 위치/읽기 기록 경로를 재사용한다.
