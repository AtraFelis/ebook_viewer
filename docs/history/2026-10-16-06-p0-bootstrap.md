## 승인과 변경

구체적 구성 승인 요청에 사용자가 “좋아”로 응답했다. Kotlin/stdlib 2.1.20, AGP 8.7.2, Gradle 8.9, JDK 17, compile/target 35/min 23, Build Tools 34.0.0, P0 PdfRenderer+View/Canvas를 채택했다. 기존 로컬 설치에 개발을 맞추지 않고 프로젝트 도구 디렉터리에 승인 구성을 설치했다. Compose 최종 선택은 여전히 별도다.

AGENTS/SESSION/CHECKLIST/ADR/환경/계획을 갱신하고 앱, Wrapper, 버전 카탈로그, 의존성 잠금·검증 메타데이터, 테스트, Windows bootstrap, CI 정의를 추가했다. 개발용 applicationId는 dev.example.ebookviewer.p0. 작업 위치는 SESSION의 실제 Windows 체크아웃이며 worktree 생성·reset·clean·강제 push 없음.

## 연결 기기에서 추가 검증

사용자가 이어서 진행하도록 요청하고 기기 연결 방법을 문의한 뒤, 작업 중 API 33 기기가 연결·승인됐다. 모델 SM-N981N, ro.kernel.qemu=0. serial은 공개 기록에 남기지 않았다.

JUnit 4를 androidTest 구성에 재사용하고 최소 Instrumentation 브리지를 작성했다. 앱 runtime 의존성은 불변이다. scripts/device-smoke.ps1은 미승인/0대/복수 기기를 구분하며 지정 기기에만 앱과 테스트 APK를 설치한다. 첫 설치 시도는 instrumentation용 lock 갱신 작업과 동시에 시작되어 기존 lock에 JUnit/Hamcrest androidTest 구성이 없어 strict 단계에서 차단됐다. 갱신 작업 완료 후 순차 재실행하여 해결했다. 검증을 끄지 않았다.

기기 테스트 첫 3개 모두 통과: matrix 타일의 실제 색상, 손상 문서 IOException, production PdfWorker의 비동기 타일 게시. 앱 설치·Activity launch Status: ok 확인. 합성 문서 UI 열기/Activity 재생성 테스트를 추가해 후속 실행 중이며 최종 결과는 아래에 기록한다. 프레임/메모리 측정이나 API 23·35 검증으로 확대 해석하지 않는다.
