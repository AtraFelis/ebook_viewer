# 서재·문서 조작 UI 구현과 검증

2026-10-24. 현재 체크아웃 `codex/bookshelf-library-redesign`의 기존 미커밋 작업을 이어 진행했다. 사용자 ‘좋아’ 뒤 계획을 단계별로 구현했다. 더보기의 문서 추가는 후속 답변의 2번, **이미 등록한 PDF 선택**으로 확정했다. 새 파일은 메인의 PDF 추가에서만 가져온다. 새 런타임 의존성·저장 형식 변경은 없다.

## 변경

- 메인 제목/이어 읽기는 보존하고 설정을 톱니바퀴, PDF 추가·정렬/전체 문서 등을 투명 아이콘 도구로 변경했다. 편집만 회색 테두리, 더보기는 작은 전경색 아이콘이다. 표지 실패는 앱 바탕과 다른 중성색/문서 아이콘이다.
- 목록 재사용 시 표지/제목/관리 영역의 LayoutParams를 명시하고 빈 관리 영역은 GONE으로 제외했다. 40×56dp 표지, 최소64dp 행/4dp 간격으로 줄였다. 문서 범위의 중복 이어 읽기는 제거했다.
- 선택0개에서 하단을 숨기고 전체 선택/뒤로가기 종료를 제공한다. 전체 문서는 삭제만, 책장/미분류는 이동+삭제를 제공한다. 원본 파일을 삭제하지 않는다.
- 플랫폼 Dialog의 하단 시트/별도 편집 화면을 추가했다. 동일 창 안에서 이름·확인 단계로 이동하며 입력/선택/순서/토글 초안을 Bundle로 보존한다. 편집의 삭제/순서 탭, 드래그·저장, 기존 등록 문서 추가, 새 책장 만들기와 정보 수정을 제공한다. 관리 조작은 짧은 가로 화면에서 목록 헤더와 함께 스크롤한다.
- 이동은 source/target/keep를 한 번의 AtomicFile 쓰기로 처리한다. keep=false는 현재 관계만 제거하고 다른 소속을 유지한다. 미분류에서 선택한 문서만 분류하며 원본/위치/문서 순서를 보존한다. 기존의 모든 소속을 덮는 단일 이동 API를 새 UI에 연결하지 않았다.
- 책장 순서 저장은 전체 ID 집합을 검증한다. 일괄 책장 삭제는 관계만 제거하고 문서/원본/읽기 위치는 유지한다. 이름순 표시와 저장한 사용자 순서는 별개다.

## PC 검증

PowerShell에서 `. ./scripts/android-env.ps1` 후 다음을 실행했다.

`./gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug ktlintCheck --max-workers=2 --dependency-verification strict --console=plain`

- 초기 실행: ktlint 줄바꿈/서식 위반으로 실패. 이번 변경 파일에만 ktlint CLI1.5.0 --format을 명시적으로 적용했다. 전역 포맷은 하지 않았다.
- 2차: 새 썸네일의 draw 중 RectF 할당1개와 더 이상 쓰지 않는 문자열4개로 Lint5오류/경고0 실패. 객체를 미리 보유하고 불필요한 리소스를 제거했다. 억제/기준 완화는 하지 않았다.
- 3차:21초 성공. 단위83개, 실패/오류/건너뜀0. 새 두 검사에서 다중 소속 이동/현재 관계 보존·없는 대상 거절/재시도 멱등성·정확한 순서 집합과 일괄 삭제의 문서 보존을 검증했다.
- 4차 UI/계측 보완:11초 성공. 관리 헤더 스크롤/중성 표지 보완 후 앱·계측/Lint/ktlint10초 성공. 단위 로직은 이후 변경하지 않아83개를 반복하지 않았다. 로그는 `local-artifacts/library-refinement-*-build.log`이며 Git에 올리지 않는다.

## 기기 진행과 제한

첫 연결 확인에서는 기기가 없었고 사용자 재연결 뒤 승인된 기기/잠금 해제를 확인했다. 정식판은 건드리지 않고 개발용 `.p0`와 계측만 `adb install -r`로 갱신했다.

- 새 합성100문서 목록 검사1개 성공: 제목의 실제 폭/행 높이·재사용·중복 이어 읽기 없음·전체 문서의 이동 없음·0/1/전체 선택·뒤로가기·책장 안의 이동 하단.
- 새 이동/등록 추가 검사1개 성공: keep 기본값/꺼짐의 창 재구성 복원, source만 제거하고 다른 관계/위치 보존, 등록 문서를 source에 다시 추가해 기존 소속 합집합 유지. 개인 기록 파일을 테스트로 대체하지 않는다.
- 기존 카드/편집 검사1개 성공: 미분류 조건/더보기와 편집의 투명 배경·별도 편집 콜백. 예전 ‘채운 배경’ 기대를 새 요구의 투명 기대에 맞췄으며 검사를 건너뛰지 않았다.
- 드래그 검사는 초기 targeted input이 시스템 드래그 표면의 UID 경계에서 거절돼 실패했다. UIAutomation 입력으로 바꾼 뒤에는 실제 순서 변경을 확인하지 못했다. 새로 만든 손잡이의 배치 완료 대기를 추가해 재확인 중이다. 이 실패를 앱 저장/기기 성능 통과로 보고하지 않는다.

배치 완료 대기를 추가한 드래그 검사는 실제 드래그/저장 전 취소/창 재구성 복원과 합성 저장 실패 후 초안 유지·재시도까지1개/실패0이다. 같은 최종 앱에서 나머지6개도 재확인해 고유7개 분할 성공했다. 메인 복원/격자 선택 복원·문서 격자의 큰 글꼴/가로6조합을 포함하며 기본96개 전체는 아니다. 이름순 표시에 저장한 사용자 순서를 강제 적용하지 않는다.

합성 카탈로그만 그린 PNG를 PC로 가져와 대조했다. 대체 표지 아이콘의 Drawable.bounds 수신자 혼동으로 모서리에 걸리는 결함과 PDF 추가의 글자/아이콘 간격을 추가 보완했다. 최종 표시 APK의 strict debug/계측/Lint0/0·ktlint10초와 메인 관련1개/실패0 재검사가 성공했다. 갱신한 합성 PNG에서 아이콘 중앙 정렬·글자 간격을 확인했다. 앞선7개 전체를 이 표시 APK에서 반복한 것으로 보고하지 않는다. 앱/계측 force-stop·ADB kill-server를 실행해 종료했다.

사용자 최종 화면 수용은 대기다. 기본96개 전체/장시간·성능/OOM·다른 API/정식 서명·설치/원격 CI/CodeRabbit은 이번 검증으로 대체하지 않는다. 아이콘 모양만으로 읽기 성능을 반복 측정하지 않는다.

## 보존과 게시

사용자 `docs/design.md`/`gradle.properties` SHA-256은 기존 값과 동일하고 stash `20fbf558655599c0e7af93c1855c30789dafdb91`은 commit 객체로 보존돼 있다. git diff --check는 공백 오류0이다. 개인 PDF/읽기 기록/키를 로그·PC·외부로 추출하지 않았다. 이 단계에서 commit/push/PR/리뷰 호출은 하지 않았다. 최종 사용자 화면 수용 후 관련 변경을 묶어 게시한다.
