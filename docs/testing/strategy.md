# 검증 전략

2026-10-22 개인 사용 후속은 [전용 계획](../plan/reader-usability-follow-up.md)/[실제 결과](../history/2026-10-22-05-reader-usability.md)를 따른다. 기록v1~v4·원본 앵커/남은 페이지 기하·가시 타일은 JVM, 미준비 배경색·픽셀 clip·여백 저장/실패/재실행·방향 빠른 진입은 합성 기기로 확인한다. 새 ReaderUsabilityDeviceTest5개는 `-e methodClass usability -e method <메서드명>`의 명시적 실행이며 기본91개에 포함하지 않는다. 큰 글꼴 검사는 새 방향 아이콘과 네 여백 슬라이더도 접근 대상으로 삼는다. 기존 전체/장시간/성능 결과를 이번 앱 전체 재실행으로 확대하지 않는다.

2026-10-22 현재 기준은 [P3 최종 통합 기록](../history/2026-10-22-01-p3-final-verification.md)이다. 기본91개 고유 검사의 최신 성공을 분할 보완해 확인했으며, 최초 전체81통과/3실패/7미완료·720초 중단과 미재현 회전/포커스 이력을 보존한다. 단일전체91개 성공으로 보고하지 않는다. 단위53개는 이번에 Gradle up-to-date 재사용했고 아래41/48 등 수치는 당시 기록이다. 기본 전체의 한도900초·개별 선택·고지/설치 절차는 [배포 준비](../release-preparation.md)를 따른다.

과거 표시 설정 검증 당시 단위 테스트 41개와 API 33 기본 전체 계측 48개가 통과했습니다([당시 표시 설정/회귀](../history/2026-10-19-02-reader-display-settings.md), [수명/캐시 검증](../history/2026-10-17-10-reader-lifecycle.md)). 별도 화질 대조/seed·force-stop·verify는 당시 기본48개와 구분합니다. 메모리 알림 주입/실제 HOME 복귀를 실제 시스템 고갈/OOM·재부팅 검증으로 취급하지 않습니다. 디버그 기능 검증과 릴리스 성능 판정은 구분하며 실제 수치는 history에 기록합니다. 아래 모든 성능 목표/다른 기기 범위를 통과한 것은 아닙니다. P1은 사용자가 현재 성능을 수용했으므로 별도 성능 최적화를 필수로 추가하지 않습니다.

## 성능 초기 목표

2026-10-16 사용자 결정에 따라 이번 P0 판정 기기는 개인용 SM-N981N(API 33)으로 한정한다. 아래 기준의 다른 대표 기기/API 검증은 후속이다.

대표 중급 실기기, release/profileable, 60Hz, 로컬 PDF 기준. 기기·OS·메모리·주사율·SHA를 기록합니다.

- warm 연속 플링/핀치 프레임 p95 ≤ 16.7ms, p99 ≤ 33.3ms.
- 30초 시나리오의 50ms 초과 프레임과 jank 비율도 기록. 90/120Hz는 해당 예산으로 별도 평가.
- 일반 PDF 최초 유효 문서 화면 ≤ 2초 잠정 목표. cold/warm·provider·파일 크기 명시.
- 앱 소유 렌더 캐시 초기 상한 목표 64MiB 이하. 총 PSS/Java/native/graphics는 별도 측정 후 P0 예산 확정.
- 10분 이상 왕복 읽기에서 지속 메모리 증가/OOM/핸들 누수 확인.

Macrobenchmark/Perfetto/FrameMetrics 중 지원 도구 선택. 동일 조건 3회 이상 측정하고 에뮬레이터로 실기기 성능을 대체하지 않습니다. 목표 변경 근거는 history에 남깁니다.
