## 이번 범위

- 설정의 백그라운드 저장 중 페이지 이동/문서 교체/앱 복귀에서 최신 읽기 위치와 실제 저장된 잠금 선택을 함께 보존한다. 재현 가능한 경합을 합성 문서와 테스트 전용 큐 장벽으로 먼저 확인한다.
- 확대·잠금·페이지 이동과 재시작/문서별 이어 읽기의 조합을 점검한다. 기존 PdfRenderer/타일/64MiB 캐시·스택·저장 형식v3를 유지하며 새 의존성은 도입하지 않는다.
- 기존 수명주기 검사의 캐시 상한/정지 중 캐시 비움·복귀/취소된 타일 무시/문서 닫기의 descriptor 해제를 현재 앱에서 확인한다. 메모리 알림 주입은 실제 OOM/시스템 메모리 압박으로 보고하지 않는다.
- 검색·선택/복사·목차·비밀번호 PDF·TalkBack 전용 작업·EPUB·다른 기기/API·릴리스는 제외한다. 긴 세션과 실제 메모리 압박, 새로운 렌더 성능 실험은 이 작은 묶음의 종료 조건으로 늘리지 않고 후속 P3에 남긴다.
- 앱 아이콘은 디자인 시안의 최종 선택 후 별도 변경으로 진행한다. 시안 탐색을 최종 채택으로 간주하거나 미확정 이미지를 앱에 적용하지 않는다.

## 검증과 종료 조건

1. 의심 경로를 실제 Activity와 합성 문서로 재현하고 원래 실패 결과를 보존한다. 재현되지 않으면 추정만으로 앱을 고치지 않는다.
2. 확인된 오류만 최소 수정한다. 저장 큐 순서와 성공/실패 결과에 맞춰 읽기 위치를 갱신하고, 이전 설정 값으로 성공한 설정을 덮지 않는다. 문서 닫기/교체 뒤 이전 문서에 해당하는 저장을 잃지 않는다.
3. strict 앱/계측 빌드·관련 단위·Lint·ktlint와 새 경합 검사/기존 수명주기·탐색·잠금의 관련 회귀를 한 번씩 실행한다. 앱 변경/실패/새 우려가 없는 검사를 불필요하게 반복하지 않는다. 기기가 없으면 PC 작업을 먼저 끝내고 기기 검증을 미완료로 남긴다.
4. 실제 통과·실패·미실행, 설치 APK/원래 설정 복원/앱·계측·ADB 종료를 기록한다. 기능/UI가 같고 합성 경합만 고친 경우 사용자에게 실제 저장 오류를 만들거나 같은 외관 수용을 반복하도록 요구하지 않는다.
5. SESSION/CHECKLIST/history와 PR 설명에 이번 검증 범위를 명시하고 리뷰 지적·CI를 처리한다. 사용자 병합까지 확인하면 이번 묶음을 닫는다. P3 전체/모든 PDF·전체 기기 검사·장시간/실제 OOM 검증 완료로 확대하지 않는다.
