# 서재·문서 조작 UI 정리 계획

작성: 2026-10-24. **상태: 구현·관련 PC/기기 검증·최종 중앙 삭제 확인창 사용자 수용 완료, 게시/CI·리뷰 준비.** 사용자는 계획 검토 뒤 ‘좋아’로 진행을 수용했다. 기존 미커밋 구현과 사용자 변경을 보존한다. 아래 계획 작성 시점의 미실행과 이후 실제 구현·검증은 이력에서 구분한다.

## 1. 확정된 방향

- 메인의 기존 제목·이어 읽기 카드·PDF 추가와 책장 격자 구조는 유지한다. PDF 추가에서는 ‘여러 파일 선택’ 문구만 제거하고 SAF 다중 선택 동작은 유지한다.
- 일반 도구는 아이콘과 짧은 글자를 함께 쓴다. 뒤로가기·설정·더보기·삭제처럼 뜻이 익숙한 동작은 아이콘만 사용한다. 뒤로가기는 왼쪽 꺾쇠, 설정은 톱니바퀴, 삭제는 빨간 휴지통이다.
- 기본 버튼에는 지속 배경을 두지 않고 눌림 반응만 제공한다. 최신 사용자 피드백에 따라 메인 편집의 회색 테두리도 제거한다. 더보기는 배경 없는 작은 아이콘이며 어두운 테마에서는 흰색, 밝은 테마에서는 읽을 수 있는 전경색을 쓴다. 작은 시각 크기와 누를 영역을 구분해 터치 영역은 확보한다.
- 표지가 없는 PDF도 앱 바탕과 구분되는 중성색 대체 표지/문서 아이콘으로 표시한다. 표지 성공 여부가 문서 열기를 막지 않는다.
- 실제 책장과 미분류 가상 책장은 구분한다. 미분류는 내용이 있을 때만 표시하며 이름 변경/삭제/사용자 순서 편집 대상에 넣지 않는다.
- 문서 삭제는 기존 동작을 유지한다. 앱의 등록·읽기 위치와 모든 책장의 해당 문서 등록을 제거하되 **원본 PDF는 보존**한다. 확인에서 이 범위를 명시한다. 책장 삭제는 해당 책장/관계만 제거하고 문서 등록·원본·다른 책장 소속을 보존하는 별도 동작이다.
- **전체 문서 화면에서는 책장 이동 기능을 제공하지 않는다.** 길게 눌러 선택한 뒤 하단에는 삭제만 표시한다.

## 2. 화면별 구성

### 메인 책장 영역

기존 메인 상단 배치를 유지한다. 설정 글자 버튼을 톱니바퀴로 바꾸고, PDF 추가 문구를 짧게 한다. 책장 조작 줄에는 개수·투명 편집·아이콘이 붙은 정렬/전체 문서를 둔다. 표지 묶음·이름·문서 수와 실제 최근 읽은 시각을 유지하며 더보기의 시각 크기를 줄인다.

책장 더보기는 하단 시트로 연다. 문서 추가·책장 정보 수정(현재 이름 변경)·책장 삭제를 아이콘과 함께 제공하며 삭제만 빨간색으로 강조한다. 미분류에는 실제 책장의 이름 변경/삭제 메뉴를 노출하지 않는다. 새로 저장하지 않는 책장 생성/수정 시각이나 저자 정보를 꾸며 넣지 않는다.

### 책장 편집

메인 편집은 격자 안에 위/아래 버튼을 늘어놓는 대신 별도 ‘내 책장 편집’ 화면을 연다. 상단 닫기와 ‘책장 삭제 / 순서 바꾸기’ 두 탭, 책장 표지·이름·문서 수의 목록으로 구성한다.

최신 참고 사진에 따라 제목을 중앙에 놓고 편집 안의 생성은 오른쪽 +로 둔다. 두 탭은 회색 구역/선택된 표면으로 구분하고 원형 선택을 행 왼쪽에 둔다. 삭제는 하단 중앙 원형 버튼이며 미선택 회색 비활성/선택 후 빨간 휴지통이다. 편집의 이 탭/삭제 버튼 배경은 사용자가 보낸 참고의 명시적 예외이며 일반 도구의 배경을 다시 채우지 않는다. 하단 시트는 뒤 창을 어둡게 하고 내용에 맞는 높이와 시스템 안전 여백을 사용한다. [이번 시각 보완](../history/2026-10-24-04-bookshelf-reference-polish.md)을 따른다.

- 책장 삭제: 체크/전체 선택 후 하단 휴지통으로 선택 책장만 삭제한다. 확인에는 책장 개수와 문서/원본 보존을 명시한다.
- 순서 바꾸기: 오른쪽 드래그 손잡이로 순서를 조정하고 ‘저장하기’로 확정한다. 저장 전에는 실제 순서를 쓰지 않고 닫으면 초안을 취소한다. 저장 실패는 초안과 재시도를 유지한다.
- 메인의 상시 추가 버튼은 두지 않는다. 기존 요구의 책장 생성은 편집 화면에서 제공하고, 새 참고의 이동 시트에서도 목적지를 만들 수 있게 한다.

### 전체 문서·책장 안·미분류의 평상시 화면

상단은 뒤로가기 아이콘·현재 범위 이름·더보기다. 본문 위에는 문서 수, 아이콘이 붙은 정렬/격자·목록 전환을 둔다. 제목이 보이는 격자/목록을 유지하고 **이 화면의 중복 ‘마지막으로 읽던 문서’ 줄은 제거**한다. 메인 상단 이어 읽기는 유지한다.

목록은 작은 표지와 제목/보조 정보의 촘촘한 행으로 구성한다. 제목은 최대 두 줄을 확보하고 숨지 않게 한다. 과한 세로 간격과 비어 있는 관리 영역을 없앤다. 기본 행 높이는64~72dp를 출발점으로 제안하되 큰 글꼴/긴 제목에서는 자연스럽게 늘려 잘리지 않게 한다. 시각 아이콘20~24dp와 최소48dp 터치 영역은 구분한다.

### 문서 선택 상태

길게 누르기 또는 선택 동작으로 진입한다. 상단에는 선택 개수와 체크 상태를 가진 ‘전체 선택’을 표시한다. 문서 탭은 선택/해제만 수행한다. ‘관리 마침’은 없애고 뒤로가면 먼저 선택 상태를 끝낸다.

최신 사진 요청에 따라 선택 전 정렬/보기 사이 체크 아이콘은 제거했다. 선택 후 하단은 아이콘+책장 이동 둥근 버튼과 빨간 휴지통 원형 버튼을 중앙에 모으며, 전체 문서는 삭제만 표시한다. 버튼의 얇은 경계/그림자는 참고 사진에 맞춘 선택 도구의 예외다. 책장·문서 삭제 확인은 취소/빨간 삭제가 있는 내용 높이 하단 시트로 통일한다. 사용자가 이 세 항목을 수용했으며 이동 시트의 글자/행 사이4~8dp 여유를 추가 요청했다. [최신 실행 이력](../history/2026-10-24-05-document-selection-and-deletion-sheets.md)을 따른다.

이후 사용자 정정으로 **삭제 확인만 화면 정중앙의 둥근 대화상자**를 사용한다. 뒤 창은 어둡게 하고 중앙 제목/안내문, 테두리형 취소·붉은 삭제 버튼을 나란히 둔다. 이전 하단 경고는 최종안이 아니다. 이동/더보기는 하단 시트로 유지하며 원본 보존·취소/복원 의미도 유지한다. [중앙 확인 변경 이력](../history/2026-10-24-06-centered-delete-confirmation.md)을 따른다.

- 선택0개: 하단 작업 영역을 숨긴다.
- 전체 문서에서 선택: 빨간 휴지통만 표시한다.
- 실제 책장에서 선택: 아이콘+‘책장 이동’과 빨간 휴지통을 표시한다.
- 미분류에서 선택: 분류를 위한 ‘책장 이동’과 삭제를 제공하는 안을 제안한다. 미분류는 출발 책장이 아니므로 아래의 남겨두기 토글은 표시하지 않는다.

하단 작업 영역은 내용을 덮지 않는 별도 영역으로 두고 마지막 문서까지 스크롤할 수 있게 한다. 시트가 열렸을 때의 뒤로가기는 시트만 닫고 문서 선택을 보존한다. 그 다음 뒤로가기에서 선택 상태를 끝낸다.

### 책장 이동 시트

사용자가 추가로 보낸 참고처럼 제목/뒤로가기, 새 책장 만들기, 표지와 이름을 가진 목적지 책장 목록, ‘이 책장에도 남겨두기’ 토글로 구성한다. 전체 문서에서는 이 시트로 진입하지 않는다.

- 토글 켜짐: 목적지에 추가하고 현재 책장 및 다른 기존 책장 소속을 유지한다.
- 토글 꺼짐: **현재 책장 소속만** 제거한 뒤 목적지에 추가한다. 다른 책장 소속은 유지한다.
- 미분류에서 이동: 토글 없이 목적지에 추가해 분류한다. 등록·원본·읽기 위치는 그대로다.
- 출발과 같은 실제 책장은 목적지에서 제외하고 중복 소속은 만들지 않는다. 원본 PDF 파일을 복사/이동하지 않는다.
- 성공은 이동/남겨두기를 하나의 저장으로 확정한다. 실패 시 대상 문서·목적지·토글 선택을 보존하고 재시도할 수 있게 한다. 취소/뒤로가기로는 소속을 변경하지 않는다.

## 3. 수용한 세부 흐름과 배치

계획 수용 시 아래 기본 흐름을 채택한다. ‘문서 추가’는 후속 질문에서 사용자가 2번(이미 등록한 PDF 선택)으로 확정했다.

- 남겨두기는 참고 이미지와 기존 소속 보존을 고려해 **기본 켜짐**을 제안한다.
- 참고처럼 목적지 하나를 누르면 처리하는 흐름을 제안한다. 한 PDF가 여러 책장에 속하는 기능은 토글 켜짐으로 유지한다. 여러 목적지를 한 번에 고르는 추가 UI는 필수로 두지 않는다.
- 새 책장 생성 후에는 이동 시트로 돌아와 새 책장을 선택해 처리한다. 생성만으로 선택 문서를 바로 이동시키지 않는 안이다.
- 책장 더보기의 ‘문서 추가’는 이미 앱에 등록한 PDF 중 선택한다. 새 파일은 메인의 PDF 추가에서만 가져온다. 기존 소속·읽기 위치를 보존하며 선택한 책장 관계만 추가한다.
- 편집 화면은 두 탭, 이동/더보기는 하단 시트로 역할을 나눈다. 색상은 참고의 흰 배경을 고정 복제하지 않고 앱의 밝음/어두움 테마에 맞춘다. 메인의 이어 읽기 강조 배경은 기존 배치를 기준으로 시안에서 함께 판단한다.

## 4. 읽기 전용 원인 검토

목록 제목 누락은 데이터 제목이 사라진 문제보다 셀의 폭 배분 문제 가능성이 높다. 현재 Cell은 세로 격자 기준으로 image/caption/buttons를 추가한 뒤 목록에서 가로로 바꾼다. 제목 쪽에 가중치를 주지만 빈 buttons 컨테이너의 기존 가로 크기는 명시적으로 다시 설정하지 않는다. 빈 관리 영역이 제목 폭을 차지하는 것이 유력한 원인이다. 이번에는 소스만 읽었고 새 기기 재현/확정은 하지 않았다.

개발 단계에서는 목록의 표지/제목/선택 표시 영역 크기를 각각 분명히 하고 빈 관리 영역을 배치에서 제외한다. 제목의 실제 표시 폭·행 간격을 기기에서 확인해 원인과 해결을 검증한다. 격자와 목록 재사용 전환도 확인한다.

## 5. 진행 순서와 완료 기준

1. 화면 역할/이동 의미를 먼저 검토했고 사용자 ‘좋아’로 방향을 수용했다. 개발 전 계획 작성과 이후 구현을 이력으로 구분한다.
2. 메인/문서 평상시·선택 상태, 편집 두 탭, 이동/더보기 시트의 배치를 아래처럼 구체화했고 사용자 표시 이미지와 대조한다.
3. 목록 제목/간격·아이콘 도구, 선택 하단/범위별 동작, 책장 편집/드래그 저장·이동 토글을 구현했다. 새 라이브러리는 추가하지 않았다. 실제 검증/미결은 [구현 이력](../history/2026-10-24-03-library-interaction-implementation.md)을 따른다.
4. 변경 위험에 맞는 검사만 실행한다. 목록 제목의 실제 폭/긴 이름·큰 글꼴, 선택0/1/전체·뒤로가기·범위별 하단, 취소/실패/재생성 초안 보존, 토글별 다중 소속/읽기 위치 유지·삭제 시 원본 보존이 기준이다. 아이콘 모양만 바뀐 부분 때문에 전체 읽기·성능 검사를 반복하지 않는다.
5. 사용자 화면 수용과 필요한 PC/기기 검증을 마친 관련 변경을 묶어 PR/CI와 CodeRabbit 실제 리뷰를 진행한다. 이전 성공을 새 구현 결과로 취급하지 않으며 병합은 사용자다.

배치는 메인 ‘개수/편집 — 정렬/전체 문서’, 문서 ‘꺾쇠/제목/더보기 — 개수/정렬/보기 — 목록 — 선택 시 하단 작업’, 편집 ‘닫기/제목 — 삭제/순서 탭 — 목록 — 삭제 또는 저장’, 이동 ‘뒤로/책장 이동 — 새 책장/목적지 목록 — 남겨두기’로 구체화한다. 단순 아이콘 교체 때문에 PDF 성능 측정을 반복하지 않고 목록 폭/선택/저장 의미의 회귀를 검증한다.
