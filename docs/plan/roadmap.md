### 목표와 우선순위

개인용으로 불편함 없이 PDF를 하나의 긴 스크롤 문서처럼 읽는 수준을 완성한다. 대상은 현재 SM-N981N(API 33)이며, 기능 완성을 먼저 하고 세부 폴리싱은 이후 진행한다. 이 단계의 Ebook/읽던 책은 PDF 문서를 뜻하며 EPUB 지원은 후속 범위를 유지한다.

2026-10-16 사용자 정정: 현재 성능으로 충분하므로 요구사항 1번의 **별도 렌더링·스크롤 성능 최적화는 P1 필수 범위에서 제외**한다. P0의 비동기 렌더링·가시 미리보기·타일·64MiB 캐시를 기준으로 사용한다. 기존 빠른 이동의 미준비 영역 개선이나 새 성능 목표 달성을 P1 완료 조건으로 추가하지 않는다. 기능 추가에 따른 명백한 성능 악화·ANR·OOM은 회귀로 처리한다.

우선 완성할 기능은 읽기 기록/이어 읽기, 가로·세로 고정, 사용자 지정 배경색, 몰입형 전체 화면, 읽는 도중의 설정 접근이다. 기존 P1의 파일 접근·오류, 간격/크기 모드, 줌/앵커 복원, 페이지 이동·북마크도 유지한다. 새 기능을 위해 저장/UI 라이브러리를 자동 채택하지 않으며, 새 런타임 의존성 또는 승인 스택 변경은 AGENTS의 승인 절차를 따른다.

### P1-1. 파일 접근·읽기 기록·이어 읽기

2026-10-17 후속: [ADR 0007](../adr/0007-document-access-and-failure-recovery.md)에 원인별 실패/재시도와 비탐색 파일의 취소 가능한 제한 복사를 구현/검증했다(API 33, 최종 전체 36개). 실제 테스트 결과는 [이력](../history/2026-10-17-09-document-access.md)을 따른다. 자체 test provider의 권한/스트리밍 검증을 제조사 DocumentsUI·재부팅·개인 PDF 수용으로 확대 해석하지 않는다.

2026-10-17 첫 구현: 새 런타임 의존성 없이 플랫폼 기반 목록/문서별 위치 저장·복원을 구현한다([ADR 0002](../adr/0002-local-reading-records.md)). 실제 통과 항목은 CHECKLIST/history로 판정한다. provider별 수용과 비탐색 임시 복사는 후속이며 P1-1 전체 완료를 뜻하지 않는다.

- ‘PDF 열기’는 SAF로 기기의 문서를 선택하는 로컬 가져오기다. 서버 업로드·계정·외부 서비스는 요구하지 않는다.
- 최근 읽은 PDF 목록과 읽던 Ebook 목록을 제공한다. 최근 목록은 마지막 열기 순서, 읽던 목록은 저장된 읽기 상태를 가진 문서의 이어 읽기 진입점으로 구분한다. 동일 문서의 식별자·기록은 공유하고 중복 등록을 방지한다.
- 문서 식별/접근 정보, 표시 이름, 최근 열기 시각, 페이지 인덱스·페이지 내부 앵커·사용자 줌·유효 가로 위치·간격/크기 모드를 로컬에 저장한다. 화면 px 오프셋만으로 복원하지 않는다.
- 목록에서 문서를 선택하면 마지막 페이지의 **읽던 내부 위치**부터 이어 읽는다. 새 문서는 기존 최초 열기 기본값을 사용한다. 문서 전환·백그라운드·종료·프로세스 재생성에서도 기록을 보존하며 저장 I/O는 UI 스레드를 막지 않는다.
- 지원하는 provider의 영구 URI 권한을 확보한다. 권한 소실·이동/삭제·변경된 문서·손상/빈 파일은 원인을 안내하고 다시 선택할 수 있게 한다. 재연결 가능한 읽기 기록을 임의로 지우지 않는다. 비탐색 provider는 용량 상한·취소·실패 정리를 갖춘 앱 전용 임시 복사로 처리한다.
- 최근 목록/북마크에서 항목을 제거해도 원본 파일은 삭제하지 않는다. PDF·URI·추출 텍스트를 로그나 외부 서비스로 보내지 않는다.

수용 기준: 서로 다른 PDF A/B를 오가고 앱을 재시작해도 각 기록·줌·내부 앵커가 복원된다. 최근/읽던 목록에서 같은 문서를 중복 생성하지 않는다. 접근 권한 소실과 파일 재선택을 안내하며 정상 문서 읽기로 복귀할 수 있다.

### P1-2. 몰입형 읽기와 설정 진입

2026-10-17 후속 구현: 플랫폼 FrameLayout/WindowInsets와 중앙 탭 메뉴로 읽기 UI를 분리한다. P1-3 방향 설정과 함께 [ADR 0003](../adr/0003-immersive-reader-and-orientation.md)에 기록하며, 실제 수용 결과는 CHECKLIST/history로 구분한다.

- 비열람 화면은 최근/읽던 목록, PDF 열기, 설정 진입을 제공한다. 파일을 연 뒤 ‘PDF 열기’ 버튼·상태 문구·상시 도구가 콘텐츠를 가리거나 읽기 영역을 차지하지 않도록 분리한다.
- 기본 읽기 상태는 콘텐츠 중심의 전체 화면이다. 앱 도구와 상태/내비게이션 시스템 바를 숨긴다. OS 제스처에 의한 시스템 바의 일시 노출은 허용하고 정상 읽기 상태로 돌아오게 한다.
- 읽는 도중 **화면 중앙 단일 탭**으로 도구/설정 메뉴를 표시하고 다시 숨길 수 있게 한다. 추가 특수 제스처는 MVP의 필수가 아니다. 드래그·플링·핀치를 설정 호출로 오인하지 않는다.
- 설정을 닫으면 전체 화면으로 돌아간다. 메뉴 열기/닫기·뒤로 이동·시스템 바 변화가 읽던 위치·줌을 초기화하지 않아야 한다. 표시되는 메뉴에는 실제 제공하는 기능만 배치한다.

수용 기준: 읽기 중 불필요한 앱 UI가 상시 보이지 않는다. 중앙 탭과 비열람 화면 양쪽에서 설정에 도달하고 다시 읽기로 돌아온다. 핀치/스크롤 후 메뉴가 의도치 않게 열리지 않는다.

### P1-3. 화면 방향 고정

2026-10-17 사용자 추가 요청으로 가로/세로 역방향 고정을 포함한다. 기존 설정 v1 이름을 유지하며 선택 저장 후 플랫폼의 역방향 상수를 적용한다([ADR 0003](../adr/0003-immersive-reader-and-orientation.md), [실제 검증](../history/2026-10-17-11-reverse-orientation.md)).

- 설정에 가로 고정·세로 고정·가로 역방향 고정·세로 역방향 고정을 제공하고 선택을 로컬에 보존한다. 기존 기기 회전 정책을 쓰는 자동 모드도 유지한다.
- 읽는 중 설정에서 방향을 바꿀 수 있으며 앱 재실행에도 선택이 유지된다. 고정 상태에서는 기기 센서 회전에 따라 화면이 바뀌지 않는다.
- 방향 변경에 따른 Activity/화면 재생성에서도 같은 문서의 내부 앵커와 사용자 줌을 보존한다. 자동 너비 맞춤으로 사용자의 확대를 덮어쓰지 않는다.

수용 기준: 세로↔가로 고정 전환, 앱 재실행, 자동 모드 복귀를 확인한다. 고정 중 물리 회전과 설정 변경 후에도 선택한 방향 및 읽기 상태가 유지된다.

### P1-4. 페이지 외부 사용자 지정 배경색

2026-10-17 사용자 범위 조정: 자동 모드는 P2로 이관한다. P1은 사용자가 배경색을 지정하고 유지하는 기능으로 완성한다.

- 앱이 그리는 페이지 외부 영역에만 사용자 지정 색상을 적용한다. PDF 자체의 흰 여백/콘텐츠, 페이지 간격, 색상 반전, 자동 crop과 구분한다.
- 미설정 기본값은 기존 중립 회색(#444444)이다. 흰색·검정·회색·종이색 버튼과 임의 #RRGGBB 입력·색상 미리보기를 제공한다. 잘못된 입력은 적용하지 않고 안내하며 취소하면 기존 값을 유지한다.
- 앱 설정에 저장해 재실행/다른 문서 열기에도 유지한다. 설정 저장은 UI 스레드를 막지 않으며 읽기 기록/방향 설정을 덮어쓰지 않는다.
- 배경색 변경은 타일을 재렌더링하거나 캐시를 비우지 않고 외부 영역만 다시 그린다. 읽던 줌·앵커를 유지한다.

수용 기준: 비열람/열람 양쪽에서 설정에 접근한다. 사용자 지정/기본 색상 적용, 잘못된 입력·취소, 재실행 보존을 확인한다. 지정 색상은 페이지 외부에만 반영되고 PDF 픽셀·줌·앵커·캐시가 변하지 않는다. 자동 색상은 P1 완료 조건이 아니다.

### P1-5. 기존 핵심 MVP 기능 완결

2026-10-17 후속: 백그라운드의 캐시 재충전과 취소 전 동일 키 타일의 늦은 표시를 [ADR 0008](../adr/0008-reader-lifecycle-and-cache-cancellation.md)에 따라 보완한다. 실제 기기 홈 왕복·캐시 상한/정리·문서 전환/FD 해제와 별도 프로세스 복원의 실행 결과는 [이력](../history/2026-10-17-10-reader-lifecycle.md)에서 판정한다. 이는 P2 선명도 최적화와 별개다.

2026-10-17 후속: 문서별 원본/너비 통일·간격 0~72 pt와 v1 읽기 기록 호환을 구현했고 로컬 검사까지 통과했다([ADR 0006](../adr/0006-page-layout-and-reading-records-v2.md)). 신규 API 33 기기 3개와 최종 전체 30개 회귀를 통과했다. 개인 PDF/실제 provider 수용과 P1 전체 완료는 별도다.

- 페이지 스냅 없는 단일 열 연속 스크롤과 두 축 이동, 페이지 경계의 공통 줌/가로 위치 유지.
- 사용자 확대/축소 피드백 반영: 최대 32 px/PDF point(이전 8의 4배), 화면 짧은 변 너비 맞춤의 75%를 핀치 축소 하한으로 사용한다. 회전/기존 기록 복원은 하한으로 강제 재맞춤하지 않는다.
- 혼합 크기 문서, 원본 크기/너비 통일 두 모드, 앱 페이지 간격 기본 0 및 사용자 설정. 간격/모드 변경 시 읽던 내부 앵커를 유지한다.
- 도구가 표시된 상태의 페이지 번호 확인·지정 페이지 이동, 북마크 추가·삭제·목록·이동. 이동 시 줌과 유효 가로 위치를 보존한다.
- 페이지 번호 표시/숨김을 사용자가 설정하고 재실행에도 보존한다(기본 숨김). 숨김 상태에서도 도구의 페이지 이동/북마크는 사용할 수 있으며 번호 overlay가 읽기 영역 크기를 바꾸지 않는다.
- 문서 교체·종료·메모리 압박 시 취소·바이트 캐시 상한·자원 해제, 지원하지 않는 문서와 빈 목록/실패 상태의 안내·재시도.

이 기능들은 기존 P1 범위로 유지하며, 위 사용자 추가 필수 기능을 먼저 사용할 수 있게 한 뒤 완결한다. 선택/복사는 P2에 남긴다. 검색은 2026-10-18 사용자 후속 결정으로 보류하고 P2 필수에서 제외했다. 목차/비밀번호 PDF 읽기도 P2 필수에서 제외했다.

4. 간격/크기 모드·페이지 이동·북마크·오류 UX 등 기존 MVP 범위 완결.
5. 현재 실제 기기에서 개인 PDF 수용 확인과 관련 회귀 검증. 기능 완성 후 세부 폴리싱.

완료는 위 수용 기준을 실제로 확인하고 CHECKLIST/SESSION/history에 기록했을 때 판정한다. 회전·백그라운드·프로세스 재생성 복원, 20페이지 왕복 줌 유지, 문서 접근 실패, 전체 화면/설정 진입을 검증한다. 현재 성능은 유지 기준이며 별도 최적화나 반복 성능 벤치마크를 필수 작업으로 두지 않는다. 성능 악화가 의심되는 변경에만 필요한 계측을 추가한다. P0 통과를 새 P1 기능의 구현/테스트 통과로 재사용하지 않는다.

## P2 — 기본 기능 확장

최신 사용자 결정(2026-10-18): **검색은 필수 기능이 아니므로 후속으로 미루고 P2 필수/종료 조건에서 제외**한다. 추가 검색 진단·제품 격리 통합을 현재 작업에서 보류하며, 검색 UI는 계속 제공하지 않는다. 원래 LOW_MEMORY 원인은 미확정이고 해결/기능 완료로 체크하지 않는다. [범위 변경/남은 일](https://github.com/AtraFelis/ebook_viewer/blob/f94ffc4/docs/history/2026-10-18-11-search-deferral.md).

이전 검색 실험은 개인 PDF에서 수용 실패해 철회했다. [격리된 별도 APK](https://github.com/AtraFelis/ebook_viewer/blob/f94ffc4/docs/adr/0011-isolated-search-diagnostics.md)의 보호 검사 9개·작은 이미지 430페이지 검색 통과와 앞선 RSS 보호 중단은 [실행 이력](https://github.com/AtraFelis/ebook_viewer/blob/f94ffc4/docs/history/2026-10-18-10-search-probe-termination.md)으로 보존한다. 고해상도 원본의 재현/해결 증거가 아니며 재개 시 [안전 조건](https://github.com/AtraFelis/ebook_viewer/blob/f94ffc4/docs/history/2026-10-18-08-p2-search-low-memory-withdrawal.md)을 다시 검토한다. 검색 진단 PR #12의 추가 작업/병합은 나머지 P2의 선행 조건이 아니다.

2026-10-18 사용자 결정: **기존 P2에서 목차·비밀번호 PDF 읽기는 후속 요청으로 제외**하고 나머지 기능 확장은 유지한다. Figma 디자인 적용은 별도 단계로 분리한다. 착수 검증으로 API 33/S·T 확장 23의 공개 API·합성 검색/선택/비밀번호 기능과 24개 표본의 격리 native 렌더 측정을 완료했다([실제 결과·한계](../history/2026-10-18-05-p2-platform-readiness.md)). 이후 보통 스크롤의 실제 onDraw 선명화 기준선·페이지 재사용 1차 개선을 전후 각 540표본으로 검증했고 개인 PDF 체감/화질 수용도 확인했다([1차 결과](../history/2026-10-18-13-sharpness-baseline-and-page-reuse.md)). 빠른 플링·고배율·복잡한 자료 및 최종 통합 앱 검증은 남아 있다. [세부 수용·정확한 완료 판정](p2-scope-and-completion.md)을 기준으로 하며 엔진/의존성 승인은 별도다.

1. 스크롤 선명도 복구 지연 측정/개선([진단 계획](p2-sharpness-recovery.md)).
2. 자동 배경색 추출·대체색·경계 안정화와 수동 모드 보존: 구현/37개 단위·44개 기본 기기·보강 배경 6개/수동·자동 프레임 비교·개인 PDF 수용 완료([실행/원격 미결](../history/2026-10-19-01-automatic-background.md)). PR/리뷰/원격 CI·사용자 병합과 최종 P2 통합 검증은 별도.
3. 텍스트 선택·복사와 필요한 페이지 단위 텍스트 접근/native 안전 검증.
4. 시스템/밝게/어둡게 테마, 앱 읽기 밝기, 열람 중 화면 유지, TalkBack/큰 글꼴(현재 페이지 본문 읽기 포함).

문서 전체 검색·강조·결과 이동은 후속 보류다. 검색을 빼더라도 선택/복사·TalkBack 본문 읽기를 암묵적으로 제외하지 않는다.

선명도 기준선/목표와 보통 스크롤 1차 개선은 완료했다. 선명도 후속은 빠른 플링·고배율·복잡한 자료 대조와 최종 통합 검증이다. 자동 배경색은 앱 검증/개인 수용을 완료했으며 PR 절차를 마친 뒤 읽기 설정으로 이어간다. 선택/본문 읽기에 필요한 API 33 플랫폼 어댑터·native 안전·구성 승인/ADR은 해당 기능에서 검증한다. 현재 PdfRenderer의 compile SDK 35 서명을 API 33 실행 증거로 쓰지 않는다. 남은 필수 기능이 엔진 미지원이면 대안을 결정하며 임의로 완료 처리하지 않는다. 검색 진단·목차 보조 엔진과 비밀번호 입력/복원은 선행 조건에서 제외하며 기존 북마크/페이지 이동과 지원 불가 오류 처리는 유지한다.

P2 종료는 위 전체 기능의 실제 수용, 최종 통합 앱의 기능/성능/접근성 회귀, 사용자 개인 기기 확인, 해당 PR 사용자 병합, 완료 기록까지 끝난 시점이다. P1 사용자 성능 수용을 새 P2의 선명화 검증으로 재사용하지 않는다. 날짜는 엔진 경로·승인·기준 측정을 마친 뒤 제시한다. Figma 전면 디자인 적용, OCR/EPUB/주석/crop/편집/암호화 저장, 다른 기기 검증과 스토어 출시는 이번 종료 조건이 아니다.

## P3 — 안정화

기기/API·긴 세션·메모리 압박·접근성 회귀, CI와 라이선스/릴리스 체크리스트. 서명·스토어 게시 별도 승인. 주석·crop·EPUB는 이후 범위.
