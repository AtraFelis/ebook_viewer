# 메인 방향 정책·최근 읽은 문서·내부 합성 자료

작성: 2026-11-07. 사용자가 본문과 메인 회전 분리, 최근 문서 약 5개, 사용자 메뉴의 합성 100페이지 제거를 요청했다. 기존 체크아웃의 병합된 PR #35 기준에서 진행하며 디자인/로컬 버전과 기존 상태 기록은 보존한다.

구현/PC 검증과 API33 관련 고유9개 분할 검증은 완료했다. 사용자 체감 수용/게시·CI/실제 리뷰는 실행 이력의 현재 상태로 별도 판정하며 아래 수용 기준을 모든 기기·전체 검사 통과로 확대하지 않는다.

## 구현 방향

1. 저장된 다섯 방향 설정은 **본문 읽기 전용**이다. 메인/책장/문서 목록에서는 `SCREEN_ORIENTATION_UNSPECIFIED`로 기기 회전 정책을 따른다. 본문에서 메인으로 복귀할 때 고정을 해제하되 저장된 선택은 보존하고 다음 본문 진입에 다시 적용한다. 메인에서 방향을 바꿔도 본문 설정만 저장한다. Activity 재생성/앱 재실행/비동기 설정 로드 뒤에도 현재 화면을 기준으로 정책을 적용하며, 읽기 줌/원본 앵커 복원을 유지한다.
2. 메인 ‘마지막으로 읽던 문서’ 영역을 ‘최근 읽은 문서’로 바꾼다. 위치가 있는 실제 열람 기록만 최근 열기 시각 내림차순으로 최대 5개 표시한다. 동률은 URI 키 순서로 안정화하며 문서 제목/URI는 로그에 남기지 않는다. 가장 최근 문서는 기존 이어 읽기 카드/진행률을 유지하고 나머지는 제목/읽기 위치가 있는 작은 항목으로 표시한다. 항목을 누르면 해당 위치/줌으로 열고 길게 누르면 기존 등록 제거 확인으로 연결한다. 책장/수동 정렬과 독립적이며 기록 삭제/재연결은 최신 카탈로그 결과에 따른다.
3. 전체 문서/책장 등의 더보기에서 합성 100페이지 항목과 UI 콜백 연결을 제거한다. 내부 `openSample`/자료 생성과 직접 사용하는 계측은 유지하고 새로운 외부 진입점이나 공개 메뉴를 추가하지 않는다.

## 저장·원본·의존성

기존 방향 AtomicFile v1과 읽기 기록 v6에서 표시 목록을 계산한다. 형식 변환/추가 라이브러리·서명/정식 앱 변경은 없다. PDF 원본·책장 소속·기존 기록을 보존한다.

## 완료 기준과 검사

- 메인·책장·콜드 시작은 시스템 정책, 본문은 저장된 고정 방향을 적용한다. 본문→메인→다른 본문과 Activity 재생성에서 설정/앵커·줌이 보존된다. 기존 방향 검사의 ‘메인도 고정’ 기대는 새 요구에 맞춰 교체한다.
- 최근 목록은 미열람 제외·최대5개·재열기 재정렬·중복 없음/삭제/재연결·수동 정렬 독립성을 단위 검사하고, UI의 다섯 항목 제목/콜백·큰 글꼴과 재실행 복원을 관련 계측으로 확인한다.
- 사용자 메뉴에 합성 항목이 없고 테스트의 내부 합성 열기가 유지된다.
- strict debug/계측 빌드·단위·Lint/ktlint와 관련 검사만 실행한다. 앱 전체/장시간·성능 검사를 일괄 반복하지 않는다. 기기가 없으면 PC 결과와 실제 미실행 기기 검증을 구분한다.
- 구현/검증이 모인 시점에 PR과 CodeRabbit 검토를 진행한다. 기존 미게시 상태 기록은 함께 정리하며 사용자 디자인/버전은 포함하지 않는다. 병합은 사용자다.
