# 앱 전용 PDF 복사본과 파일 오류 복구

2026-11-07. PR #36 병합 e8e8fd1 이후 현재 체크아웃에서 진행한다. 사용자는 원본 보존과 앱 복사본·기록의 함께 삭제를 선택했다. 새 런타임 의존성은 없다.

구현과 관련 PC/API33 검증·평소 PDF 읽기 사용자 수용은 완료했다. 고유11개 분할/보완 후5개·최초 실패와 미검증/게시 결과는 [실제 이력](../history/2026-11-07-02-managed-pdf-storage.md)을 따른다. 원격 CI/리뷰·사용자 병합은 각각 별도 확인한다.

## 저장과 전환

- 새로 등록하거나 여는 외부 PDF는 filesDir/documents에 복사한다. 캐시가 아닌 영구 앱 저장소이며 앱 삭제/데이터 초기화 때 함께 지워진다. 원본 수정/삭제/이동 권한은 사용하지 않는다.
- 읽기 기록의 URI 식별자는 유지하고 v7에 앱 생성 UUID 파일 토큰을 추가한다. 읽기 위치·북마크·여백·책장 소속을 다시 만들지 않는다. v1~v6 읽기를 유지하며 첫 v7 쓰기 전 기존 바이트를 before-v7로 보존한다. 기존 before-v6 백업은 그대로 둔다.
- 기존 등록 문서는 다음 열기 또는 재등록 시 복사한다. 이미 접근할 수 없는 원본은 자동 복원이 불가능하므로 다시 선택한다. 재선택이 성공해야 기존 기록과 북마크를 이전한다.
- 메인 스레드에서 복사하지 않는다. 복사는 작은 버퍼·취소 확인·공간 검사·임시 파일/동기화/원자적 이름 변경을 사용한다. 실패/취소 시 불완전 복사본을 정리한다. 비탐색 입력은 기존 256MiB/유휴 시간 제한을 유지한다. 정상 탐색 파일에 일괄 256MiB 제한을 새로 적용하지 않는다.
- 본문·공유 표지·본문 추출은 동일한 앱 복사본을 사용한다. 관리되는 복사본이 없어지면 임의로 외부의 다른 내용으로 바꾸지 않고 복구 창을 연다.
- 문서 등록 삭제는 저장 성공 뒤 해당 앱 복사본만 지운다. 책장 삭제/관계 이동으로는 PDF를 지우지 않는다. 메타데이터 쓰기 실패 시 복사본을 보존한다. 삭제 실패는 성공으로 숨기지 않는다.

## 복구 창

목록 사이의 파일 오류 설명/버튼을 없애고 중앙 창에 이유와 다시 시도·파일 다시 선택·문서 삭제를 둔다. 문서 삭제는 기존 중앙 확인을 거치고 원본은 보존한다. 닫기/뒤로·회전/복구 재시도에서 오래된 콜백이 새 문서를 덮지 않도록 한다. 실패한 문서의 앵커를 덮어쓰지 않는다.

## 검증과 완료

파일 복사/공간 부족/취소/임시 정리/소유권 경계·v7 왕복과 이전 버전 읽기를 PC에서 검사한다. 합성 PDF로 원본 이동·삭제 후 재열기/표지·이어 읽기, 기존 기록 변환/북마크·책장 보존, 복사본 없는 경우 복구 창/재선택·등록 삭제의 원본 보존을 관련 기기 검사한다. 이전 home 계측의 종료 후 저장/삭제 경합도 고친다. 사용자 파일명·본문·화면을 수집하지 않는다. strict debug/계측/release 빌드·단위·양쪽 Lint·ktlint를 실행하고 실제 결과를 기록한다. 검증한 변경을 모아 PR과 CodeRabbit을 요청하고 병합은 사용자에게 맡긴다.
