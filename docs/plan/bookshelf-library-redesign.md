## 목표와 확정한 요구

**사용자 최종 구체화: 기존 메인 상단을 유지하고, ‘등록한 문서’ 영역을 ‘책장’ 표지 격자로 바꾼다.** 기존 ‘내 문서’ 제목·설정·이어 읽기 카드·PDF 열기의 배치/동작을 유지한다. 별도 제목 옆 진입 버튼 대신 아래 책장 카드를 직접 눌러 해당 문서 목록을 연다. 뒤로가면 메인 책장 영역의 스크롤 위치를 복원한다. 최초 앱 화면을 별도 ‘내 서재’로 대체하지 않는다.

여러 문서를 찾고 분류하는 책장 문서 목록/선택 모드는 메인 책장 영역에서 진입하는 목적지다. 사용자 첨부의 세 번째 참고 화면은 책장 표지 묶음과 간결한 관리 구조를 참고한다. 스토어/구매/계정/관심 작품/하단 다섯 탭을 그대로 추가하지 않는다.

- 문서 보기는 **표지 격자가 기본**이고 **목록으로 전환**할 수 있다.
- **같은 PDF를 여러 책장에 넣을 수 있다.** 파일을 복제하지 않으며 읽기 위치·줌·북마크·문서별 여백/잠금/배치는 문서 하나의 기록을 공유한다.
- 문서 정렬에 **이름순·최근 읽은 순**을 제공한다.
- 책장 정렬에 **사용자 지정·이름순**을 제공하고, 사용자 지정 순서를 변경할 수 있다.
- 기존 SAF 다중 추가, 이어 읽기, 책장 추가/이름 변경/삭제, 문서 다중 선택, 등록 제거와 원본 보존을 유지한다.

위 네 선택은 사용자 답변으로 확정했다. 아래 화면 구성·기본 정렬·표지 예산·PR 분할은 구현을 위한 제안이다. 사용자가 수정하면 계획을 갱신한다. docs/design.md는 별도 디자인 작업의 소유 파일이므로 이 작업에서 편집하지 않는다.

## 화면 구성 제안

사용자 요청에 따라 구현 전 [Figma 시안 6개](https://www.figma.com/design/wFQ8qOUx3YfMy8u0E3t7fM?node-id=109-907)와 [대표 클릭 흐름](https://www.figma.com/proto/wFQ8qOUx3YfMy8u0E3t7fM?node-id=111-1217&starting-point-node-id=111%3A1217&scaling=scale-down&content-scaling=fixed)을 먼저 작성했다. 홈→학습→격자/목록→선택→책장 추가와 순서 화면 진입 예시다. 모든 정렬/순서 변경·선택 조합의 동적 구현은 아니며 설정/생성/빈 상태 등 상세 화면은 후속 설계에 남는다. 시각 검토 후 선택 표시를 더 명확하게 하는 보완은 MCP 한도로 미실행이다. 앱 구현이나 최종 디자인 수용과 구분한다.

### 1. 책장 홈

- 메인 상단은 ReaderMainHeader로 보존하고 이전 ‘등록한 문서’ 위치에 ‘책장’ 제목과 카드 격자를 둔다. ListView의 헤더/재사용 카드 행으로 상단부터 책장까지 하나의 스크롤을 사용한다. 안에 다시 스크롤하는 중첩 격자를 추가하지 않는다.
- 책장 영역의 ‘전체 문서’ 버튼과 책장 카드로 진입한다. ‘미분류’는 소속 없는 문서가 있을 때만 첫 번째에 표시하는 가상 책장 카드이며, 별도 미분류 버튼/빈 가상 카드는 표시하지 않는다. 이 카드는 기록 형식에 책장으로 저장하지 않고 이름 변경/삭제/사용자 순서 이동의 대상에서도 제외한다. 문서 목록의 뒤로가기는 메인 책장 위치로 복귀하고 오류/재시도·파일 다시 연결은 현재 목적지에 표시한다.
- 첨부 참고에 맞춰 개수·‘편집’·정렬(사용자 지정/이름순)·전체 문서를 간결한 조작 줄로 둔다. 큰 글꼴/좁은 폭은 두 줄로 나누며 격자를 가리는 고정 도구를 추가하지 않는다.
- 책장 카드: 최대3개 표지를 첫 표지는 크게, 나머지는 오른쪽 위/아래로 묶은 정사각 대표 이미지로 표시한다. 아래에는 책장 이름·문서 수와 작은 더보기 버튼을 둔다. 실제 읽은 시각이 있는 경우에만 ‘최근 읽음’으로 표시하며 저장하지 않는 생성/수정 시각을 만들어 표시하지 않는다. 표지 실패는 기본 그림으로 대체하고, 실제 사용자가 만든 빈 책장은 유지한다.
- ‘책장 추가’는 **편집을 눌렀을 때만** 보인다. 이름순에서도 편집/추가는 가능하고 위/아래 순서 변경만 사용자 지정 정렬에서 제공한다. 본문 읽기 버튼의 배경 제거 규칙을 서재로 확대하지 않으며 책장·문서 관리 버튼에는 기존 ReaderStyle의 옅은 배경색을 쓴다. 본문 도구/보기 설정의 기존 버튼 스타일은 유지한다.
- 기존 이어 읽기 카드는 메인 상단에서 유지하며 책장 안의 작은 이어 읽기 줄은 낮은 가로 화면에서 숨긴다. 목록 끝 카드와 겹치는 고정 생성 버튼은 추가하지 않는다.
- 책장 격자는 휴대폰 세로에서2열을 출발점으로 하고 폭·큰 글꼴에 맞춰 조정한다. 사용자 지정 순서 편집은 별도 편집 모드에서 위/아래 이동으로 먼저 제공한다. 이름순으로 볼 때는 수동 순서 변경을 숨기고, 사용자 지정으로 돌아오면 원래 순서를 복원한다. 드래그 정렬은 초기 필수가 아니다.

### 2. 책장 안 / 전체 문서 / 미분류

- 상단: 뒤로가기, 현재 책장/범위 이름, 더보기. 뒤로가면 이전 책장 홈의 스크롤 위치를 복원한다.
- 조작 줄: 문서 수, 정렬(최근 읽은 순/이름순), 격자·목록 전환, ‘선택’. 작은 화면/큰 글꼴에서는 줄을 나눠 잘리거나 터치 영역이 줄어들지 않게 한다.
- 기본 격자: 표지, 두 줄 이내 제목, 기존 읽기 진행 표시. 휴대폰 세로2~3열을 기준으로 폭·글꼴에 따라 자동 조정한다. 표지 클릭은 마지막 읽던 위치로 연다.
- 목록: 작은 표지, 제목, 기존 읽기 위치/최근 시각. 관리 버튼은 선택 모드/더보기에서만 보인다.
- 기본 문서 정렬은 최근 읽은 순을 제안한다. 아직 읽지 않은 문서는 뒤에 두고, 같은 시각은 이름·안정적인 문서 ID로 순서를 고정한다. 이름순은 한국어/숫자 제목을 확인하고 대소문자/동률 처리 규칙을 고정한다.
- 기존 문서 수동 순서는 저장 데이터를 유지하며 ‘사용자 순서(기존)’ 선택으로 접근하게 한다. 이름순·최근순 선택이 저장된 수동 순서를 덮어쓰지 않는다. 문서별 책장 독립 수동 순서 신설은 이번 필수가 아니다.
- 보기 방식/정렬 선택은 앱 공통으로 재실행에도 보존한다. 처음에는 격자·최근 읽은 순이다. 책장별 개별 설정은 초기 필수가 아니다.
- 읽기 진행률은 실제 마지막 위치와 알려진 총 페이지로만 표시한다. 페이지 수 미확정/미열람을0% 완료 등으로 꾸며 표시하지 않는다.

### 3. 문서 선택 모드

- 길게 누르기와 명시적 ‘선택’ 버튼을 둘 다 제공한다. 선택 개수, 현재 범위 전체 선택/해제, 취소를 표시한다. 선택 중 문서 탭은 본문 열기가 아닌 선택 변경이다.
- **책장에 추가**: 여러 책장을 선택해 선택 문서의 기존 소속에 추가한다. 이미 들어 있는 문서도 중복 등록하지 않는다.
- **이 책장에서 빼기**: 현재 책장 소속만 제거한다. 다른 책장/읽기 기록/원본 PDF는 유지한다. 전체 문서 화면에서는 이 동작을 제공하지 않는다.
- **서재에서 제거**: 모든 책장의 등록과 기존 정책의 읽기 기록을 제거하는 별도 동작이다. 확인창에 원본 파일을 지우지 않는다고 명시한다. 기존 북마크 별도 파일의 삭제 정책은 임의로 바꾸지 않는다.
- 더 이상 어느 책장에도 속하지 않는 문서만 ‘미분류’에 보인다. ‘전체 문서’와 최근 목록은 여러 책장에 속해도 문서를 한 번만 센다.
- 책장 삭제는 해당 책장과 그 소속 관계만 제거한다. 다른 책장 소속은 유지하고, 남은 소속이 없는 문서만 미분류로 남는다. 확인창에서 ‘문서를 삭제’하는 동작과 구분한다.
- 선택/현재 범위·정렬/보기/스크롤은 회전 재생성에서 보존한다. 저장 실패 때 초안·선택을 유지하고 성공으로 표시하지 않는다.
- 기존 후속 제한인 ‘등록 중 회전하면 완료 안내가 사라지는 경우’는 비차단 후속으로 보존한다. 이번 작업에서 완료 안내 복원을 고쳤다고 주장하지 않으며 원본/등록 성공과 안내 표시를 구분한다.

## 기존 구현에서 바꿀 기반

착수 전 LibraryCatalog는 URI→책장 ID 하나인 memberships와 전체 문서 순서 order를 갖고 Bookshelf 목록은 추가 순서였다. 메인 상단은 기존 배치를 재사용하고 아래의 문서 행/관리 도구를 책장 카드/선택 시 도구로 교체한다. 이름 변경/삭제 등 저장은 기존 LibraryRepository 직렬 큐/AtomicFile을 재사용한다.

1. 읽기 기록 **v6/ADR0020**: 소속을 URI→책장 ID 집합으로 확장한다. 동일 URI/동일 책장 중복 소속을 금지한다. v5 단일 소속은 원소 하나인 집합으로 변환하고 v1~v4는 기존 의미대로 미분류를 유지한다. 최초 전환 전 원본 바이트를 앱 private 파일에 원자 보존한다. 기존 문서/책장 ID·제목·순서·위치·줌·배치/여백/잠금은 보존한다.
2. 책장 목록의 저장 순서를 사용자 지정 순서로 사용한다. 이름순은 표시용으로 계산하고 원래 저장 순서를 정렬로 덮어쓰지 않는다. 기존 문서 order도 유지한다.
3. 보기/정렬 선호는 버전이 있는 별도 작은 설정으로 저장한다. UI 선호 변경 때문에 카탈로그/읽기 위치를 쓰지 않는다. 구체 파일/codec/한도는 구현 전 ADR에서 확정한다.
4. 오래된 Activity의 위치 자동 저장이 새 다중 소속/책장 순서를 덮어쓰지 않는 현재 병합 원칙을 유지한다. 손상/미지원 데이터를 빈 서재로 덮어쓰지 않는다. v6 작성 후 구버전 앱의 읽기 불가도 고지한다.
5. 메인의 책장은 헤더가 있는 ListView의 재사용 격자 행, 책장 안 문서는 GridView의 재사용 셀로 표시한다. 전체 기록10,000개/책장1,000개를 매번 View로 만들거나 표지를 모두 렌더하지 않는다. 새 AndroidX/이미지 라이브러리가 필요하면 목적·대안·라이선스·영향을 먼저 제시하고 별도 승인을 받는다. 이번 구현은 새 런타임 의존성 없이 진행했다.

## 표지와 성능·안전 제안

- PDF 첫 페이지의 작은 표지를 로컬에서 생성한다. 책장 대표 이미지는 기존 문서 표지를 재사용하며 추가 PDF 렌더를 하지 않는다. 큰 가로 페이지는 표지 상자에 맞추되 원본 PDF를 잘라 저장하지 않는다.
- 먼저 표지가 없는 상태의 제목 카드/기본 문서 그림을 즉시 표시한다. 현재 보이는 항목부터 백그라운드 작업으로 채우고, 화면 밖/문서 열기/서재 종료 시 작업을 취소한다. 동시에 PDF를 여러 개 디코딩하지 않는다.
- 초기 예산 제안: 표지 한 장 최대384×512px·RGBA 약0.75MiB, 메모리 캐시8MiB·앱 내부 디스크 캐시64MiB, 생성 동시성1. 실제 화면과 기기 측정으로 예산을 확정하고 이후에도 바이트 상한/LRU를 유지한다. 이 수치는 측정 결과가 아니다.
- **출력 크기를 줄였다고 PDF 내부 이미지 디코딩 메모리까지 제한됐다고 주장하지 않는다.** 별도 요청 수명/취소·시간 상한·오류 격리 경로를 먼저 설계한다. 기존 현재 페이지 본문 읽기의 격리 서비스 패턴을 검토하되 텍스트 서비스를 표지 렌더에 그대로 쓸 수 있다고 가정하지 않는다. 구체 프로세스/타임아웃/종료 복구는 표지 착수 ADR에서 확정한다.
- 원본이 크거나 손상/비밀번호/권한 소실로 표지를 못 만들면 기본 문서 그림을 유지한다. 표지 실패가 서재 열기·읽기 재시도를 막지 않는다. 사용자의 PDF/표지/제목/URI를 Git·로그·외부 서비스로 내보내지 않는다.
- 캐시 키는 원본 URI를 파일명으로 쓰지 않는 내부 ID와 캐시 형식/표지 조건으로 구성한다. 제공자가 알려 주는 변경 정보·명시적 다시 연결/갱신을 반영하며, 변경 정보를 주지 않는 파일의 자동 수정 감지를 보장하지 않는다. 캐시는 언제든 지워도 기록/원본에 영향을 주지 않는다.

## 구현 순서와 PR 경계 제안

1. **화면 구조 확정·데이터 전환**: 이번 계획/클릭 시안 검토 → v6/다중 소속·책장 순서/설정 ADR → 마이그레이션·복수 소속 조작·저장 병합 검증. 간단한 기존 UI에서도 데이터를 잃지 않고 동작하는 기반을 만든다.
2. **새 책장 구조·관리**: 기존 메인 상단 아래 ‘등록한 문서’를 책장 격자로 교체한다. 카드→책장 안 진입, 간결한 도구/선택 모드, 실제 어댑터 기반 격자·목록 전환, 이름·최근순/책장 사용자 지정순·이름순, 이어 읽기. 표지 실패/미준비는 기본 문서 그림으로 표시해 이 단계도 사용할 수 있게 한다.
3. **표지·최종 수용**: 표지 안전 경로/예산 확정 → 가시 항목부터 생성·재사용/캐시 → 큰 글꼴·가로 화면/설정·읽기 회귀·개인 기기 수용. 단계1·2의 단위/계측 전체를 무조건 반복하지 않고 변경 위험에 맞춰 선택한다.

개발 시에는 사용자 변경·기존 로컬 상태 기록을 보존한 뒤 병합된 main의 최신 상태를 확인하고, 현재 체크아웃에 codex/bookshelf-library-redesign 등 전용 브랜치를 만든다. 이번 계획 작성에서는 checkout/pull/브랜치 생성·코드/기기 변경을 하지 않는다. 실제 변경을 검토 가능한 PR로 나누고, 동작/필요 검증이 모인 시점에만 CodeRabbit을 요청한다. 병합은 사용자다. 날짜를 확약하기보다 위 단계별 완료 기준으로 진행한다.
