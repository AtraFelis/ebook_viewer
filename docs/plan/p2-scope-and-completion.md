# P2 — 착수 준비·기능 범위·완료 판정

2026-10-18 (Asia/Seoul). 상태: **사용자 결정으로 검색 후속 보류·P2 필수 제외 / 나머지 P2 미완료**.

현재 API 33/S·T 확장 23에서 PreV의 합성 검색·선택·렌더·AES-128/256 비밀번호 처리와 격리 이미지 렌더 probe를 실행했다([실제 결과/미결](../history/2026-10-18-05-p2-platform-readiness.md)). 앱 컨텍스트 통합·전체 선명화 기준선과 최종 수용은 아직 미완료다. 목차/비밀번호 UI는 후속 사용자 결정으로 제외했다. 과거 기기 미연결 기록과 현재 실행을 구분한다.

## 사용자 결정과 경계

2026-10-18 사용자 후속 결정: 문서 목차와 비밀번호 PDF 읽기를 제외한 데 이어 **검색도 필수 기능이 아니므로 후속으로 미룬다**. 현재 P2는 선명도 복구 지연 개선·자동 배경색·선택/복사·앱 테마·밝기·화면 유지·TalkBack/큰 글꼴을 포함하며 Figma 디자인 적용은 별도 단계다. [목차/암호 제외](../history/2026-10-18-06-p2-scope-reduction.md), [검색 보류](../history/2026-10-18-11-search-deferral.md)를 따른다. 검색 구현/추가 원인 진단/제품 격리 통합은 보류하며 현재 UI를 다시 켜지 않는다. 원인 미확정을 해결이나 기능 완료로 바꾸지 않는다.

대상은 계속 개인용 SM-N981N(API 33)이다. min 23 선언을 다른 API 실기기 검증 완료로 표현하지 않는다. 기존 Activity/View/Canvas UI에 필요한 기능과 설정만 추가한다. Figma의 홈/도구/설정 재배치, 컴포넌트·타이포그래피 전면 적용, Compose 셸 선택은 별도 디자인 구현 단계다. P2 테마와 접근성 수정은 기능 수용에 필요한 범위이며 전면 디자인 적용을 뜻하지 않는다.

이 문서의 기능 세부 경계와 성능 수치는 개발 전에 검토할 제안이다. 새 엔진/런타임 의존성 승인이나 아직 하지 않은 측정·실기기 수용을 대신하지 않는다. 날짜를 먼저 약속하지 않고 아래 준비 단계와 기능별 종료 조건으로 진행한다.

## 0. 기능 구현 전에 끝낼 준비

1. **기준 소스 보존.** P1 완료 main `0aea06e`와 APK/기존 검증 근거를 기록한다. 로컬 변경을 먼저 구분하며 2026-10-18 디자인 문서 변경을 덮어쓰거나 이번 변경으로 묶어 커밋하지 않는다. 기준 브랜치가 바뀌면 차이와 새 기준 SHA를 기록한다.
2. **API 33 지원 경로 결정.** 현재 PdfRenderer의 선택/텍스트 경로와 SDK 확장을 실제 대상 기기와 버전을 특정한 자료/소규모 검증으로 확인한다. compileSdk 35만으로 API 33에서 동작한다고 가정하지 않는다. 착수 probe에서 현재 기기의 확장/일부 기능 실행은 확인했으며 앱 통합/native 안전 검증은 남아 있다. 검색 전용 추가 진단과 목차 보조 엔진 선정은 현재 착수 조건에서 제외한다. 선명도/설정 등 독립 기능을 텍스트 어댑터 통합 대기 때문에 막지 않는다.
3. **엔진 구성안·ADR.** 플랫폼/확장 유지, 텍스트 보조 엔진, 렌더 엔진 교체를 비교한다. 선택 후보의 정확한 버전·전이 의존성·라이선스/고지·ABI·APK 크기·메모리·유지보수·취소/자원 소유권·기존 좌표/캐시 영향과 대안을 제시한다. 보조 엔진과 렌더러를 병행하면 좌표/페이지 대응 및 중복 메모리도 검증한다. 새 의존성/스택 변경은 AGENTS에 따른 사용자 구성 승인 후에만 도입한다. 현재 PDFium/MuPDF 등 어떤 후보도 채택하지 않았다.
4. **검증 자료·동작 정책 고정.** 합성 텍스트 PDF(한글/영문/줄바꿈/회전/혼합 크기), 스캔·손상/권한 소실 자료의 생성법·해시·예상 결과와 복사 권한 정책을 정한다. 이미 만든 목차/암호 합성 자료의 검증 이력은 보존하지만 해당 앱 기능 개발/개인 파일 수용은 필수로 요구하지 않는다. 개인 PDF/본문/암호/URI는 Git·로그·외부 조회에 넣지 않는다.
5. **성능 측정 설계와 기준선.** 선명도 정의·자료·배율·동작·캐시 상태·측정 회수·기기 설정을 고정하고 개선 전 기준선을 얻는다. 엔진을 변경하면 P1 원본과 새 엔진을 구분해 측정하며 최종 통합 앱을 P1과도 비교한다. 수치 목표는 아래 제안을 기준선 확인 후 확정하고 최적화 전에 기록한다. 측정 후 결과에 맞춰 몰래 기준을 낮추지 않는다.

준비 완료는 범위 문서만 작성한 시점이 아니다. 대상 기기 지원 경로·필요한 구성 승인·샘플 기대값·측정 기준선과 목표가 갖춰져야 엔진 통합/최적화로 넘어간다. 승인과 관계없는 조사·문서·환경 점검은 먼저 수행한다.

## 플랫폼 지원 확인 근거와 남은 조사

2026-10-18 공식 [PdfRenderer.Page](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page#searchText(java.lang.String))에서 검색/선택의 API 35 도입을, [PdfRenderer 생성자](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer#PdfRenderer(android.os.ParcelFileDescriptor,%20android.graphics.pdf.LoadParams))에서 LoadParams 비밀번호 경로의 API 35 도입을 확인했다. 설치 compile SDK 35의 `javap`에도 관련 서명이 있다. 이는 API 33 실기기 지원 증거가 아니다.

[PdfRendererPreV](https://developer.android.com/reference/android/graphics/pdf/PdfRendererPreV)에는 S Extensions 13 경로도 명시돼 있어 OS API 숫자만으로 가능/불가능을 단정하지 않는다. 대상 기기의 SDK 확장/클래스/지원 메서드와 통합 빌드 구성을 확인해야 한다. 현재 SDK 35 PdfRenderer/Page 공개 서명에 문서 전체 outline 트리 조회는 확인하지 못했다. 페이지의 goto link를 계층형 문서 목차와 동일시하지 않는다. 실제 목차 엔진 지원은 미결이다.

Context7은 `/websites/developer_android_reference` 조회가 가능했으나 최신 API와 PdfRendererPreV 자료가 섞이고 API 33 고정 문서가 없었다. 공식 메서드별 도입 버전·설치 SDK 서명으로 교차 확인했다. 향후 엔진 선정에서도 버전 특정 근거와 실제 API 33 실행을 분리한다.

## 1. 선명도 복구 지연

관련 진단과 개선 후보는 [별도 계획](p2-sharpness-recovery.md)을 따른다. 첫 방문과 캐시 재방문, 일반 스크롤·빠른 플링/반전·높은 배율을 구분한다. 미리보기 확대만으로 선명화 개선을 통과 처리하지 않는다.

- 측정 시작은 새 가시 영역의 요청 시점, 첫 선명 타일 표시, 가시 면적 95% 이상이 현재 렌더 배율 타일로 그려진 시점을 구분한다. 페이지 외부/앱 여백은 분모에서 제외하고 작은 저해상도 미리보기는 선명 타일에 포함하지 않는다. worker 완료/캐시 적재와 실제 draw를 구분한다.
- 멈춘 뒤의 지연은 마지막 viewport 변화부터 동일 viewport의 95% 선명화 draw까지다. 계속 움직이는 동안에는 영역별 체류 시간과 가시 선명 비율을 별도로 기록한다. 2초 안에 준비되지 않은 표본도 timeout/미완료 비율로 남기며 p95 계산에서 조용히 버리지 않는다.
- **초기 합격선 제안:** 고정한 일반 스크롤 시나리오의 정지 후 95% 선명화 지연 p95가 시나리오별 500ms 이하이거나 P1 기준보다 30% 이상 감소할 것. 기준선이 이미 500ms 이하인 시나리오는 500ms 이하를 유지한다. 빠른 플링/반전·높은 배율은 별도 보고하고 1초 초과 미완료 비율이 증가하지 않을 것. 기준 측정 후 달성 가능성과 사용자 체감을 보고 최적화 전에 확정한다.
- 비교 가능한 표본을 시나리오별 최소 30개, 같은 profile 빌드 조건 3회 이상 수집한다. 자동 표본은 개인 기기에서 실행하고 동일 자료 해시/순서/배율/주사율을 기록한다. 기준/개선 APK를 구분하며 thermal/충전/백그라운드 차이로 비교가 무효면 재측정한다.
- 기존 60Hz 프레임 p95 16.7ms/p99 33.3ms 목표와 64MiB 공유 비트맵 캐시를 함께 확인한다. 제안한 선명도 개선으로 프레임 실패·지속 메모리 증가·ANR/충돌·이전 문서 타일 노출이 생기면 통과가 아니다. 새 엔진 native/텍스트/인덱스 메모리는 비트맵 캐시와 별도 상한/수명 정책을 선정 ADR에 정한다.

종료: 기준/최종 통합 앱의 비교 보고서와 사용자 읽기 체감 확인, 프레임·캐시·취소·줌/앵커 회귀 통과. 임의 PDF/32 px/point의 모든 상황에서 무지연을 보장하지 않는다.

## 2. 자동 페이지 외부 배경색

- 기존 수동 색상과 기본값을 보존하고 자동/수동을 선택·재실행 보존한다. 기존 설치를 업데이트했다고 자동 모드로 강제 변경하지 않는다.
- 현재 화면 중심과 가장 가까운 페이지를 대표 페이지로 정한다. 경계에서 페이지/색이 반복 전환되지 않게 안정화 규칙을 구현 전 명시한다.
- 이미 준비된 가장자리 표본에서 백그라운드로 색을 구한다. 사진·스캔·어두운 페이지·투명/표본 부족의 대체색과 전환 규칙을 합성 자료로 확인한다. 모든 페이지를 추가 렌더하거나 UI 스레드에서 분석하지 않는다.
- PDF 픽셀/페이지 내부 여백·줌/앵커·설정 보존을 변경하지 않는다. 자동 분석이 선명한 가시 타일 작업을 밀어내거나 캐시 상한을 넘으면 안 된다.

종료: 자동/수동 전환·입력/복원·경계 안정성·대체색·PDF 픽셀 불변 테스트와 최종 성능 회귀 통과. ‘어울림’은 합성 기대색 검사와 개인 기기 사용자 확인을 함께 사용한다.

## 3. 문서 검색 — 후속 보류, P2 필수/종료 조건 제외

사용자 결정으로 아래 요구사항은 후속 재개용으로만 보존한다. 추가 개발/진단은 현재 진행하지 않는다. 재개 시 안전 구조와 수용 기준을 다시 검토하며 기존 합성 검사 통과로 LOW_MEMORY 문제를 해결 처리하지 않는다.

- 텍스트 레이어가 있는 PDF 전체에서 한글/영문 일반 문자열 검색, 일치 위치 강조, 현재/전체 결과 수와 이전/다음 결과 이동을 제공한다. 부분 결과/검색 중 상태와 최종 결과 수를 구분한다.
- 새 질의/문서 전환/검색 닫기 때 이전 작업을 취소/무효화한다. 검색 이동은 현재 줌과 유효 가로 위치를 유지하고 일치 영역을 보이게 한다. 가시 렌더를 굶기지 않도록 검색 우선순위/작업 단위를 정한다.
- 문자열 정규화·영문 대소문자·줄바꿈 경계의 검색 정책은 엔진 시험 때 기대 결과와 함께 고정한다. 정규식·퍼지 검색·OCR·스캔 이미지의 문자 인식은 P2 필수에서 제외한다. 텍스트 없는 문서는 검색 가능 텍스트가 없음을 알린다.
- 전체 문서 이미지/텍스트를 무제한 선적재하거나 추출 본문을 로그/외부 서비스로 보내지 않는다. 인덱스가 필요하면 저장 여부·바이트 상한·문서 변경 무효화·삭제를 ADR에 명시한다.

후속 재개 시 종료 기준: 알려진 결과 수/좌표의 한글·영문·혼합/회전 샘플, 결과 없음/빈 입력·연속 질의·취소·문서 교체와 읽기 성능 회귀 통과. 현재 P2 종료 판정에는 적용하지 않는다.

## 4. 텍스트 선택·복사

검색 보류와 별개로 유지한다. 문서 전체 검색을 재활성화하는 작업 없이 선택 기능의 페이지 단위 텍스트 접근·취소/중단·메모리/FD 수명을 검증한다. 같은 native 텍스트 기반을 사용할 경우 검색에서 확인한 위험/안전 제한을 무시하지 않는다.

- 텍스트 페이지에서 길게 누르기→단어 선택→핸들로 같은 페이지의 여러 줄 범위 조정→복사를 제공한다. 페이지를 넘는 드래그 선택과 이미지 복사/OCR은 후속이다.
- 확대/가로 이동/페이지 회전/너비 통일에서도 강조와 실제 복사 범위가 일치한다. 중앙 탭 메뉴·핀치/스크롤·선택 해제/뒤로가기와의 충돌을 검증한다.
- 텍스트가 없는 곳과 복사 제한 문서는 이유를 안내한다. 복사 권한을 존중하며 복사는 사용자가 누른 때만 클립보드로 보낸다. 자동 클립보드 읽기/본문 로그는 하지 않는다.

종료: 합성 문서의 기대 문자열과 실제 복사 결과 일치, 선택 좌표·다중 줄·취소·확대/회전·문서 교체 회귀 통과. 잘못된 페이지의 텍스트를 복사하면 미완료다.

## 5. 테마·밝기·화면 유지·접근성

- **앱 테마:** 시스템 따름/밝게/어둡게를 선택·저장한다. 홈/도구/설정/다이얼로그/시스템 바 가독성을 확인한다. PDF 픽셀 반전과 페이지 외부 수동/자동 배경색은 별개이며 테마가 이를 덮어쓰지 않는다.
- **밝기:** 시스템 따름/앱 읽기 밝기를 선택한다. 읽기 화면의 Window에만 적용하고 앱 밖/비열람/백그라운드에서는 시스템 정책으로 복귀한다. 기기 전체 밝기나 별도 시스템 권한을 자동 변경하지 않는다.
- **화면 유지:** 사용자가 켠 경우 열람 중에만 화면 켜짐을 유지한다. 목록/닫기/정지/백그라운드에서는 해제하고 설정은 재실행 보존한다.
- **TalkBack:** 홈/도구/설정/선택 등 제공하는 액션의 이름·상태·초점 순서, 오류 안내, 키보드/뒤로가기를 검증한다. 텍스트 레이어가 있는 PDF는 현재 페이지의 텍스트 읽기 경로를 제공하고 페이지 이동/읽기 위치를 조작할 수 있어야 한다. 페이지 텍스트 추출에도 native 안전 검증을 적용하며 검색 UI/검색 결과 조작은 이번 범위에서 제외한다. 스캔 본문 OCR/모든 PDF의 완전한 의미 구조 복원은 제외한다.
- **큰 글꼴:** UI 글꼴 배율 100%/150%/200%와 가로/세로에서 주요 동작·설정/오류 문구가 잘리거나 접근 불가가 되지 않아야 한다. PDF 본문은 기존 줌을 유지하며 UI 글꼴 배율로 PDF 줌을 자동 변경하지 않는다.

종료: 각 선택 저장/복원·열람/비열람 전환·회전/백그라운드, 개인 기기 TalkBack 조작 및 큰 글꼴 수동 확인을 완료한다. 색상/뷰 속성 자동 검사만으로 접근성 사용 확인을 대신하지 않는다. Figma 전면 적용은 이 단계의 종료 조건이 아니다.

## P2 제외 — 문서 목차·비밀번호 PDF 읽기

두 기능은 사용자가 개인용으로 필요하지 않다고 판단해 필수 범위에서 제외했다. 구현 통과로 체크하지 않고, 수요가 생길 때 별도 범위/지원 구성을 다시 결정한다. 이미 완료한 AES 플랫폼 probe는 조사 결과로 보존하며 비밀번호 입력/암호 보관·복호화·암호화 문서 이어 읽기 UI를 추가하지 않는다. 비밀번호 문서의 기존 지원 불가 안내/목록 복귀는 유지한다.

문서 내장 계층형 목차는 기존 사용자 북마크·페이지 이동과 구분한다. 후자의 P1 기능은 그대로 유지한다. 목차만을 위한 외부 엔진/파서 도입과 그 승인·빌드/라이선스 검토는 현재 P2의 선행 조건이 아니다.

## 작업 순서와 PR 경계

검색 어댑터/앱 UI를 먼저 실험했으나 개인 PDF에서 수용 실패해 철회했다. 이후 별도 진단에서 일부 보호/합성 검사를 수행했고, 사용자 결정으로 검색 작업 자체를 후속 보류한다. [LOW_MEMORY 근거와 재개 조건](../history/2026-10-18-08-p2-search-low-memory-withdrawal.md)은 재개용 이력으로 보존한다. 현재 앱은 원래 main 픽셀 읽기이며 검색은 제공하지 않는다. 검색 진단/PR #12 병합을 다른 P2 기능의 선행 조건으로 두지 않는다. 단순 결과 수/페이지 수를 native 메모리 상한으로 취급하지 않으며 선택/본문 읽기에도 필요한 안전 검증을 수행한다. 선명도 기준선/합격선과 최종 통합 검증은 계속 필요하다.

1. 선명도: 기준선/측정 목표 확정 → 스케줄링·캐시 개선 → 전후 비교. 기존 렌더러를 우선 유지한다.
2. 자동 배경색과 테마/밝기/화면 유지: 관련 설정·스키마 호환·성능을 검증한다.
3. 선택/복사와 현재 페이지 본문 읽기: 필요한 어댑터/수명·좌표·native 안전 검증/ADR을 별도로 진행한다. 엔진 변화가 있으면 P1 회귀부터 통과하며 새 의존성/스택 변경은 승인 후 적용한다. 검색 구현은 포함하지 않는다.
4. TalkBack/큰 글꼴과 기능 전체의 통합 회귀·개인 PDF 사용 확인·최종 측정/완료 기록.

PR마다 목적·실제 검사·한계를 기록하고 CodeRabbit 수동 요청/실제 응답을 확인한다. 타당한 리뷰 지적은 수정·검증 후 일반 push하며 사용자만 병합한다. CI 대기 중에는 독립적인 다음 기능을 진행할 수 있지만 미병합 부모를 포함하는 기준과 검사 SHA를 구분한다. 최종 성능 검증은 개별 PR이 아니라 모든 기능을 포함한 최종 앱에서도 수행한다.

## P2의 정확한 종료 시점

**필수 1·2·4·5(선명도·자동 배경색·선택/복사·설정/접근성)의 기능 수용, 최종 통합 앱의 기능/성능/접근성 검증, 사용자의 개인 기기 확인, 해당 기능 PR의 사용자 병합, 완료 문서 반영까지 끝난 시점**을 P2 완료로 한다. 3번 검색은 후속 보류로 제외한다. 모든 기능 버튼이 있거나 빌드만 성공한 시점이 아니다.

- 준비 단계에서 확정한 대상 텍스트/측정 목표를 충족하고 모든 필수 기능 체크가 완료돼야 한다. 미지원 기능을 뺄 때는 사용자가 범위를 변경해야 하며 ‘나중에’ 목록만 작성해 P2 완료로 선언하지 않는다.
- 기존 22개 단위/41개 기본 계측의 관련 회귀를 유지하고 새 동작에 필요한 테스트를 추가한다. 개수 자체를 고정 합격선으로 쓰거나 기존 검사를 제외해 통과시키지 않는다. 별도 프로세스 복원도 재검증한다.
- strict 앱/테스트 APK 빌드·단위·Lint·ktlint와 해당 최종 앱 소스의 원격 CI를 통과한다. 검사한 SHA/설치 APK/기기 결과를 연결하고 후속 Markdown 전용 CI 제외와 실제 앱 검사 성공을 구분한다.
- 취소/권한·자원·비밀 정보·앵커/줌, 64MiB 비트맵 캐시와 선정 엔진의 별도 메모리 예산, 개인 기기의 10분 이상 통합 읽기를 확인한다. 실제 OOM/다른 API 기기 미검증을 통과로 확대하지 않는다.
- 사용자에게 개인 PDF에서 선택/복사·이어 읽기, 체감 선명도·새 설정이 필요한 대로 동작하는지 확인받는다. 검색 수용은 이번 종료 조건에서 제외한다. 개인 파일을 제출하도록 요구하지 않고 합성 계측과 자기보고를 구분한다.
- 미해결 충돌/데이터 소실/잘못된 문서/암호 노출·평문 잔류·주요 읽기 차단과 타당한 미수정 리뷰 지적이 없어야 한다. CodeRabbit 한도로 실제 리뷰가 없으면 외부 검토 미완료로 명시하고 최종 인수 때 잔여 위험을 사용자에게 알린다. skipped 성공을 리뷰 통과로 세지 않는다.
- SESSION/CHECKLIST/history에 최종 결과·미검증·지원 한계·원격 병합/검사를 기록한다. 이후 P3 안정화나 별도 Figma 디자인 적용은 새 범위로 진행한다. 스토어 게시/릴리스는 별도 승인이다.

달력상의 완료일은 지금 정하지 않는다. **엔진 경로/구성 승인과 기준 측정이 끝난 P2-0 종료 시점에**, 남은 PR 단위와 측정 결과를 근거로 일정 범위를 다시 제시한다. 엔진/의존성 승인이나 기기 미연결로 남은 항목이 있으면 그 상태를 공개하고 완료라고 하지 않는다.
