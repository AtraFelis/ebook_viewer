# 혼합 페이지 폭 문서의 가로 이동 잠금

2026-10-21 사용자 요청. 이번에는 계획만 추가하고 PR #22 리뷰 수정을 먼저 완료한다. 잠금 기능 구현·기기 검증은 별도 후속 변경으로 진행한다.

## 문제와 목표

현재 문서 폭은 가장 넓은 페이지를 기준으로 하고, 한 손가락 스크롤과 플링은 X/Y 입력을 모두 반영한다. 좁은 페이지를 확대해 읽을 때 세로 스와이프에 섞인 가로 입력과 관성이 옆 이동으로 이어진다. 원본 비율/선택한 확대 배율을 유지한 채 아래로 읽을 수 있게 한다. 기존 ‘너비 통일’과는 별도 옵션이며 PDF 내용/페이지 폭을 강제로 바꾸지 않는다.

## 동작 범위

- ‘가로 이동 잠금’은 한 손가락 드래그와 관성 이동의 가로 성분만 막는다. 세로 이동/관성은 유지한다. 켜거나 끌 때 확대 배율을 초기화하거나 화면을 가운데로 옮기지 않는다. 켜는 순간 진행 중인 기존 플링은 멈춰 잔여 가로 속도를 제거한다.
- **잠금 중에도 두 손가락 핀치 확대·축소를 계속 허용한다.** 기존 줌 한도와 핀치 중심 기준 확대를 유지하고, 잠금 때문에 핀치를 무시하거나 배율을 고정하지 않는다.
- 핀치 중에는 확대 중심을 유지하는 데 필요한 가로 좌표 변화와 기존 문서 경계 보정을 허용한다. 핀치 종료 뒤에는 그 결과의 가로 위치를 기준으로 세로 스크롤한다. 확대 전의 가로 위치로 되돌아가는 점프를 만들지 않는다. 즉, 잠금은 모든 상황에서 X를 절대 고정하는 기능이 아니다.
- 핀치에서 손가락 하나로 돌아오는 전환은 새 터치 기준점을 잡아 가로 튐/잔여 가로 플링/단일 탭 도구 오인식을 막는다. 잠금을 끄면 기존 자유 가로 이동을 복원한다.
- 좁은/넓은 페이지의 경계를 지날 때 자동 줌·페이지별 재중앙 정렬·페이지 스냅을 추가하지 않는다. 기존 회전/이어 읽기·페이지 이동의 앵커 보존 규칙을 유지한다.
- 기본 해제와 문서별 선택을 제안한다. 문서별 크기·간격 설정에서 접근하는 구성, 저장 범위·기존 기록 호환은 구현 전에 관련 ADR에 구체화한다. 새 런타임 의존성/렌더러/캐시 변경은 필요하지 않다.

## 구현과 수용 기준

1. `PdfCanvasView`의 드래그·플링·핀치 전환에만 잠금 정책을 적용한다. `DocumentLayout`의 최대 폭과 사용자 줌을 잠금 목적으로 바꾸지 않는다. 진행 중 native 렌더·전체 페이지 선로딩을 추가하지 않는다.
2. 합성 좁음–넓음–좁음 문서에서 확대 후 대각선 입력/세로 플링으로 여러 경계를 지나도 잠금 중 가로 위치와 배율이 유지되는지 검증한다. 허용된 문서 경계 보정은 별도로 구분한다.
3. 잠금 중 핀치 확대/축소가 실제로 배율을 바꾸고 중심을 보존하는지, 이후 한 손가락 세로 스크롤에서 새 가로 위치를 유지하는지 확인한다. 두 손가락에서 한 손가락 전환·취소·토글 중 플링·잠금 해제도 검사한다.
4. 원본 비율/너비 통일·회전/재생성·이어 읽기·페이지 이동·중앙 탭 도구가 기존 동작을 유지하는지 관련 회귀만 실행한다. strict 빌드/단위/Lint/ktlint와 현재 개인 기기에서의 사용자 수용을 기록한다. 렌더러 변경이 없으면 장시간 성능 전체 실험을 반복하지 않는다.

아직 구현/테스트를 실행하지 않았으며 PR #22의 첫 안내·설정 재시도 완료 조건에 끼워 넣지 않는다.
