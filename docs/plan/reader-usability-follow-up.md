# 개인 사용 피드백 — 배경색·방향 빠른 접근·문서 여백

2026-10-22. 사용자 요청 세 가지를 현재 체크아웃의 main b3acea0 기반 `codex/reader-background-orientation-crop`에서 진행한다. 사용자 디자인 문서128줄은 보존/제외한다. 새 런타임 의존성이나 PDF 파일 수정은 없다.

## 구현 순서와 수용 조건

1. 자동 배경색: 대표 페이지 변경 후 미리보기 분석 결과를 기다리는 동안 직전 표시 색을 유지한다. 첫 문서/명시적인 수동 전환/실제 분석 실패는 기존 사용자 대체색을 쓴다. 늦은 이전 문서 결과 무효화·색16개/캐시64MiB 상한과120ms/24dp 안정화는 유지한다. 미준비 페이지를 여러 개 통과해도 중간 대체색이 노출되지 않는 합성 검사를 추가한다.
2. 방향 빠른 접근: 중앙 탭 읽기 도구의 제목 오른쪽에48dp 방향 아이콘을 추가한다. 사용자 후속 요청에 따라 다섯 방향 선택은 PDF 위 작은 드롭다운으로 펼친다. 선택 후에도 펼쳐진 상태를 유지하며 바깥 탭/뒤로로 닫는다. 일반 설정에서는 기존 세부 설정창을 유지한다. 회전 재생성에도 드롭다운 상태를 보존한다. 큰 글꼴·짧은 화면·제목 말줄임·가로 잠금 조작을 유지한다.
3. 문서 여백 자르기: 사용자는 문서 전체 공통 적용을 선택했다. 원본 PDF는 변경하지 않으며 각 페이지의 좌/상/우/하를 원본 크기에 대한 백분율(각0~45%,1% 단위)로 숨긴다. 화면px는 확대/화면 크기에 따라 달라져 저장 단위로 쓰지 않는다. 사용자 후속 요청에 따라 실제 현재 PDF 페이지를 상단에 고정하고 슬라이더 조절 중 숨길 영역을 표시한다. 초기화/적용·취소를 제공하며 적용 전에는 저장하지 않는다. 문서별로 저장하며 다른 문서에 전파하지 않는다.
   - 잘린 크기로 페이지 배치·스크롤 경계·타일 가시 영역을 계산하고, 미리보기/기존 타일은 원본 좌표에서 잘라 그린다. 전체 고해상도 선로딩/추가 PDF 디코딩은 없다.
   - 기록v4에 네 여백을 추가하고 v1/v2/v3는 여백0으로 읽는다. 기존 위치/북마크는 원본 페이지 비율 기준을 유지하고 자르기 변경 때도 원본 앵커와 줌을 보존한다(사라진 영역·문서 끝의 경계 제한은 허용).
   - 재실행/회전/이어 읽기·페이지 이동·크기/간격 변경·가로 잠금/두 손가락 확대·이동·저장 실패 입력/재시도를 검증한다. 본문 읽기는 원본 페이지 전체 기준임을 안내한다. 원본에서 내용을 삭제하거나 비밀을 가리는 기능이 아니다.

## 검증·완료

추가 오류: 페이지 크기·간격에서 입력칸을 탭해도 숫자 키패드가 나타나지 않는다. 공통 ReaderFormDialog가 setContentView로 추가한 편집기를 AlertController가 인식하지 못해 남긴 FLAG_ALT_FOCUSABLE_IM을 편집기 포함 창에서만 해제한다. 실제 탭/IME 표시·숫자 입력/적용 버튼 접근·저장으로 검증한다. SHOW_FORCED/새 입력 라이브러리는 사용하지 않는다.

- JVM: 잘린 기하/원본 앵커 왕복/혼합 페이지·균일너비·최대배율 가시 타일/빈 페이지 방지, 기록v1~v4/손상/잔여 바이트.
- strict debug/계측 빌드·단위·Lint·ktlint. 필요한 관련 합성 기기 검사만 실행하고 전체91개/20분/모든 문서 성능 검증으로 확대하지 않는다.
- 기기 미연결 시 PC 작업을 먼저 마치고 실제 검증은 미실행으로 남긴다. 사용자가 만든 정식판 키/비밀번호를 읽지 않으며 정식판 설치·데이터를 변경하지 않는다. 검증은 별도 개발용 앱이다.
- 구현/필요 검증 후 PR과 수동 CodeRabbit 한 번, 실제 CI·리뷰와 사용자 수용을 구분한다. 병합은 사용자다.
