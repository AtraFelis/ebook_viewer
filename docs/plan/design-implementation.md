> 2026-10-29 상태: 합의한 구현/검증과 사용자 수용·병합은 완료했다. 현재 완료 범위·보류/제외는 [로드맵](roadmap.md), 실제 검증 한계는 [최신 정리](../history/2026-10-29-01-documentation-and-cleanup.md)를 따른다. 아래는 당시 계획/진행 기록이며 ‘다음·대기·미게시’ 문구나 포괄 검사 조건을 현재 미완료 필수 작업으로 재개하지 않는다. 모든 기기/API·전체 검사·공개 배포 완료를 뜻하지 않는다.


2026-10-20 사용자 요청으로 시작한다. 기준은 [디자인 인계](../design.md)와 실제 Figma 화면이다. 디자인 명세의 소유권은 디자인 세션에 두고 이 계획에서 구현 상태를 관리한다. P2 기능 완료와 디자인 적용 완료를 구분한다.

## 자료와 작업 기반

- 2026-10-20 사용자 “TalkBack은 필요없어”에 따라 이후 TalkBack 전용 구현·음성/초점/제스처 검증을 완료 조건에서 제외한다. 기존 구현·과거 검증 이력은 보존한다. 큰 글꼴·일반 터치·현재 페이지 본문 읽기는 유지하며, 디자인 명세의 TalkBack 요구보다 이번 사용자 지시를 우선한다.

- Figma MCP는 사용자 지시로 사용하지 않는다. 로그인된 Chrome에서 홈 `30:147` → 읽기 `30:176` → 도구 `30:190`을 직접 열고 시각 확인했다. 추가 화면도 필요할 때 브라우저로 확인한다.
- 명세의 색상/치수/상호작용과 화면 PNG가 기본 자료다. 새 아이콘이 필요하면 SVG를 사용한다. 전체 `.fig`보다 주요 프레임 PNG + SVG 묶음이 구현에 바로 쓰기 쉽다. 현재 자료로 착수할 수 있어 추가 업로드를 요구하지 않는다.
- 사용자 커밋 `ea91122`를 보존한 `codex/design-foundation`에서 병합 완료된 origin/main `8d0731b`를 일반 merge했다. 현재 체크아웃을 사용하고 디자인 worktree는 건드리지 않는다.
- 기존 Kotlin/Activity/View/Canvas, PdfRenderer, AtomicFile과 저장 형식을 유지한다. 런타임 의존성/서체 패키지/Compose/엔진 변경은 포함하지 않는다. Android 시스템 글꼴의 sp와 실제 fontScale을 사용한다.

## 검토 가능한 적용 순서

1. **공통 스타일과 홈**: light/dark 토큰, 글자·둥근 버튼·카드·간격, 홈 제목/설정/마지막 문서/진행 표시/SAF 열기/최근 목록/빈 상태/기록 관리. 긴 제목과 글꼴 200%에서 조작을 스크롤로 접근할 수 있게 한다. 합성 문서 진입과 오류 복구를 보존한다. 첫 PR의 범위다.
2. **기존 입력·설정 화면**: 페이지 이동, 북마크, 방향/배경색/표시/문서별 배치, 본문 읽기 창에 공통 스타일과 스크롤 가능한 폼/접근 가능한 확정 영역을 적용한다. 문서 없는 설정의 비활성 상태, 입력 오류/취소와 실제 저장 결과를 유지한다.

   2026-10-20 사용자 추가 수용 기준: 세부 설정의 뒤로/닫기/적용은 상위 설정으로 돌아간다. 상위 설정을 유지해 세부 화면의 비동기 로드/전환 사이에 PDF나 홈이 드러나지 않게 한다. 방향/테마 재생성 뒤에도 상위 설정을 복원하고, 목록 항목은 사용자 서체/200%에서 글자 전체가 들어가는 높이를 사용한다.

   2026-10-21 방향 창 추가 기준: 방향 항목 선택 자체는 세부 창을 닫지 않는다. 회전/재생성 뒤에도 방향 세부 창과 실제 저장된 선택을 복원하고, 사용자가 닫기/뒤로를 누를 때만 상위 설정으로 돌아간다. 다른 세부 창의 적용 후 상위 복귀는 유지한다. 구현/strict PC 검사는 완료했으며 기기 확인은 연결 후 남아 있다([이력](../history/2026-10-21-01-orientation-settings-stay-open.md)).
3. **읽기 도구**: 상단 제목/벡터 뒤로가기 + 하단 조작, ‘읽기 계속’ 제거, 빈 곳 단일 탭 닫기. 문서 뷰포트/줌/앵커를 밀거나 초기화하지 않는다. 스크롤/핀치/버튼을 닫기로 오인하지 않는다. 시안에 빠진 현재 페이지 본문 읽기 진입을 유지한다. 가로/좁은 화면 분기는 명세의 문서 제안을 Android에서 검증한다.
4. **페이지 슬라이더**: 목표 번호만 미리보기, 놓을 때 기존 페이지 이동 한 번, 같은 페이지는 이동 없음, 취소/뒤로가기/두 손가락/회전/비활성화/문서 교체에서 미확정 목표 폐기. 1페이지/페이지 수 미확정/양 끝/탐색 중/실패를 구분한다. 썸네일/렌더 선로딩은 추가하지 않는다.
5. **안내·실패 초안·통합**: 세션 최초 성공 열기 한 번의 비차단 안내와 첫 조작 해제, 표시 설정 저장 실패 시 초안을 유지하는 재시도 UI를 적용한다. 회전/키보드/inset/긴 제목/200%/다크 대비와 기존 읽기를 검증한다. 안내는 메모리 상태만 사용하며 새 영속 형식을 만들지 않는다.

검토 가능한 변경을 PR로 묶는다. 사용자 후속 지시에 따라 현재 Draft #19에 공통 스타일·홈과 입력·설정 화면을 함께 적용한다. 읽기 도구/슬라이더 등 동작 변경은 별도 범위로 남긴다. CodeRabbit은 Draft에서도 필요하면 호출할 수 있지만, 구현·필요한 검증이 어느 정도 마무리된 최신 head에 요청하며 작은 수정마다 호출하지 않는다. 실제 접수/리뷰 확인, 타당한 지적의 수정·검증·일반 push를 수행하며 병합은 사용자가 한다. 뒤 단계가 남아 있으면 전체 디자인 완료라고 보고하지 않는다.

## 검증과 완료 조건

- 각 코드 변경에 strict dependency verification으로 빌드/Lint/ktlint를 실행한다. 저장/이동 로직을 바꾸면 해당 단위 테스트를 포함한다. ktlintFormat은 실행하지 않는다.
- 홈 단계는 기존 문서 복원/오류 보존 검사, 홈의 긴 제목·200%·밝음/어둠·기록 삭제 취소/확정에 집중한다. 합성 자료만 사용하며 개인 PDF 제목/URI/내용을 수집하지 않는다.
- 도구/슬라이더 단계는 줌/뷰포트 불변과 미확정 이동·저장 부재, 입력/터치 제스처 경계를 직접 검증한다. 기존 본문 읽기 안전 프로세스와 검색 비활성 범위는 유지한다.
- 마지막에 변경 영향에 맞는 통합 기기 검사를 실행한다. 디자인 변경만으로 P2 성능 실험 20그룹/장시간 측정을 반복하지 않는다. 렌더러/캐시가 바뀌면 별도 근거를 마련한다.
- 모든 단계 구현·실제 검사·주요 화면 시각 확인·사용자 수용 후 완료한다. 미실행 기기/해상도/글꼴 조합은 명시한다. TalkBack 전용 검증은 사용자 결정으로 제외한다.
