# 읽기 페이지 번호·도구 버튼 표현 보정

> 2026-10-29 상태: 합의한 구현/검증과 사용자 수용·병합은 완료했다. 현재 완료 범위·보류/제외는 [로드맵](roadmap.md), 실제 검증 한계는 [최신 정리](../history/2026-10-29-01-documentation-and-cleanup.md)를 따른다. 아래는 당시 계획/진행 기록이며 ‘다음·대기·미게시’ 문구나 포괄 검사 조건을 현재 미완료 필수 작업으로 재개하지 않는다. 모든 기기/API·전체 검사·공개 배포 완료를 뜻하지 않는다.


2026-10-21 사용자 스크린샷 피드백을 가로 이동 잠금보다 먼저 처리한다. 현재 체크아웃의 main 기반 별도 브랜치 `codex/reader-chrome-polish`에서 진행한다. 사용자 `docs/design.md` 변경은 보존/제외한다.

- 읽기 중 번호는 하단 중앙에 작은 글자로 표시하고 배경 상자는 제거한다. 짙은 글자와 얇은 흰 외곽선의 두 번 그리기로 흰/검은/색상 배경의 대비를 확보한다. 배경 PDF 픽셀의 별도 분석·I/O·렌더 요청은 추가하지 않는다. 복잡한 무늬와 겹치는 모든 상황의 완전한 가독성을 보장한다고 보고하지 않는다.
- 물리 cutout·내비게이션 영역과12dp 간격을 두고, 일시적인 시스템 바 표시가 번호를 흔들지 않도록 안정된 inset을 사용한다. PDF 영역·줌·앵커·현재 페이지 계산과 사용자의 번호 표시/숨기기 저장은 유지한다. 번호는 터치를 소비하지 않는다.
- 하단의 페이지 이동/북마크/설정/현재 페이지 본문 읽기는 기존 테마의 옅은 강조 바탕을 사용한다. 버튼 사이8dp 간격, 비활성 색·눌림 ripple·48dp 이상 조작 영역·큰 글꼴 스크롤 접근을 유지한다.
- strict 앱/계측 빌드·Lint·ktlint 후 새 대비/투명/위치·터치·양 테마 버튼 픽셀 검사와 관련 navigation/immersive/font만 실행한다. 단위 로직·렌더러 변경이 없으므로 단위/전체 성능 실험을 불필요하게 반복하지 않는다. 미실행 결과는 구분한다.
- 합성 화면만 확인하고 새 앱의 실제 외관은 사용자 수용으로 마무리한다. 작업/검증을 모은 PR에서 CodeRabbit을 한 번 요청하며 실제 접수/리뷰 여부를 구분한다. 병합은 사용자다.

가로 이동 잠금은 기존 [후속 계획](horizontal-pan-lock.md)을 유지하며 이번 구현에 포함하지 않는다.
