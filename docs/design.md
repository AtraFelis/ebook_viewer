# Ebook Viewer UI/UX 디자인

최종 갱신: 2026-10-20 (Asia/Seoul).

이 문서는 이 디자인 세션의 결정, Figma 산출물, 구현 차이, 검증과 남은 작업을 모으는 단일 관리 문서다. 2026-10-20 사용자 요청으로 기존 개발 세션에 앱 디자인 적용 기준으로 인계한다. 디자인 완성과 앱 구현 완료를 구분한다. 기능·기술 계약은 [AGENTS.md](../AGENTS.md), 개발 범위는 [P2 계획](plan/p2-scope-and-completion.md)이 우선한다.

## 관리 범위와 다른 세션과의 협업

- 사용자 지시에 따라 이후 저장소의 디자인 기록은 **이 파일만 수정**한다. 앱 코드, SESSION, CHECKLIST, README, ADR, 기존 history는 이 디자인 세션에서 수정하지 않는다.
- Figma는 디자인 산출물이고 이 문서는 결정과 인계 기준이다. 이전 디자인 이력은 당시 스냅샷으로 보존한다. 예전 기록의 변수 39개·정적 시안·자동 배경색 미포함 등의 상태는 아래 현재 상태로 대체한다.
- 다른 개발 세션은 이 파일을 읽되 편집은 이 디자인 세션에 맡긴다. 구현 상태가 달라지면 기준 소스를 다시 확인해 이 파일의 차이 목록을 갱신한다.
- 서로 다른 파일을 편집하면 직접적인 파일 편집 충돌을 줄일 수 있다. 다만 **같은 작업 폴더를 공유하면 브랜치, 작업 파일, Git index도 공유**한다. 다른 세션의 브랜치 전환은 이 세션이 보는 파일도 바꾸며, 미커밋 변경이 있으면 전환이 거부되거나 변경이 다른 브랜치에 따라갈 수 있다. 서로 다른 파일만 편집한다는 약속으로 이 영향까지 없어지지는 않는다.
- 2026-10-19 사용자 승인으로 디자인 전용 worktree를 만들었다. 개발 폴더는 `C:\Users\cotjs\workspace\ebook_viewer`, 디자인 폴더는 `C:\Users\cotjs\.codex\worktrees\ebook-design\ebook_viewer`, 디자인 브랜치는 `codex/ui-design`이다. 분리 당시에는 해당 폴더에서 작업했다. 2026-10-20 사용자 요청으로 현재 프로젝트의 `docs/design.md`에 합쳤으며, 현재 프로젝트의 이 파일을 최신 관리본으로 사용한다. 기존 worktree 문서는 합치기 전 보관본으로 유지하며 동시에 편집하지 않는다.
- worktree별 작업 파일·브랜치·Git index는 분리된다. 개발 폴더의 브랜치 전환은 디자인 폴더 파일을 바꾸지 않는다. Git 저장소의 커밋/참조는 공유하므로 다른 세션의 브랜치를 삭제하거나 변경하지 않는다.
- 2026-10-19 분리 당시에는 SHA-256 일치를 확인해 문서를 worktree로 이전하고 개발 폴더의 사본을 제거했다. 기존 SESSION/CHECKLIST 및 두 디자인 history 변경은 개발 폴더에 보존했다. 2026-10-20에는 사용자 요청으로 최신 문서를 현재 프로젝트에 다시 합쳤다.
- 앞선 분리 단계는 worktree와 디자인 브랜치 생성, 문서 이전만 수행했고 앱 코드 변경·stage·commit·push·stash는 실행하지 않았다. 2026-10-20에는 문서 파일만 현재 프로젝트로 복사하고 관리 위치와 오래된 범위 표기를 갱신했다. 브랜치 전환·Git 병합·stage·commit·push·stash는 실행하지 않았다. 현재 프로젝트의 브랜치 전환이 이 문서에도 영향을 주므로 다른 세션과 같은 파일을 동시에 편집하지 않는다.

## 승인된 방향과 결정 이유

- 긴 PDF를 확대하고 연속 스크롤하며 읽는 사용이 최우선이다. 차분한 중립색과 제한된 파랑으로 문서보다 도구가 먼저 보이지 않게 한다.
- 홈은 이어 읽기와 최근 문서를 중심으로 구성한다. 다시 열었을 때 마지막 읽던 위치에 가장 빨리 접근하게 한다.
- 기본 읽기는 전체 화면이며 중앙 1/3 단일 탭으로 도구를 연다. 도구는 문서 위에 겹쳐 표시해 노출 전후 PDF의 배율과 내부 위치를 유지한다.
- 큰 ‘문서 목록’ 버튼은 PDF 제목 왼쪽의 작은 뒤로가기 아이콘으로 바꾼다. 문자 `<` 대신 끝이 둥근 벡터 chevron을 사용해 다른 UI와 일관된 조형을 만든다.
- 도구의 ‘읽기 계속’ 버튼을 없앤다. 도구가 열린 동안 조작 버튼을 제외한 문서·도구 여백 탭으로 닫아 읽기로 복귀한다. 도구가 닫힌 상태의 열기 제스처는 중앙 탭으로 유지한다.
- 도구 하단에 페이지 번호와 수평 페이지 이동 슬라이더를 둔다. 대략적인 위치 이동은 슬라이더, 정확한 번호 이동은 기존 페이지 입력으로 담당한다.
- 테마는 앱 UI에 적용하며 PDF 내부 색과 외부 배경색 설정은 유지한다. 읽기 밝기와 화면 유지는 열람 중에만 적용해 문서 목록 사용에 영향을 남기지 않는다.

사용자가 추천 방향·플로우 진행과 뒤로가기/읽기 복귀 변경을 지시했고 페이지 슬라이더 추가를 요청했다. 개별 시안 수정의 진행 승인을 전체 디자인의 최종 수용이나 개발 완료로 해석하지 않는다.

## 사용자 흐름과 화면별 상태

### 시작과 홈

첫 실행 → 빈 홈 → PDF 열기 → Android SAF → 문서 준비 → 첫 읽기 안내 → 전체 화면 읽기. 재방문은 이어 읽기 카드/최근 목록 → 마지막 내부 위치 복원이다. SAF 자체를 앱에서 재설계하지 않는다.

- 기본: 이어 읽기 카드, 최근 문서, PDF 열기, 설정.
- 빈 상태: 첫 행동으로 PDF 열기를 안내한다.
- 로딩: 진행 중 표현과 취소/복귀 경로를 제공한다. 실제 측정 불가한 진행률을 숫자로 만들지 않는다.
- 오류: 파일 열기/권한 오류는 다시 시도·다시 선택을 제시하고 읽기 기록을 임의로 지우지 않는다. 목록 저장소 오류와 개별 파일 오류를 구분한다.
- 기록 삭제는 원본 PDF 삭제와 다르다는 점을 확인 문구로 알린다.

### 읽기와 도구

기본 전체 화면 → 중앙 탭 → 상단 제목/뒤로가기 + 하단 페이지 수/슬라이더/페이지 이동·북마크·설정 → 빈 공간 탭으로 복귀한다. 슬라이더는 도구를 열었을 때만 보인다.

- 슬라이더 조작 전 현재 페이지를 표시하고, 조작 중 목표 페이지를 미리 보여 준 뒤 놓을 때 이동한다는 동작을 설계했다. 실제 드래그 구현은 아직 없다.
- 이동은 기존 페이지 이동 정책을 사용하며 줌과 가로 위치를 유지한다. 일반 읽기에 페이지 스냅을 도입하지 않는다.
- 로딩/유효 위치 미확정이면 페이지 이동과 북마크를 비활성화한다. 1페이지 문서 등의 범위 경계도 구현 시 처리해야 한다.
- 도구를 닫았을 때 페이지 번호는 사용자 설정을 따른다. 기본은 숨김이며 도구 안의 페이지 수와 구분한다.

### 페이지 이동과 북마크

- 페이지 이동은 숫자 입력, 전체 범위 안내, 이동/취소로 구성한다. 잘못된 입력은 해당 필드에 오류를 보여 주며 입력을 유지한다.
- 북마크는 현재 위치 추가, 목록에서 이동, 삭제 확인을 제공한다. 빈 상태는 추가 행동을 안내하고 저장 실패는 성공 알림으로 덮지 않는다.
- 북마크/기록 삭제는 원본 파일에 영향을 주지 않는다. 본문 검색이나 목차를 북마크의 부가 기능으로 넣지 않는다.

### 설정

- 공통: 방향 5종, 자동/수동 외부 배경색, 페이지 번호, 표시 설정.
- 문서별: 원본 크기/통일 너비, 페이지 간격 0–72pt, 기본 0pt. 문서를 열지 않은 홈에서는 문서별 설정을 비활성화한다.
- 배경색: 자동 선택과 수동 프리셋/#RRGGBB 입력. 자동을 꺼도 이전 수동색을 유지한다. 입력 오류와 저장 오류를 구분한다.
- 표시 설정: 시스템/밝게/어둡게, 시스템 밝기 사용, 수동 1–100%, 읽는 동안 화면 유지. 시스템 밝기일 때 수동 조절은 비활성화하지만 이전 값을 보존한다.
- 표시 설정은 초안을 편집한 뒤 적용/취소한다. 테마 변경 초안만으로 배경 화면을 즉시 바꾸지 않는다. 저장 성공 뒤 적용하고 저장 실패 때 기존 값을 보존한다.
- 긴 설정은 내용 영역만 스크롤하고 하단 적용/취소는 접근 가능하게 둔다. 어두운 테마에서도 PDF 내용과 선택된 외부 배경은 유지한다.

### 크기와 접근성 검토

세로 360×800, 가로 800×360, UI 글꼴 200% 예시, 320×640 키보드 예시를 준비했다. PDF 본문은 고정 레이아웃이므로 UI 글꼴 배율 변화와 PDF 줌을 구분한다. 실기기의 시스템 inset, 긴 제목, TalkBack 포커스/레이블/슬라이더 값 조절, 대비와 확대 상태는 구현 후 검증 대상이다.

## 상호작용 상세 — 2026-10-19 검토안

이 절은 기존 방향 안에서 개발에 필요한 예외 동작을 구체화한 검토안이다. 최종 디자인 수용과 Android 구현은 별도다. 첫 상세화 단계에서 정적 예외 화면 3개를 추가했고, 이후 첫 안내/큰 글꼴 대표 연결과 중앙 탭 범위를 보완했다.

### 페이지 슬라이더: 조작과 확정

두 가지 방식을 비교했다. 드래그하는 동안 PDF를 계속 이동하면 목표 문서를 즉시 볼 수 있지만, 긴 문서에서 렌더 요청이 늘고 읽던 위치를 잃기 쉽다. **추천은 목표 번호만 미리 보여 주고 놓을 때 한 번 이동**하는 방식이다. 기존 화면을 유지하면서 대략적인 이동 위치를 선택할 수 있다.

1. 대기: 실제 현재 페이지를 `128 / 320페이지`로 표시한다. 손잡이와 트랙은 48 높이의 터치 영역 안에 둔다.
2. 누름: 현재 문서·페이지·줌·가로 위치·내부 앵커를 조작 시작 상태로 기억한다. 같은 조작에서 문서 스크롤이나 도구 닫기를 함께 실행하지 않는다.
3. 드래그: 현재 페이지와 목표를 구분해 `현재 128 / 320 · 이동할 240`으로 표시한다. PDF는 그대로 두고 손잡이와 목표 번호만 움직인다. 썸네일 렌더링은 이번 범위에 넣지 않는다.
4. 놓기: 마지막 유효 목표에 이동을 한 번 요청한다. 현재 페이지와 같으면 이동/저장을 요청하지 않는다. 연속적인 렌더·기록 쓰기를 드래그 중에 수행하지 않는다.
5. 이동 완료: 실제 위치 기준으로 페이지 수와 손잡이를 갱신한다. 기존 페이지 이동의 줌·가로 위치 보존 정책을 재사용한다. 스크러버로 이동한 뒤에는 도구를 유지해 추가 조절을 가능하게 한다. 숫자 입력 이동은 기존처럼 이동 후 읽기로 복귀한다.
6. 준비 중: 실제 이동 전에는 목표를 현재 페이지로 확정 표시하지 않는다. 기존 문서 준비 안내를 사용하고 중복 이동을 막는다. 문서가 유효한 탐색 실패면 기존 읽기 위치와 도구를 유지하고 간단한 실패 안내를 제공한다. PDF 자체의 읽기/렌더링 실패는 기존 앱처럼 기록을 보존하고 목록 오류로 복구한다.

페이지 수가 N이고 N > 1일 때, 트랙에서 정규화한 위치 t를 0–1로 제한하고 표시 목표는 `1 + round(t × (N − 1))`로 계산한다. 양 끝은 반드시 첫/마지막 페이지다. UI 표시는 1부터, 내부 페이지 인덱스는 0부터 사용하며 단일 페이지 분기는 별도로 처리한다. 일반 읽기에는 페이지 스냅을 추가하지 않는다.

### 드래그 취소와 다른 제스처

- 시스템의 제스처 취소, 두 번째 손가락 진입, 앱 비활성화, 회전/화면 재생성, 문서 교체 시 미확정 목표를 버린다. 문서 이동이나 읽기 기록 저장을 새로 요청하지 않는다.
- 드래그 중 뒤로가기는 먼저 미리보기만 취소하고 도구를 유지한다. 다시 뒤로가기를 누르면 도구를 닫는다. 별도 취소 버튼은 추가하지 않는다.
- 트랙 좌우 밖으로 움직이면 목표를 첫/마지막 페이지로 제한한다. 앱 화면 밖으로 벗어나거나 시스템에서 제어를 잃은 조작은 취소한다. 확정되지 않은 목표를 마지막 읽기 위치로 저장하지 않는다.
- 도구 바깥의 단일 탭은 도구를 닫되, 스크롤/핀치/플링을 탭으로 처리하지 않는다. 조작 버튼과 슬라이더가 소비한 이벤트는 빈 공간 닫기로 전달하지 않는다.
- Figma의 화면 전체 투명 탭 영역은 연결을 표현하기 위한 것이다. Android에서 PDF의 스크롤·확대를 가로막는 전면 터치 뷰로 그대로 구현하지 않는다.

### 한 페이지·로딩·범위 경계

- 한 페이지: `1 / 1페이지`를 표시하고 중립색 트랙만 남긴다. 손잡이/채움/목표 풍선은 숨기며 페이지 이동 버튼도 비활성화한다. 북마크와 설정은 정상 사용할 수 있다. 이동할 곳이 없다는 점을 시각적으로 드러내면서 도구 위치는 유지한다.
- 로딩/페이지 수 미확정: `0 / 0` 같은 잘못된 페이지 수를 보여 주지 않는다. 슬라이더·페이지 이동·북마크를 비활성화하고 문서 준비 상태를 표시한다.
- 첫/마지막 페이지: 손잡이 중심을 트랙 끝에 맞추고 터치 영역을 화면 안에 유지한다. 목표 풍선은 화면을 벗어나지 않게 위치를 제한한다.
- 큰 문서: 최소 터치 이동량을 한 페이지로 고정하지 않는다. 대략 이동은 슬라이더, 정확한 이동은 숫자 입력이 담당한다. 전체 문서 고해상도 선로딩이나 추가 캐시를 도입하지 않는다.

### 긴 제목과 읽기 위치

- 뒤로가기 48×48은 고정하고 제목은 남은 너비에서 한 줄 끝 말줄임을 사용한다. 여러 줄 확장이나 자동 흐르는 제목은 문서 영역을 가리므로 선택하지 않는다.
- 시각적으로 줄여도 접근성 설명에는 전체 제목을 제공한다. 전체 제목 확인용 새 상세 화면·툴팁은 이번 범위에 추가하지 않는다.
- 도구 열기/닫기, 목표 미리보기/취소, 제목 길이 변화로 PDF 영역 크기·줌·가로 위치·내부 앵커를 바꾸지 않는다. UI 글꼴 확대 시에는 헤더 높이/줄맞춤을 검증하되 문서 뷰포트를 밀어내지 않는다.

### 첫 읽기 안내와 접근성

첫 안내의 노출 정책은 **앱 실행 중 최초로 문서를 성공해서 연 시점에 한 번, 세션 메모리로만 관리**하는 안을 추천한다. 설치당 한 번 노출하려면 새 영속 상태가 필요하고, 문서마다 반복하면 읽기를 방해한다. 이 추천안은 아직 사용자 최종 수용이나 앱 구현이 아니다.

- 안내는 읽기를 막지 않는 짧은 설명으로 하고 첫 탭/스크롤/확대 시 숨긴다. 첫 중앙 탭은 안내 닫기와 도구 열기를 함께 수행해 추가 탭을 요구하지 않는다. 기존 첫 안내 화면에도 하단 비차단 안내를 반영했고 확인 버튼과 dim 처리를 제거했다. 노출 이력과 실제 스크롤/확대에 따른 해제는 앱 구현 대상이다.
- TalkBack에서는 페이지 슬라이더를 현재 값/전체 범위가 있는 조절 요소로 제공한다. 증가·감소 한 동작에 한 페이지를 이동하고 매 단계 확인 피드백을 제공하는 안을 사용한다. 터치 드래그 중 매 픽셀 값을 연속 읽지 않는다.
- 비활성 슬라이더와 페이지 이동은 포커스 가능한 활성 조작으로 안내하지 않는다. 한 페이지 상태와 현재 페이지는 일반 텍스트로 전달한다. 홈 복귀 아이콘에는 ‘문서 목록으로’ 접근성 이름을 제공한다.
- PDF 본문 읽기/TalkBack은 현재 앱에 구현된 별도 기능이다. 이 디자인의 접근성 명세와 구현 수용 결과를 구분하며, 디자인 적용으로 기존 본문 읽기 접근을 제거하지 않는다.

- 128에서 240까지 드래그하는 동안 PDF가 움직이지 않고, 놓을 때 최종 목표로 이동 요청을 한 번만 보낸다.

- 긴 제목과 UI 글꼴 200%에서도 뒤로가기 터치 영역·설정 접근을 유지한다. 긴 제목과 글꼴 200% 조합의 세로 대표 시안은 확인했으며, 이를 가로·다른 화면 크기·실기기 검증으로 대신하지 않는다.
- TalkBack으로 현재 값/범위를 알 수 있고 페이지 조절·정확한 숫자 입력·홈 복귀가 가능하다. 실제 기기에서 별도 검증한다.

### 첫 안내의 시각 표현과 대표 연결

기존 첫 읽기 화면 `8:105`의 중앙 확인창·‘알겠어요’ 버튼·전체 화면 dim을 제거하고, 기존 Info Notice 컴포넌트를 재사용한 하단 안내로 바꿨다. 문구는 ‘화면 중앙을 탭하면 / 읽기 도구가 나타나요.’다. 별도 확인 동작을 요구하지 않고 문서의 원래 배율과 위치를 유지하기 위한 변경이다.

- 하단: y=532, 높이 268. 현재 페이지 28/44, 슬라이더 터치 높이 48, 도구 행 높이 112를 사용한다.
- ‘페이지 이동’은 두 줄로 배치하고, 북마크/설정은 한 줄을 유지한다. 버튼 너비 약 98.67 안에서 라벨 너비 78/78/52, 높이 88/44/44로 들어감을 확인했다.
- 기존 도구 컴포넌트 인스턴스를 재사용하되 큰 글꼴 표본에서 라벨을 내용 너비에 맞게 조절했다. 최초에 상속된 좁은 텍스트 폭 때문에 과도한 줄바꿈이 발생한 것을 보정했다. 새 컴포넌트·변수·서체 의존성은 추가하지 않았다.
- [큰 글꼴 읽기](https://www.figma.com/design/wFQ8qOUx3YfMy8u0E3t7fM?node-id=81-926)와 도구 사이의 중앙 탭/빈 공간 닫기를 연결했다. 설정은 기존 큰 글꼴 설정 검토 화면으로, 페이지 입력과 북마크는 기존 일반 글꼴 예시로 연결한다. 모든 후속 화면을 큰 글꼴로 완성한 흐름은 아니다.

첫 안내와 큰 글꼴용 대표 프레임은 81:896, 81:911, 81:926, 81:941의 4개다. PDF 위치 x=24/y=-110, 크기 312×996과 PDF 하위 텍스트·서체·크기·채움·위치가 원본 읽기 프레임과 동일함을 검사했다. 도구가 덮는 영역만 늘어나며 PDF 뷰포트를 밀어내지 않는다.

### 중앙 탭 범위 보정과 검증 한계

기존 읽기 프로토타입 5개에서 중앙 탭 영역이 가로 전체 너비였음을 발견했다. 기본/자동 배경색/이동 후/다크 읽기 예시와 새 읽기 예시의 중앙 영역을 가로·세로 모두 화면의 1/3로 맞췄다. 360×800 기준 x=120/y≈266.67, 크기 120×266.67이다. 앱의 중앙 탭 구현을 바꾼 것은 아니다.

- 기본 첫 안내, 글꼴 200% 첫 안내, 긴 제목/글꼴 200% 도구의 렌더를 시각 확인했다.
- 구조 검사에서 도구 라벨의 너비/높이가 각 버튼의 내부 영역에 들어갔다. 프로토타입 내비게이션 연결 397개 중 잘못된 목적지는 0개였다.
- 대표 연결의 출발점/목적지를 검사했다. 이번 단계에서 브라우저 클릭 재현, 실제 기기의 스크롤/핀치, TalkBack, 자동 글꼴 배율/회전 검증은 실행하지 않았다.
- 후속 단계에서 짧은 가로 화면/좁은 폭의 배치와 오류/복구를 문서로 구체화했다. 추가 Figma 프레임은 호출 한도로 미실행이다. 이번 세로 대표 시안을 모든 화면 크기의 검증으로 확대 해석하지 않는다.

## 반응형 배치와 복구 흐름 — 2026-10-19 인계 초안

이번 단계는 **문서로 작성한 설계안**이다. Figma MCP가 Starter 요금제 호출 한도를 반환해 기존 화면을 더 읽거나 새 프레임을 작성하지 못했다. 아래 가로/좁은 화면 배치와 복구 세부 상태는 Figma 반영·시각 확인이 남아 있다. 앞서 확인한 세로 대표 시안과 완료 상태를 섞지 않는다.

### 반응형 도구 배치

가로 화면에서도 세로 도구를 그대로 쌓는 안, 옆 패널로 옮기는 안, 하단을 좌우로 나누는 안을 비교했다. **추천은 넓고 짧을 때만 하단을 좌우로 나누는 안**이다. 기존 조작 순서를 유지하면서 큰 글꼴에서도 문서가 보이는 공간을 확보하고, 문서를 옆으로 밀지 않는다.

치수는 시스템 inset을 제외한 사용 가능 영역을 기준으로 하는 검토용 논리 크기다. PDF point·실제 화면 px와 구분하며, 아래 단순 산술 확인은 실제 Android 레이아웃 검증이 아니다. 분기점도 구현에서 글꼴 측정과 함께 검증한다.

- 일반 세로 360×800/글꼴 100%: 기존 상단 64, 하단 198, 가로 여백 24를 유지한다. 도구 사이에 가려지지 않는 문서 높이는 538이다.
- 좁은 세로 320×640/글꼴 200%: 가로 여백을 16으로 줄여 내부 너비 288을 확보한다. 상단 80, 하단 268, 가운데 문서 높이는 292다. 제목의 남은 너비는 240이며 한 줄 말줄임한다. 세 도구 너비는 약 90.67, 양옆 padding 4를 뺀 내부 너비 약 82.67에 기존 큰 글꼴 라벨 78이 들어가는 계산이다. 실제 서체 렌더는 미확인이다.
- 넓고 짧은 화면: 사용 가능 너비 약 760 이상/높이 480 미만을 초기 분기 기준으로 제안한다. 하단 높이 120 안에서 페이지 번호/슬라이더를 왼쪽, 페이지 이동/북마크/설정을 오른쪽에 둔다. 세로의 독립된 3단 배치를 그대로 축소하지 않는다.
- 800×360 예시: 양옆 24, 내부 너비 752를 페이지 탐색 240 + 간격 24 + 도구 488로 나눈다. 도구 한 개 너비 약 157.33, 높이 104를 확보한다. 200%에서 상단 80/하단 120이면 가운데 문서 높이 160, 100%에서 상단 64/하단 120이면 176이다. 라벨이 두 줄로 흐르더라도 도구 안에서 88의 글자 높이와 상하 8을 수용한다는 설계안이다.
- 좁으면서 짧은 화면: 위 좌우 배치가 맞지 않으면 하단 도구의 페이지 번호/슬라이더 구역만 세로 스크롤하고, 페이지 이동/북마크/설정 행은 하단에 유지한다. 640×360/200%의 예시는 상단 80, 하단 최대 184로 문서 노출 높이 96을 남긴다. 하단 내부는 탐색 스크롤 영역 48 + 간격 8 + 조작 행 112 + 상하 여백 합계 16이다. 페이지 수와 슬라이더를 스크롤로 모두 접근할 수 있어야 한다.
- 이보다 작은 다중 창/접근성 조합에서 96의 문서 노출을 항상 보장한 것은 아니다. 도구 접근과 닫기 동작을 우선 유지하고 추가 조합을 검토한다. PDF 뷰포트는 도구 때문에 resize하거나 자동으로 축소하지 않는다.

가로 전환에서도 PDF 서체와 사용자 줌을 UI 배율에 맞춰 바꾸지 않는다. 보이는 영역 크기에 따른 내부 위치 복원은 기존 뷰포트 정책을 따르고, Figma 문서를 임의로 화면 너비에 늘여 실제 동작처럼 보이게 하지 않는다. 노치/시스템 바와 키보드를 제외한 남은 크기를 다시 계산한다.

### 짧은 화면의 설정과 입력

- 설정은 헤더, 세로 스크롤 가능한 내용, 적용/취소 조작 영역으로 나눈다. 가로 공간을 쓰더라도 항목을 두 열로 흩어 읽기 순서를 바꾸지 않는다.
- 기본 크기의 적용/취소는 가로로 둘 수 있다. 큰 글꼴에서 두 문구가 들어가지 않으면 세로로 쌓고 버튼 높이를 내용에 맞춘다. 폰트를 줄이거나 터치 영역을 48보다 작게 만들지 않는다.
- 헤더와 고정 조작 영역을 제외한 나머지를 스크롤 본문에 할당한다. 매우 짧아 본문이 거의 사라지면 조작 영역도 같은 세로 스크롤 흐름에 포함하고 포커스 이동으로 입력/확정에 접근하게 한다. 모든 높이에서 고정 footer를 강제하지 않는다.
- 페이지 번호/색상/간격 입력 중에는 포커스 필드, 오류, 확정 동작이 키보드에 가려지지 않게 스크롤한다. 오류가 나도 입력값과 포커스를 보존하고, 뒤로가기는 키보드 → 입력/설정 → 읽기 순서로 닫는다.
- 이는 새 설정 기능 추가가 아니라 기존 설정 표현의 반응형 적용안이다. 800×360 설정, 320×640 큰 글꼴+키보드 조합은 아직 새 Figma 프레임으로 검토하지 않았다.

### 오류 유형별 복구 계약

[PdfFailure](../app/src/main/java/dev/example/ebookviewer/PdfFailure.kt), MainActivity의 `documentFailed`/`requestPage`/`showDisplaySettings`, 플랫폼 다이얼로그 저장 흐름을 기준 소스에서 다시 읽었다. 오류별 실제 동작을 다음처럼 구분한다.

- 파일 접근 권한 소실/위치 변경: 문서 목록에서 기존 기록을 유지하고 ‘다시 선택’을 우선 제공한다. 선택은 Android SAF로 진행하며 취소하면 기존 기록을 지우거나 다른 문서로 바꾸지 않는다. 단순 재시도가 권한을 되살린다고 설명하지 않는다.
- 일시적 열기 실패/시간 초과: ‘다시 시도’와 목록 복귀를 제공한다. 재시도는 사용자의 행동으로 시작하고 실패 반복을 자동 루프로 만들지 않는다. 현재 소스에도 재시도/다시 선택 경로가 있다.
- 빈 파일/손상/지원하지 않는 문서: 읽을 수 없다는 사실과 다른 파일을 선택하는 행동을 제공한다. 원인을 특정할 수 없는 오류를 ‘파일 손상’으로 단정하지 않는다.
- 비밀번호 PDF: 현재 제외 범위임을 알리고 목록/다른 파일 선택으로 복구한다. 비밀번호 입력, 암호 해제, 외부 업로드를 새 메뉴로 추가하지 않는다.
- 페이지 번호 입력 오류: 입력 화면에서 범위를 안내하고 값을 수정하게 한다. 기존 문서 위치와 입력값은 유지한다. 무효한 번호를 마지막 페이지로 조용히 바꾸지 않는다.
- 페이지 위치 준비 중/스크러버 목표 이동: 현재 값과 미확정 목표를 구분한다. 문서가 유효한 단순 탐색 실패는 기존 읽기 위치를 유지한다. **PDF 자체의 읽기/렌더링 실패는 현재 앱처럼 기록을 보존하며 문서 목록의 파일 오류로 전환**한다. 렌더러가 종료된 상태에서도 문서를 계속 보여 준다고 약속하지 않는다.
- 표시 설정 저장 실패: 적용된 기존 값은 유지한다. 원인이 확정되지 않으면 ‘설정을 저장하지 못했어요. 기존 설정을 유지했어요.’처럼 사실만 안내한다. 저장 공간 부족 등 특정 원인은 확인된 경우에만 설명한다.
- 설정 저장 실패 후 초안: 새 UI에서는 편집 초안을 메모리에 유지해 같은 값으로 재시도/수정할 수 있게 하는 안을 추천한다. 현재 플랫폼 다이얼로그는 적용 직후 닫히고 저장 실패를 따로 알리므로 이 초안 복구 UI는 아직 없다. 실패를 저장 성공으로 표시하거나 즉시 새 테마를 적용하지 않는다.
- 기록/북마크 저장 실패: 성공 안내나 완료 체크를 보여 주지 않는다. 원본 PDF는 보존하며 실제 저장 결과 기준으로 목록을 갱신한다. 목록을 읽지 못한 상황을 문서 0개인 정상 빈 상태로 바꾸지 않는다.
- 삭제 취소/실패: 읽기 기록 삭제와 북마크 삭제를 각각 명시한다. 취소 시 변화가 없어야 하며, 실패 시 기존 항목을 성공적으로 없앤 것처럼 표시하지 않는다. 원본 PDF 삭제는 제공하지 않는다.

실제 복구 UI에는 현지화한 안전한 오류 문구를 쓰며, provider의 원시 예외/개인 URI를 그대로 표시하지 않는다. Figma의 저장 실패 화면 `72:2737`은 기존 대표 예시이고 이번 단계에서 다시 검사하거나 확장한 것은 아니다.

### 개발 인계 순서와 완료 기준

이 순서는 검토 가능한 **인계 제안**이며 다른 개발 세션에 자동으로 구현 지시를 보내거나 앱 코드를 수정하지 않는다. 병합/출시 승인도 아니다.

1. **기존 기능의 스타일·배치 적용:** 색상/서체/간격, 홈의 이어 읽기/최근 목록, 기존 페이지 이동·북마크·설정 UI를 적용한다. 기능 저장 모델과 PDF 엔진은 유지한다. 인수 조건은 기존 열기/복원/저장·방향 동작 유지와 문서 없는 설정의 비활성 상태다.
2. **읽기 도구와 반응형:** 제목 옆 아이콘, ‘읽기 계속’ 제거, 빈 공간 닫기, 가로/좁은 화면 배치를 적용한다. 인수 조건은 PDF 뷰포트/줌 보존, 스크롤/핀치를 닫기로 오인하지 않음, 긴 제목·큰 글꼴에서도 모든 조작 접근 가능이다.
3. **신규 페이지 슬라이더:** 목표 미리보기/놓을 때 1회 이동/취소/준비 중/단일 페이지/접근성 조절을 구현한다. 인수 조건은 미확정 목표 저장 없음, 실제 위치 기준 표시, 기존 숫자 이동과의 일관성, 추가 고해상도 선로딩 없음이다.
4. **안내·저장 실패 초안 복구와 통합:** 첫 안내 노출 정책과 실패 후 초안 유지 여부를 최종 확인해 적용한다. 기존 기능의 오류 피드백은 앞 단계에서도 보존한다. 인수 조건은 중복 확인 요구 없음, 실패를 성공처럼 표시하지 않음, 실제 기기의 TalkBack/키보드/회전/큰 글꼴 검증이다.

표시 설정, 자동 배경색 등 이미 있는 기능을 ‘신규 기능 개발’로 다시 요구하지 않는다. 선택/복사 UI는 후속 보류이며, 이미 구현된 본문 읽기/TalkBack과 전면 디자인 적용을 하나의 완료로 합치지 않는다. 새 런타임 의존성·Compose 전환·렌더 엔진 변경은 이 인계안에 포함하지 않는다.

새로운 UI 전용 기능을 발견하면 이 목록에 추가하고, 구현을 소스로 확인한 항목은 기준 SHA와 함께 아래 구현 확인 목록으로 옮긴다.

## Figma 프로토타입의 재현 범위와 한계

- 홈 → 읽기 → 도구 → 설정과 자동/수동 배경색 대표 흐름을 연결했다. 빈 공간 탭 닫기, 아이콘으로 홈 복귀, 취소의 대표 경로를 확인했다.
- 페이지 이동은 128 → 240을 탭으로 전환하는 대표 예시다. 드래그 상태 화면은 있으나 실제 연속 드래그·PDF 위치 계산·렌더링은 없다.
- 표시 설정은 테마 3 × 시스템 밝기 2 × 수동값 표본 2 × 화면 유지 2의 초안 24개와 적용 후 24개 상태로 표현했다. 밝기 표본은 50/70%이며 실제 앱은 1–100%다.
- 시스템 테마 예시는 OS가 밝은 상태라고 가정한다. 실제 OS 테마/밝기 변경, SAF, 파일 저장, PDF 확대·렌더링과 영속 저장은 Figma에서 실행하지 않는다.
- 조건부 프로토타입 동작 제약 때문에 고정 상태 화면으로 연결했다. 모든 호출 화면·직전 저장값·취소 복귀를 보존하는 완전한 상태 모델은 아니다. 적용 후 재편집이나 일부 자동/다크 화면의 보조 이동 경로는 초기 대표 상태로 돌아갈 수 있다.
- 어둡게 선택 → 시스템 밝기 끄기 → 50에서 70 선택 → 화면 유지 켜기 → 적용 → 다크 설정 요약/읽기 화면을 대표 경로로 확인했다. 모든 조합의 실제 앱 동작을 검증한 것은 아니다.

## 검증 기록과 남은 작업

이 절은 앞선 Figma 작업의 확인 결과와 이번 문서 정리를 구분한다.

- Figma 기초 규칙과 초기 화면 보드 렌더를 시각 검토했다. 도구 표시 전후 문서 위치/크기가 동일하고, 뒤로가기 터치 영역과 벡터 아이콘, 슬라이더 터치 영역을 확인했다.
- 큰 글꼴 예시는 콘텐츠가 스크롤되며 키보드 예시의 입력/주요 조작이 키보드 위에 배치되는 것을 확인했다. 표시 설정은 스크롤 본문과 고정 적용/취소 영역을 확인했다.
- 앞선 연결 검사에서 내비게이션 연결 385개 중 잘못된 목적지 0개를 확인했다. 라이트/다크 읽기 예시의 PDF 내용·서체·채움·위치/크기는 동일했다. 이는 그때의 Figma 상태 검사이며 Android 테스트 결과가 아니다.
- 이번 정리는 기준 소스와 문서 읽기, 이 파일의 로컬 링크/공백/변경 범위 검사로 검증한다. 앱 코드 변경이 없으므로 빌드·단위·Lint·ktlint·기기 테스트는 실행하지 않는다. 다른 세션의 기존 테스트 통과를 새 디자인 구현 통과로 옮기지 않는다.

남은 작업:

1. 문서의 반응형/복구 인계안을 Figma에 반영해 시각 확인한 뒤 사용자 최종 디자인 수용과 실제 인계 범위를 확정한다. 현재 추가 Figma 편집은 Starter MCP 호출 한도로 미실행이다.
2. 드래그 취소·단일 페이지·긴 제목의 상세 검토안과 정적 예외 화면 3종을 작성했다. 첫 안내의 비차단 시각 반영과 긴 제목/글꼴 200% 조합을 보완했다. 안내 노출 정책의 사용자 최종 수용과 Android 실제 드래그/안내 구현·실기기 검증은 남아 있다.
3. 다른 세션의 구현이 진행되면 기준 SHA를 갱신하고 차이 목록을 재대조한다. 앱 코드는 해당 개발 세션에서 수정한다.
4. 실제 구현 후 읽기 위치/줌 보존, TalkBack, 큰 글꼴, 회전, 키보드/inset, 다크 대비, 저장 실패를 검증한다.
5. 검토가 끝난 범위만 개발 준비 상태로 인계한다. 현재 Ready for dev나 전체 디자인 구현 완료를 선언하지 않는다.
