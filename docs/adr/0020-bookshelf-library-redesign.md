# ADR 0020 — 서재 격자·다중 책장 소속·격리 표지

날짜: 2026-10-23. 사용자 책장 요구/시안 기반 구현 지시에 따른 결정. 새 런타임 의존성은 없다.

## 결정

- 사용자 최종 구체화에 따라 기존 메인 상단은 ReaderMainHeader로 보존하고 ‘등록한 문서’ 영역을 ‘책장’ 격자로 교체한다. 헤더를 가진 ListView에 재사용 카드 행을 두어 전체 화면을 한 번에 스크롤한다. 카드에서 문서 목록으로 진입하고 뒤로가면 메인 책장 위치를 복원한다. 제목 옆 별도 진입 버튼/메인 전체 교체 안은 사용하지 않는다. 새 ‘책장에 추가’는 다중 소속 합집합이며 기존 모델의 단일 이동 API는 호환 목적으로 유지한다.
- 플랫폼 GridView/BaseAdapter로 표지 격자/목록을 재사용한다. 서재 홈, 책장 안, 문서 선택 모드를 분리한다. 기존 ReaderStyle/공통 폼과 시스템 글꼴을 재사용한다. Figma의 합성 표지 이미지를 앱에 넣지 않고 실제 문서 첫 페이지/실패 대체를 표시한다.
- 2026-10-24 후속 피드백: 미분류는 내용이 있을 때만 표시하는 첫 가상 책장으로 계산하며 저장/이름 변경/삭제/수동 순서 대상에 넣지 않는다. 대표 표지는 최대3개를 큰 표지+오른쪽 두 칸으로 구성하고 실제 읽은 시각만 표시한다. 관리 버튼은 투명 아이콘 중심이며 최신 피드백으로 메인 편집 테두리도 제거한다. 메인 이어 읽기 카드는 보존한다. 참고 사진의 편집 두 탭/원형 삭제 버튼에는 구분 배경을 제공하고 하단 시트는 뒤 창을 어둡게 하며 내용 높이에 맞춘다.
- 사용자가 계획을 수용한 뒤 별도 ‘내 책장 편집’의 삭제/순서 탭·드래그 초안/명시 저장, 더보기/이동 하단 시트를 플랫폼 Dialog로 구현했다. 이름 입력/선택/순서/이동 토글 초안은 Bundle로 보존하고 실패 후 재시도한다. 책장 생성은 편집 또는 이동 시트에서 제공한다. 더보기의 문서 추가는 이미 등록한 PDF 선택이며 새 파일은 메인에서 가져온다.
- 전체 문서에는 책장 이동이 없다. 실제 책장 이동은 기본 켜짐의 keep 토글로 현재 관계를 유지하거나 현재 관계만 제거하고 목적지에 추가하는 하나의 원자 저장이다. 다른 소속/읽기 위치/원본은 유지한다. 미분류에서는 토글 없이 목적지에 추가한다. 일괄 책장 삭제는 책장 관계만 지운다. 새 런타임 의존성/저장 형식 변경은 없다.
- 읽기 기록 v6은 URI별 책장 ID 집합을 저장한다. v5 단일 소속은 원소 하나인 집합, v1~v4는 미분류로 읽는다. 문서10,000/책장1,000 및 전체 소속100,000개를 상한으로 검증하며 중복/빈 소속/유효하지 않은 ID/잘림/미지원 버전을 거절한다. v6 작성 뒤 이전 앱으로의 다운그레이드는 지원하지 않는다. 읽기 위치 저장은 현재 카탈로그 소속/수동 순서와 병합한다.
- 책장에 추가는 합집합, 이 책장에서 빼기/책장 삭제는 해당 관계만 제거한다. 서재에서 제거는 원본을 지우지 않는 별도 확인이다. 문서 수동 순서와 책장 저장 순서는 정렬 선택으로 덮어쓰지 않는다.
- library-preferences.bin v1에 보기/문서 정렬/책장 정렬만 별도 AtomicFile·Application 직렬 큐로 저장한다. 처음은 격자/최근 읽은 순/사용자 지정이다. 한국어 Collator와 URI/책장 ID로 동률을 고정한다. 숫자는 Collator의 사전식 정렬이며 자연수 정렬을 보장하지 않는다. 아직 읽지 않은 문서는 최근순의 뒤에 둔다.
- BookCoverService는 요청별 isolated process/API30+ bindIsolatedService를 사용한다. 앱은 백그라운드에서 원본 읽기 FD와 작은 결과 파일 FD만 넘긴다. 이 서비스는 본문 읽기 서비스와 분리한다. API23~29에서는 기본 PDF 표지를 사용하고 원래 읽기는 유지한다. provider가 비탐색 FD를 주면 이 선택적 표지는 실패 대체하며 별도 원본 복사를 추가하지 않는다.
- 동시에 표지1개, 최대384×512 ARGB, 6초 서비스/7초 클라이언트 제한, RSS192MiB·가용512MiB 및 시스템 임계2배·lowMemory 거절을 적용한다. 100ms 샘플링은 순간 native 할당 상한 보장이 아니다. 원본이 큰/손상 PDF를 모든 경우 안전하다고 보장하지 않는다.
- 화면에 보이는 문서/책장 모음만 요청하고 최대32개 URI를 스케줄한다. 현재 가시 범위에서 이미 시도한 표지는 캐시에서 밀려도 계속 재생성하지 않는다. 문서 열기/서재 비활성/종료 때 취소하고 요청 세대와 완료 상태로 늦은 콜백을 버린다. provider 열기가 취소를 무시하면 기존 IO가 돌아올 때까지 새 준비를 시작하지 않는다.
- 메모리8MiB LRU, 앱 cacheDir의 book-covers-v1 디스크64MiB LRU, 원본 URI의 SHA-256 파일명을 사용한다. 출력 PNG 크기/폭/높이를 확인한 뒤 디코딩한다. 이전 비정상 종료의 임시 파일은15초가 지난 것만 정리한다. 표지 새로고침은 이 선택적 캐시만 지우며 기록/원본에 영향이 없다. provider 수정 시각은 신뢰하지 않아 자동 변경 감지를 보장하지 않고 명시적 갱신으로 처리한다.
- 표지 실패/메모리 부족/시간 초과는 PDF 기본 그림을 유지한다. 원본/PDF/표지/제목/URI를 로그/Git/외부 서비스로 내보내지 않는다. 이 수치는 코드 정책이며 실기기 측정 결과는 history에서 별도로 기록한다.

## 대안과 영향

최종 삭제 확인은 사용자 정정에 따라 화면 중앙의 둥근 대화상자와 테두리 취소/붉은 삭제 버튼을 사용한다. 이동/더보기만 하단 시트다. 원본 PDF 보존과 취소/복원 의미는 유지한다. [실행·사용자 수용](../history/2026-10-24-06-centered-delete-confirmation.md)을 구분한다.

AndroidX RecyclerView/이미지 라이브러리·새 PDF 엔진을 추가하지 않고 기존 플랫폼 계약을 유지했다. 작은 비트맵만 렌더해도 원본 디코딩 메모리는 클 수 있어 앱 프로세스 내부의 일반 executor 렌더는 채택하지 않았다. 표지 생성 속도보다 취소/읽기 독립/원본 보존을 우선하며 실패 시에도 서재를 사용할 수 있다.

## 검증

v5 고정 바이트 마이그레이션, v6 왕복·다중 소속·삭제·위치 병합·수동/이름/최근 정렬·설정 codec을 검증한다. 기기는 합성 PDF로 격리 표지/대체·실제 격자 선택·회전/큰 글꼴/가로·이어 읽기를 확인한다. 실제 실행 결과와 미실행은 SESSION/CHECKLIST/history에 구분한다.
