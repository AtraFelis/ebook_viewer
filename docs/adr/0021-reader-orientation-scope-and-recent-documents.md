# ADR 0021 — 본문 전용 방향과 최근 읽은 문서

2026-11-07. 사용자 요청으로 기존 방향/메인 UI 계약을 확장한다. 기존 Kotlin/Activity/View·AtomicFile을 사용하며 새 런타임 의존성이나 저장 형식 변경이 없다.

## 결정

방향 설정 v1은 본문 읽기의 선택을 저장한다. 메인·책장·문서 목록은 항상 `SCREEN_ORIENTATION_UNSPECIFIED`로 기기 회전 설정을 따른다. 본문 진입에 저장된 선택을 적용하고 이탈 때 고정을 해제한다. 메인에서 방향을 선택해도 그 화면을 강제 회전시키지 않고 다음 본문에 적용한다.

Activity의 방향 선택 캐시는 Bundle에도 보존해 읽기 재생성 도중 디스크 로드가 늦어도 선택을 유지한다. 비동기 로드/저장 결과는 완료 시점의 읽기 여부로 요청 방향을 계산한다. 홈 복귀 시 source/읽기 상태와 UI 복원을 준비한 뒤 방향을 해제해 새 Activity가 문서를 다시 열지 않도록 한다. 기존 줌·원본 앵커의 Bundle/기록 복원은 유지한다. 기기의 회전 잠금/센서 정책을 앱이 별도로 변경하지 않는다.

메인의 최근 읽은 문서는 읽기 기록 v6에서 position이 있는 항목만 골라 openedAt 내림차순·URI 동률 순서로 최대 5개 계산한다. 책장 소속/문서 사용자 정렬과 독립적이며 별도 최근 목록 파일을 만들지 않는다. 최신 문서는 기존 이어 읽기 카드/진행률, 나머지는 제목/읽기 위치가 있는 작은 항목이다. 모든 항목은 같은 열기/등록 제거 확인 경로를 사용하고 원본은 보존한다. 전체 카탈로그를 5개로 줄이거나 오래된 기록을 지우지 않는다.

합성 100페이지의 사용자 메뉴/콜백 연결은 제거한다. 내부 openSample/생성 코드는 계측과 합성 복원에 유지하며 새 외부 진입점은 없다. 실제 개인 PDF를 시험용 자료로 바꾸거나 진단 데이터를 공개하지 않는다.

## 대안과 영향

메인을 세로 고정하는 방식은 기기 회전 설정을 따르려는 요청과 맞지 않아 선택하지 않았다. 방향/기록을 새 저장소로 옮기거나 최근 목록을 중복 저장할 이유가 없어 기존 AtomicFile을 유지한다. 표지 렌더를 최근 목록에 추가하지 않아 캐시/격리 표지 예산도 확장하지 않는다.

메인과 본문 전환은 서로 다른 방향일 때 Activity 재생성을 유발할 수 있다. 단일 Activity의 목적지/설정과 읽기 위치를 보존하고 관련 회귀로 확인한다. 실제 센서/제조사 정책·다른 API와 전체 앱 검사 통과는 별도 판정한다. 구현과 실행 범위는 [계획](../plan/home-orientation-and-recent-documents.md)과 [실행 이력](../history/2026-11-07-01-home-orientation-and-recent-documents.md)에 기록한다.
