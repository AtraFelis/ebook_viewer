# ADR0018 — 원본을 보존하는 문서 여백과 읽기 기록v4

2026-10-22. [사용 피드백 계획](../plan/reader-usability-follow-up.md)에 따라 사용자가 문서 전체 공통 여백을 선택했다. View/Canvas·PdfRenderer·AtomicFile을 그대로 사용하며 런타임 의존성은 추가하지 않는다.

## 좌표와 저장

네 방향 각각 원본 페이지 크기의 정수0~45%를 숨긴다. 어떤 조합도 가로/세로 최소10%를 남기며 혼합 크기 페이지에는 같은 비율을 적용한다. 화면px는 DPI·사용자 줌에 따라 변하므로 저장하지 않는다. 기존 페이지 크기/간격·가로 잠금 설정에 crop을 추가하고 정상 저장 성공 뒤 반영한다. 도식 미리보기·초기화는 입력만 바꾸며 적용 전 취소는 읽기 화면에 영향을 주지 않는다. 실패 시 입력·재시도는 기존 SettingsSaveUi를 쓴다.

남은 너비/높이로 문서 최대폭·페이지 상단·스크롤 경계를 계산한다. 너비 통일도 남은 너비를 기준으로 하므로 공통 비율 자르기 전후 원본→문서 배율은 같다. 원본 타일 키/512px 격자/전체 저해상도 미리보기는 유지하고, 원본 좌상단을 잘린 양만큼 이동해 가시 범위만 요청·그린다. 기존 타일/미리보기도 새 clip 경계로 그려 숨긴 영역이 간격에 남지 않는다. 캐시64MiB/기존 취소/수명은 유지한다.

읽기 위치와 북마크 y는 계속 **원본 페이지의 비율**이다. crop은 원본 좌표와 문서 좌표의 변환에만 반영한다. 따라서 적용/초기화와 회전·점진 메타데이터·페이지 이동 시 같은 원본 지점과 사용자 줌을 유지한다. 이미 숨긴 영역의 북마크/앵커는 남은 페이지 끝으로 제한하고 문서 끝에는 기존 viewport 제한을 적용한다. 자르기로 줌을 다시 맞추거나 페이지 스냅을 추가하지 않는다.

`reading-records.bin` magic/기존 필드 순서는 유지하고 버전4에서 기존v3 잠금 바이트 뒤 좌/상/우/하 unsigned byte4개를 추가한다. 읽기는v1~v4, 구버전은 crop0으로 해석한다. 잘못된 비율·버전·잠금·간격·잔여 바이트는 오류이며 기존 파일을 초기화하지 않는다. 이전 앱은v4를 읽지 못하므로 자동 downgrade는 지원하지 않는다. Activity Bundle도 네 값을 보존하며 저장 중 재생성은 저장소의 결과를 우선한다. URI 재연결·위치 병합은 기존 전체 pageLayout을 보존한다.

PDF 원본은 수정하거나 복사/재인코딩하지 않는다. 숨긴 본문은 삭제된 것이 아니고, 현재 페이지 본문 읽기는 원본 전체를 읽는다. 설정 화면에서 이 차이를 안내한다. 페이지별 예외·OCR/검색/원본 PDF 편집·비밀 가림은 이번 범위 밖이다.

## 다른 두 피드백

자동 배경색은 새 대표 페이지 결과가 없으면 직전 색을 유지한다. 실제 분석 결과가 대체색인 경우에만 그 결과를 적용한다. 첫 문서/reset/명시적 설정 변경은 지정한 수동색을 쓴다. ADR0013의16색/120ms/24dp·늦은 결과 취소는 유지한다.

방향 아이콘은 중앙 탭 읽기 도구의 제목 오른쪽에 둔다. 기존 다섯 방향 선택/저장 성공 후 적용을 재사용하고 선택해도 창을 닫지 않는다. 일반 설정 진입은 상위 설정으로, 빠른 진입은 읽기 도구로 닫는다. 빠른 진입에는 숨겨진 상위 설정 Window를 만들지 않고 Bundle에 경로를 보존한다.

실제 빌드·JVM·기기 결과와 미검증 범위는 이번 history에 따로 기록한다. 문서/빌드만으로 기기 사용성과 성능을 완료로 세지 않는다.
