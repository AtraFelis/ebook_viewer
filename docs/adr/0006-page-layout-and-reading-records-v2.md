# ADR 0006 — 문서별 페이지 크기·간격과 읽기 기록 v2

후속 변경: 2026-10-22 [ADR0018](0018-document-crop-and-reading-records-v4.md)은 문서 공통 여백과 원본 좌표 앵커·기록v4를 추가한다. 아래는 여백 기능 이전의 결정 이력이며 현재 자르기/저장 계약은 ADR0018을 함께 따른다.

2026-10-17, P1. 기존 View/Canvas·PdfRenderer·AtomicFile을 사용하며 새 런타임 의존성이나 스택 변경은 없다. 구현·로컬 검사 및 API 33 합성 자료 기기 검증을 완료했다. 개인 PDF/다른 API 수용은 별도다.

## 배치와 설정

기본은 원본 크기 비율과 간격 0이다. 원본 모드는 PDF point를 같은 문서 단위로 배치하고 폭이 작은 페이지를 가운데 정렬한다. 너비 통일 모드는 확인된 페이지의 최대 너비 W를 기준으로 각 페이지에 배치 배율 si = W / wi를 적용한다. 화면 방향 때문에 W나 사용자 줌 z를 다시 맞추지 않는다. 점진 조사에서 더 넓은 페이지가 발견되면 W는 커질 수 있으며 같은 페이지 내부 앵커를 새 배치로 투영한다.

페이지 높이는 hi × si, 상단은 이전 배치 높이와 간격의 누적 합이다. 마지막 페이지 뒤에는 간격을 추가하지 않는다. 간격은 정수 0~72 문서 pt이며 사용자 줌에 따라 화면에서 확대된다. PDF 내부 여백을 자르거나 페이지 자체를 변경하지 않는다. 읽는 중 중앙 탭 → 설정 → 페이지 크기·간격에서 바꾸며 잘못된 입력은 적용하지 않고 취소는 원래 설정을 유지한다. 비열람 상태에는 적용할 문서가 없어 버튼을 비활성화한다.

모드·간격 변경은 사용자 줌을 그대로 두고 화면 중심의 페이지 내부 x/y 비율을 재투영한다. 문서 끝이나 좁은 페이지에서는 화면의 유효 범위로만 제한한다. 화면 중심이 앱 간격 안에 있다면 저장 앵커는 앞 페이지의 끝으로 정규화한다. 이는 실제 페이지 내부 앵커와 구분한다. 일반 스크롤에 페이지 스냅을 추가하지 않는다.

## 렌더 좌표

사용자 줌은 화면 px/문서 point이고, PDF 원본 point와의 실제 배율은 z × si이다. 원본 모드에서는 si = 1이다. 타일 키의 scale은 PDF point→비트맵 px 배율이며 배치 좌표와 혼용하지 않는다. 가시 타일 계산·미리보기·Canvas destination/clip에 si를 적용한다. 렌더러에 넘기는 타일은 계속 512px 단위이고 공유 캐시는 64MiB 상한을 유지한다. 페이지 전체의 고해상도 선로딩이나 P2 선명도 최적화는 추가하지 않는다.

## 저장과 이전 버전

`reading-records.bin`의 magic은 유지하고 쓰기 버전을 2로 올린다. 각 문서의 기존 필드 뒤에 모드 enum 이름과 간격 정수를 저장한다. 읽기는 v1/v2를 허용하며 v1은 원본/간격 0으로 해석한다. 다음 성공적인 AtomicFile 저장 때 v2로 이행한다. 기존 위치/제목/최근 시각은 유지하며 잘못된 모드·간격·알 수 없는 버전은 거부해 덮어쓰지 않는다. 북마크·방향·배경색·번호 표시 파일은 변경하지 않는다.

이후 구버전 앱은 v2 기록을 읽을 수 없다. 구버전도 미지원 버전을 덮어쓰지 않는 계약을 유지하지만 자동 역변환은 제공하지 않는다. Activity Bundle도 모드·간격과 내부 앵커를 보존한다. URI 재연결은 이전 기록의 배치 설정을 이어받는다.

## 검증
