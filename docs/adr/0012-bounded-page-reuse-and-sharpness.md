# ADR 0012 — 가시 선명도 계측과 4타일 배치 안의 페이지 재사용

2026-10-18. 기존 PdfRenderer/단일 worker/512px 타일/64MiB 캐시 유지. 새 런타임 의존성·플랫폼 텍스트 API 도입 없음.

## 계측과 비교

`PdfCanvasView`는 명시적으로 observer를 설정한 때만 가시 타일의 실제 화면 교차 면적을 구하고 onDraw 완료 시 전달한다. 현재 배율 타일만 분자에 포함하고 미리보기/다른 배율 fallback·페이지 간격·외부 배경을 제외한다. viewport가 바뀐 시점과 같은 viewport의 첫 선명 타일/95% 선명 면적 draw 시점을 구분한다. snapshot은 재사용하며 observer는 보관할 필드를 복사해야 한다. GPU 완료나 실제 디스플레이 표시 시점은 아니다.

worker의 opt-in 시간은 전달된 타일만 대상으로 한다. 요청→작업 시작(이전 타일 처리 포함), 해당 타일의 페이지 open/render/close 구간, 렌더 완료→main 전달을 나눈다. 취소/폐기된 타일 비용, bitmap 준비, 전체 요청 세대별 누적 CPU 시간과 동일하지 않다. 기본 앱 읽기에서는 observer가 null이며 로그/trace·개인 문서 정보가 생성되지 않는다.

계측 기준 소스는 main 5d74c68 + ede4e83이며 스케줄/렌더 정책은 P1과 같다. profile APK와 동일 자료 SHA·화면 크기/줌/주사율을 기준/개선에서 대조한다. 합성 벡터와 1440×2240 JPEG를 공유하는 48페이지 그레이/RGB 자료로 먼저 보통 스크롤/역방향 재방문을 비교한다. 재방문은 64MiB 초과 후 일부 타일이 퇴출되므로 완전 warm-cache 검사가 아니다. 공유 이미지·단순 내용은 원래 개인 고해상도 스캔의 구조 재현이 아니다.

## 작은 변경

기존 worker는 타일 하나마다 `openPage → render → close`를 반복한다. 페이지 준비/해석 비용이 반복될 수 있어 `RenderPageSession`으로 같은 배치의 연속된 페이지를 재사용한다. 입력 순서·가시 타일 우선순위·최대 4개 처리 후 yield·문서/세대/epoch 취소·늦은 bitmap 폐기는 유지한다. 페이지를 바꾸기 전/배치 마지막 타일/예외나 취소 후에는 페이지를 닫는다. 한 번에 열리는 페이지는 최대 1개이며 scheduler yield/메타데이터 조사/문서 종료까지 유지하지 않는다.

이는 페이지 전체 비트맵 캐시나 대량 선로딩이 아니다. native render 자체는 여전히 중간 인터럽트할 수 없고 자원 해제는 활성 호출 뒤 단일 worker에서 수행한다. 렌더/색 변환/이미지 디코딩 중 무엇이 시간을 차지하는지는 이 계측만으로 확정하지 않는다.

## 판정

최적화 전 계획의 목표(보통 정지 후 95% 선명화 p95 500ms 이하 또는 기준 대비 30% 감소, 이미 500ms 이하인 조건은 유지)를 적용하고 timeout/미완료 표본을 숨기지 않는다. 30표본×3회, 같은 profile/자료 조건을 대조한다. 빠른 플링/높은 배율·분리된 cold/warm·원본 해상도/압축별 대조·프레임·최종 통합/사용자 수용은 별도 미검증으로 남기며 일반 스크롤 비교만으로 P2 선명도 전체 완료를 선언하지 않는다.
