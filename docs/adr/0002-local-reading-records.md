# ADR 0002 — 플랫폼 기반 로컬 읽기 기록

후속: 문서별 모드/간격과 v1→v2 호환은 [ADR 0006](0006-page-layout-and-reading-records-v2.md)을 따른다. 아래의 원본/간격 0·버전 1 설명은 최초 구현 시점의 결정이다.

2026-10-17 (Asia/Seoul). P1 첫 구현 범위에 적용. 새 런타임 의존성이나 승인 스택 변경 없음.

## 결정

최근 PDF와 읽던 Ebook(PDF)은 URI 문자열을 키로 하는 하나의 기록을 공유한다. 표시 이름, 최근 열기 시각, 페이지 수, 화면 중심 페이지 인덱스·페이지 내부 정규화 좌표·사용자 줌을 앱 내부 `reading-records.bin`에 저장한다. 가로 좌표는 해당 페이지의 왼쪽 기준이며 좁은 페이지 밖의 화면 중심도 표현한다. 회전/목록 재열기는 같은 좌표 모델을 사용한다. 현재 간격 0/원본 크기 모드뿐이며 후속 모드 구현 때 스키마를 확장한다.

Android `AtomicFile`과 버전 1 이진 코덱을 사용한다. Application이 소유한 단일 작업 큐에서 읽기·쓰기·파일 정보 조회·URI 권한 확보를 처리한다. Activity가 겹쳐 재생성되어도 저장 순서가 유지된다. 기록 갱신은 이동 중 최대 초당 한 번 예약하고, 문서 전환·목록 이동·onPause·인스턴스 저장 시 현재 상태를 제출한다. 강제 종료 직전 아직 제출/완료되지 않은 최신 이동은 보장하지 않는다.

처음 연 문서는 표시 가능한 첫 페이지 크기를 확보한 뒤부터 기록한다. 저장된 위치로 복원하는 문서는 전체 페이지 크기 조사가 성공한 뒤에만 새 위치를 게시하므로 열기 실패가 이전 위치를 덮어쓰지 않는다. 새 문서의 뒤쪽 메타데이터 조사 중 실패하면 마지막으로 표시했던 부분까지의 위치는 남을 수 있다. 저장 파일의 알 수 없는 버전·손상은 빈 목록으로 간주해 덮어쓰지 않고 오류를 표시한다. 이런 경우 자동 복구/초기화 UI는 아직 없다. 기록 삭제와 URI 재연결은 원본 PDF를 수정/삭제하지 않는다.

동일 URI 재열기는 중복을 만들지 않는다. URI가 달라진 파일은 오류 화면의 다시 선택을 통해 기존 위치와 재연결한다. 서로 다른 provider URI가 실제 동일 파일인지 전체 PDF 해시로 판별하지 않는다. SAF의 영구 읽기 권한을 요청하고 확보하지 못하면 임시 접근임을 표시한다. 이동/삭제 후 권한은 여전히 실패할 수 있다.

## 목적·대안·라이선스·영향

- 현재 개인용 목록과 위치 저장에는 관계형 질의/반응형 데이터베이스가 필요하지 않다. 플랫폼 기능으로 P1 첫 기능을 검증한다.
- SharedPreferences는 복합 기록/버전 검증에 불리하고, SQLite/Room/DataStore는 현재 규모에 구현 복잡도 또는 추가 의존성을 늘린다. 필요해지면 목적·대안·라이선스·마이그레이션·영향을 제시하고 승인 후 도입한다.
- Android SDK 플랫폼 API와 기존 Kotlin/JDK API만 사용한다. APK에 새 제3자 저장 라이브러리나 라이선스가 추가되지 않으며 기존 lock/verification 메타데이터는 그대로다.
- 파일 전체를 원자 교체하므로 목록 규모가 크게 증가하면 비용이 증가한다. 버전 1은 최대 10,000개 기록을 허용하며 잘못된 좌표/중복 키/알 수 없는 버전을 거부한다. 새 저장소 채택 시 이 파일에서 마이그레이션해야 한다.
- 파일은 앱 전용이며 기존 backup 비활성 정책을 유지한다. 앱 제거/데이터 삭제 시 기록은 사라진다. PDF/미리보기/추출 텍스트를 기록 파일에 넣지 않고 URI·제목도 로그/Git/외부 서비스로 보내지 않는다.

## 근거와 남은 범위

[공식 SAF 문서](https://developer.android.com/training/data-storage/shared/documents-files)의 반환 grant flags, 영구 권한, 이동/삭제 시 재선택 제한과 [AtomicFile API](https://developer.android.com/reference/android/util/AtomicFile)의 외부 직렬화 필요성을 확인했다. Context7의 Android 문서 조회는 주로 FileProvider 자료여서 SAF 영구 권한의 직접 근거로 사용하지 않았다. 앱 compileSdk 35/minSdk 23 조합의 실제 빌드와 현재 API 33 실행 결과를 history에 기록한다.

전체 화면·설정·방향·배경색은 별도 P1 구현이다. 비탐색 provider의 상한/취소 가능한 임시 복사, provider별 영구 권한 수용, 개인 PDF 손입력과 기기 재부팅 검증은 남아 있다. 이번 구현을 P1 전체 완료로 표현하지 않는다.
