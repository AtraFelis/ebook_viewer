# ADR 0008 — 뷰어 수명과 캐시 취소

2026-10-17. 승인 스택 내 구현이며 새 런타임 의존성/저장 형식 변경 없음.

## 문제

기존 `trimCache()`는 캐시를 비운 직후 같은 타일을 요청했다. Activity가 보이지 않는 동안에도 캐시를 다시 채울 수 있었다. 또한 문서/타일 키만 비교하는 늦은 결과 검사는 취소 후 같은 키를 재요청하면 취소 전 결과를 다시 받아들일 수 있었다. Activity 종료 시 View에 남은 캐시 참조도 명시적으로 해제하지 않았다.

## 결정

- Activity의 `onStop`에서 플링을 멈추고 타일 작업을 취소하며 View 캐시/요청 키/대체 타일 참조를 비운다. 문서·페이지 메타데이터·내부 앵커·사용자 줌·페이지 설정은 유지하고 최종 위치를 비동기 저장한다.
- `onStart`에서 같은 문서/뷰포트의 가시 타일을 다시 요청한다. 부분적으로 보일 수 있는 `onPause`만으로 렌더링을 정지하지 않는다. `onStop`을 사용하므로 메모리 알림의 도착 여부에 의존하지 않는다.
- `onTrimMemory`는 타일 작업과 캐시를 무효화한다. 보이는 View는 다시 렌더링하고, 정지된 View는 복귀 전까지 픽셀을 다시 요청하지 않는다. 이 알림을 실제 OOM의 재현이나 복구 보장으로 취급하지 않는다.
- worker의 문서 ID/요청 세대와 별도로 타일 취소 epoch를 둔다. 정리 전에 완료되어 UI 큐에서 기다리는 결과는 같은 타일이 재요청되어도 버린다. 평소 스크롤의 중첩 타일 재사용 정책은 유지한다.
- 문서 교체/목록 복귀/종료에서는 기존 단일 worker 순서로 PdfRenderer/FD를 닫는다. Activity 파괴 시 View 캐시도 명시적으로 비운다. 이미 실행 중인 native 렌더는 강제로 중단하지 않고 완료 후 결과를 버린다.
- 백그라운드에서는 타일을 렌더링하지 않지만, 열린 문서의 renderer/FD와 진행 중인 제한된 페이지 크기 조사는 유지한다. provider 재접근 없이 복귀하기 위한 선택이며 전체 프로세스 메모리/FD가 0이 된다는 의미는 아니다.
- 캐시 상한은 기존 64MiB다. 제거된 Bitmap을 즉시 `recycle()`하지 않는다. 화면 렌더러가 이전 프레임의 픽셀을 참조할 수 있으므로 캐시 참조 해제와 실제 메모리 회수 시점을 구분한다.

## 근거와 검증 범위

Context7 Android Reference 조회와 [Activity 수명](https://developer.android.com/guide/components/activities/activity-lifecycle), [ComponentCallbacks2](https://developer.android.com/reference/android/content/ComponentCallbacks2)를 대조했다. Android 14부터 일부 기존 메모리 수준 알림이 전달되지 않고 API 35에서 관련 상수가 deprecated이므로 정지 처리를 해당 알림에만 맡기지 않는다. compile 35/min 23 계약을 바꾸지 않으며 실제 기기 수용은 API 33에 한정한다.

회귀는 바이트 상한/정지 중 캐시 0/같은 앵커로 복귀, 취소 전 UI 큐에 들어간 동일 키 타일의 배제, 문서 교체/종료의 FD 해제와 문서별 픽셀 분리, 실제 홈 화면 왕복 및 메모리 알림 주입을 확인한다. 동시성 테스트는 앱 자체 executor에 barrier를 넣어 완료된 타일의 UI 전달만 지연한다. native 렌더 동시 종료나 SDK 비공개 API에 의존하지 않는다. 시스템 메모리를 고갈시키거나 사용자의 문서를 읽어 측정하지 않는다. 실제 실행/실패/수정 결과는 history에 따로 기록한다.
