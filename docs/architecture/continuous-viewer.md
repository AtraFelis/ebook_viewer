# 연속 스크롤 구조 초안

상태: 목표 구조. P0는 플랫폼 Activity + PdfRenderer + View/Canvas로 승인·구현했고 Compose 최종 선택은 후속입니다. P1 후속은 원본/너비 통일·간격 설정까지 구현했고 로컬 검사와 API 33 합성 자료의 기기 검증을 통과했습니다([ADR 0006](../adr/0006-page-layout-and-reading-records-v2.md)). 아래의 전체 목표가 구현됐다는 뜻은 아닙니다. 현재 기기 검증 범위는 SESSION과 ADR을 따릅니다.

## 기술 후보

Kotlin 네이티브, 앱 셸 Compose 우선 검토. 읽기 영역은 View/Canvas와 Compose의 제스처·타일링·측정 안정성을 비교합니다. 페이지 목록 위젯만으로 요구가 충족된다고 가정하지 않습니다.

PdfRenderer를 기본 후보로 하되 검색·선택·암호화의 Android API별 차이를 확인합니다. 대안은 라이선스, 최소 API, ABI, 바이너리 크기, 유지보수, 동시성·취소·메모리로 비교합니다.

## 좌표와 배치

PDF 원점/회전/crop box를 문서 좌표로 변환합니다. 문서 y는 아래로 증가합니다. 페이지 크기 wi, hi와 배치 배율 si를 구분합니다.

- 원본 크기: si = 1, PDF point 공통 단위.
- 너비 통일: si = W / 남은 페이지 너비. 기준 너비 W도 자른 뒤 최대 너비이며 회전마다 자동 변경하지 않음.
- 페이지 상단은 이전 페이지의 남은 높이 × si와 간격의 누적 합.
- 화면 위치 = 문서 위치 × 공통 사용자 줌 z + 이동량 t.

페이지별 si와 사용자 줌 z는 별개이며 경계에서 z를 갱신하지 않습니다. 간격은 문서 단위로 정의하고 설정의 표시 의미를 명시합니다. 긴 문서는 Double 누적 좌표와 뷰포트 근처 지역 좌표를 사용합니다. 누적 위치로 가시 페이지를 탐색합니다.

2026-10-22 [ADR0018](../adr/0018-document-crop-and-reading-records-v4.md)의 문서 공통 여백은 각 원본 페이지의 비율입니다. sourceLeft/sourceTop은 남은 페이지 사각형에서 잘린 좌/상 원본 point×si를 뺀 값입니다. 타일·미리보기는 이 원점에서 그리고 남은 사각형으로 clip합니다. 가시 요청도 clip과 화면의 교집합만 계산합니다. 저장/북마크의 내부 좌표는 원본 비율로 유지하며 문서 좌표의 분모로 남은 크기를 사용하지 않습니다. PDF 파일 자체의 crop box는 변경하지 않습니다.

메타데이터는 백그라운드에서 확보합니다. 점진적으로 크기를 확정하는 엔진이면 현재 페이지 앵커를 보정해 스크롤 점프를 방지합니다.

## 상태와 제스처

저장 상태: 문서 식별자, 페이지 인덱스, 내부 정규화 좌표, 줌, 가로 앵커, 크기 모드, 간격. 화면 픽셀 오프셋만 저장하지 않습니다.

핀치 시 초점 아래 문서 좌표가 같은 화면 위치에 남도록 t를 갱신합니다. 페이지 이동·회전·설정 변경에서도 페이지 내부 앵커와 줌을 보존하고 유효 범위를 벗어난 이동량만 clamp합니다. 새 드래그/핀치는 기존 플링을 취소합니다. 포인터 변경·도구 표시가 점프를 만들지 않도록 검증합니다.

현재 `ZoomLimits`는 저장/복원/핀치의 공통 줌 범위를 0.1~32 px/문서 point로 공유합니다. PDF point의 실제 화면 배율은 z × si이고 원본 모드에서만 같은 값입니다. 새 축소 제스처의 하한은 `0.75 × min(viewWidth, viewHeight) / documentWidth`를 이 범위 안으로 제한한 값입니다. 하한보다 작게 저장된 기존 줌은 자동 확대하지 않고 추가 축소만 막습니다. 화면 크기 변경/점진 메타데이터/페이지 이동에서는 이 하한을 적용하지 않으므로 사용자 배율을 보존합니다. 높은 배율에서도 가시 512px 타일과 공유 64MiB 캐시를 사용합니다.

## 렌더링과 수명

가시 타일 → 이동 방향 인접 타일 → 나머지 프리패치 순서입니다. 메타데이터·저해상도 미리보기·고해상도 타일을 분리합니다. 캐시 키에 문서 버전·페이지·회전·타일 영역·배율 단계·렌더 옵션을 포함합니다.

핀치 중 기존 타일을 변환하고 안정되면 선명한 타일로 교체합니다. 작업 세대와 취소로 과거 결과가 새 상태를 덮지 않게 합니다. 선명도 교체가 배치 크기나 위치를 바꾸지 않습니다.

캐시는 바이트 상한과 LRU 퇴거, 메모리 압박 축소를 적용합니다. 엔진 스레드 제약과 기기 자원에 맞춰 동시성을 제한합니다. 문서 종료/전환 시 작업·파일 디스크립터·엔진 핸들·비트맵을 해제합니다.

## 파일과 개인정보

SAF 및 영구 URI 권한을 사용하며 전체 저장소 권한을 기본 요구하지 않습니다. seek 불가능 provider는 앱 전용 캐시 복사와 용량·취소·정리를 적용합니다. URI와 변경 메타데이터로 문서 버전을 구분하고 초기 열기에 전체 파일 해시를 강제하지 않습니다. 원문 업로드·원격 분석은 기본 범위가 아닙니다. 앱 내부 여백 자르기는 위 변환/원본 앵커 규약을 따르며 원본 삭제·가림 도구가 아닙니다.
